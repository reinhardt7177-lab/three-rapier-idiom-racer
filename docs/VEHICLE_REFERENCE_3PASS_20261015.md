# 실차 레퍼런스 차량 마감 3회 · 2026-10-15

## 현재 판정

차량 8종의 Blender 원본과 GLB에 3회 마감을 반영했다. 수프라 전면 재성형 후보는 화면 결함 때문에 제외했다. 정밀 실차 복제나 AAA 품질 달성을 뜻하지 않는다. **차량 변경만 담은 전체 회귀 423/423·빌드 통과, 성능 게이트는 판정 보류**다. 운영 배포는 하지 않았다.

사용자 최신 지침에 따라 계산은 로컬에서 수행한다. Colab 계산·자동 모니터 재개는 없다. 초기 연결 진단에서 노트북 계산은 실행하지 않았고, 이후 자동 활용 중단 지침을 적용했다.

### 다른 작업과 분리

작업 시작 이후 같은 폴더의 조향/음향/VFX/AI/남악 파일이 다른 작업으로 변경됐다. 해당 파일을 되돌리거나 이 작업으로 커밋하지 않는다. `validation-source/`는 시작 HEAD `aefb77897dfd33daf7edbb1552839982690cf39b`에 이번 차량 파일만 덧씌운 별도 검사본이다. 기존 사용자 변경을 지우지 않고 전체 검사와 A/B 비교를 고정한다. 이 결과를 공유 폴더의 모든 동시 변경 검증으로 확대하지 않는다.

초기 분리 검사본에서 `.blend` 원본을 복사하지 않아 cockpit 원본 존재 시험이 실패했다. 실행을 중단하고 해당 로그를 보존한 뒤 필요한 원본을 추가했다. 시험 기준을 바꾸지 않았다. 분리한 원본 브라우저 준비 과정의 `../driving` 경로 누락도 검수용 파일에서 바로잡았다. 물리/경로 등 보호 코드8개는 원본과 줄바꿈을 제외하고 동일하다(`protected-frozen-audit.json`).

## 실패·수정·남은 위험

1. 수프라 전면 후보: 첫 번째는 램프 가림, 다음은 광학 부품 들뜸이 보였다. 공유 메시 중복 변형을 막고 대칭 검사도 통과했지만 화면 결함이 남아 후보를 채택하지 않았다. 원래 차체/하우징 정렬로 복구하고 맞는 위치에 6렌즈를 넣었다. 대칭 수치 통과가 시각 품질 통과를 뜻하지 않는 사례다. 후보 GLB/Blend/화면은 `rejected-hero-candidate/`와 별도 PNG에 보존한다.
2. 휠 반경 속성 조회 위치가 달라 Pass 2 첫 실행이 실패했다. 실제 속성을 가진 리그 루트를 찾아 사용하도록 고쳤고 8종 재실행을 통과했다.
3. Blender CPU 미리보기는 메모리 부족 상태에서 지연돼 본 작업 소유 렌더 프로세스만 종료했다. 생성되지 않은 렌더를 검증으로 세지 않고 실제 Three.js 화면으로 확인했다.
4. 실제 PC 가용 RAM이 250~1,100MB까지 낮아져 탭/명령 지연이 반복됐다. 자체 비교 렌더러와 참고 탭을 정리했다. 무거운 회귀 검사 중 얻은 프레임은 정상 제품 성능 판정에 사용하지 않는다.
5. 기본 차체 비례·범퍼/램프 형상이 실차와 다르다. 재질 폴리싱만으로 해결되지 않는다. 가장 중요한 다음 작업은 수프라 한 종의 전면·측면 기준 사진/비례를 고정한 독립 재모델링과 사람의 형상 평가다.

**성능 판정이 남은 로컬 후보로 보존한다. 운영 배포·main 병합·PR은 없다.** 실제 터치 장치·장시간 누적 성능·안정된 PC 조건의 프레임 회귀는 미검증이다. 이번 작업에서 이전 키보드/포인터 취소 조합 전체를 다시 수동 실행했다고 주장하지 않는다. 관련 입력 단위 시험은 전체 검사에 포함됐다.

검사 결과·빌드 해시를 따로 보존한 뒤 본 작업이 만든 분리 검증 폴더/압축 사본 약 **1,131,700,768B**를 정리하려 했지만, 자동 승인 검토가 삭제 명령을 정책상 차단했다. 삭제는 실행되지 않았고 원본·임시 사본·의존성 연결은 모두 남아 있다. `scratch-cleanup-plan.json`은 확보한 용량이 아닌 **미실행 정리 계획**이다.
