# HORIZON CLUB — 1장 구현·검수 기록

2026-09-08 · 로컬 작업. GitHub 커밋/푸시 및 운영 배포는 하지 않았다.

## 실제로 실행되는 범위

1. 차고 **챕터 선택 →**에서 HORIZON CLUB의 6개 챕터 로드맵을 확인한다. **1장만 플레이 가능**하며, 나머지는 클릭할 수 없는 제작 예정 카드다.
2. **1장 시작 →**: 민서의 기준을 선택한다. 표준 45초, 여유 60초이며 표준 36초 이하는 상위 기록으로 남긴다. 이 숫자는 초기 기준이고 초보자 난이도 검증을 마친 수치가 아니다.
3. 정차 브리핑 → **클럽 테스트 출발 →** → 3초 카운트다운 → 기존 약 770m 공도의 3개 게이트 → 자동 감속 → 결과로 진행한다. 가속·제동·접지·길 길이는 바꾸지 않았다.
4. 목표 이내의 유효 완주만 라이선스 01을 최초 1회 획득한다. 기록 개선은 가능하지만 라이선스를 반복 발급하거나 재화를 지급하지 않는다. 지금 보상은 **차고 UI의 라이선스와 기록**이고, 3D 장식/차량 성능 증가가 아니다.
5. 차고로 돌아가도 기록이 유지된다. 저장이 차단되면 이번 방문 동안만 유지하고 영구 저장됐다고 표시하지 않는다. 기존 프롤로그·신호소 이야기·자유주행·스프린트 PB와 설정 키는 보존한다.

현재 상대는 AI나 고스트가 아닌 **민서의 기준 시간**이다. NFS 전체 규모를 구현한 버전이 아닌, 독자적인 캠페인의 첫 연결 단위다.

## 구조와 저장

- `src/campaign/campaign.js`: 챕터 정의, 성공 판정, 정제된 진행 상태, 저장·병합·중복 방어.
- `src/campaign/CampaignBoard.jsx` / `campaign.css`: 차고에서만 열리는 챕터 모달. 48px 이상 조작 영역, 키보드 순환·Esc 복귀, 세로 내부 스크롤.
- `createDriving.js`: 기존 스프린트가 `complete`로 전환된 순간에만 챕터를 심사한다. 재시도는 이번 결과만 지우고 획득한 라이선스/베스트는 유지한다.
- `DrivingMode.jsx` / `main.jsx`: 조건·결과를 표시하고 차고 복귀 시 메모리 진행 상태도 전달한다. 다른 모드에 다녀와도 저장 차단 상태의 챕터 보상은 사라지지 않는다.
- 저장 키 `mumu.coast.campaign.v1`, 코스 버전 `harbor-s860-v1`. 유효한 3개 증가하는 split과 마지막 시간 일치, 난이도와 메달의 일치, 코스 버전을 확인한다.
- 알 수 없는 버전·다른 코스 저장은 덮어쓰지 않는다. 저장소와 현재 방문의 유효 베스트를 합치고, 실제 쓰기 후 다시 읽어 영구 저장 여부를 확인한다.
- 라이선스는 로컬 진행 데이터다. 서버 검증·멀티플레이 부정행위 방지 시스템은 아니다.

## 실제 검증

환경: Windows, 설치된 Chrome의 headless/SwiftShader, Playwright. 화면 크기 검사는 실제 삼성 기기 검사가 아니다. 시험 드라이버는 키보드/터치 입력만 보내며 차량 위치·체크포인트·시간·획득 기록을 직접 주입하지 않는다.

- **77개 단위시험 + 빌드 통과.** 챕터 11개 시험은 표준/여유/상위 기준, 기록 무효·복귀·미완주·잘못된 split·희소 배열·NaN, 중복 보상, 기존 더 빠른 기록, 저장 차단, 미래 버전 보존 등을 확인한다.
- [1장 순차 브라우저 검증](../artifacts/horizon-club/serial/campaign/verification.json): **33.06초** 유효 완주, 라이선스 실제 획득, 차고→기존 GT 테스트→차고→새로고침 보존. 6개 챕터 모달 및 주행 HUD 화면 크기, 목표 선택, 입력 잠금, 복귀 무효, 48px 조작 영역, 키보드 순환/복귀 확인. 최대 139 draw calls, 브라우저 오류/요청 실패 0.
- [저장 차단 동작 검증](../artifacts/horizon-club/serial/campaign-blocked-storage-no-capture/verification.json): **33.15초** 유효 완주, 영구 저장 없음, 차고→기존 GT 테스트→차고를 거쳐 메모리 라이선스 유지. 오류/실패 0. 이 실행은 `--no-screenshots`로 캡처를 제외한 **동작 검사**이며 저장 차단 화면의 캡처 검증을 대신하지 않는다.
- [기존 스프린트 회귀](../artifacts/horizon-club/serial/sprint/verification.json): **33.23초** 유효 완주와 PB 저장, 재도전, 복귀 무효, 4개 터치 화면 크기, 실제 두 손가락 입력·취소·일시정지, 차고/새로고침 보존 통과.
- [태블릿 HUD 회귀](../artifacts/horizon-club/serial/tablet-hud/verification.json): 1280×800, 800×1280, 1024×600, 600×960, 390×844, 640×400의 겹침/화면 넘침 없음. 동시 가속·조향, 회전/메뉴 진입 시 입력 해제, 초점·설정 저장 통과. **Chrome 터치 에뮬레이션** 결과다.
- [기존 신호소 이야기 회귀](../artifacts/horizon-club/serial/signal-journey/verification.json): 실제 키보드 왕복 주행 **196.12초**, 신호소 정차·세로 화면·복귀·저장·재시도 안전성 통과. 자동 시험 벽시계 시간은 206.75초이며 FPS 인증 수치가 아니다.
- [속도감·오디오 회귀](../artifacts/horizon-club/serial/speed-feel/verification.json): 실제 **225.32km/h** 주행에서 카메라 거리 제한, 속도에 따른 오디오 신호 증가, 일시정지/볼륨 0/음소거 시 무음, 차고 복귀 시 오디오 종료와 재진입 무음 통과. 파형 검증이지 주관적인 음질·운전 재미 검증이 아니다.

위 순차 회귀 실행은 모두 종료 코드 0으로 완료했다. 화면 캡처가 포함된 일반 1장 검사와 캡처를 제외한 저장 차단 검사를 구분하며, 아래의 실패 증거도 그대로 보존한다.

## 남은 한계와 다음 작업

- 2~6장, 실제 기록 고스트, 물리 AI, 경찰/교통, 튜닝, 새 컷신/3D 보상은 아직 없다. 제일 먼저 만들 것은 **버전이 맞는 실제 주행 샘플의 고스트**다.
- 지금은 목표 시간을 넘겨도 강제로 차량을 멈추지 않고 완주 뒤 결과를 판정한다. 실패 비용은 없고 결과에서 바로 다시 도전할 수 있다.
- 여유 모드의 성공 조건은 단위시험으로 확인했고 브라우저에서는 60초 안내/선택을 확인했다. 초보자의 터치 완주 난이도 검증과는 다르다.
- 실물 삼성 기기의 스피커·두 엄지 조작·10분 이상의 성능/발열·처음 접하는 사람의 목적 이해/재도전 의향은 미검증이다.
- 자동 화면 캡처의 간헐적 시간 초과 원인은 미확정이다. 일반 챕터 화면 캡처는 최종 순차 실행에서 통과했고, 저장 차단 시나리오는 캡처를 제외한 동작 검사만 최종 통과했다.
- 빌드의 큰 청크 경고는 남아 있다. 단위시험 통과·스프린트 완주만으로 AAA 품질이나 모든 기기 지원을 선언하지 않는다.

제작의 상세 근거와 단계별 성공 조건은 [리서치·6챕터 계획](HORIZON_CLUB_PLAN.md)을 따른다.
