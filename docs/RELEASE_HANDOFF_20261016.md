## 무무클래스에 올린 방식

기존 **앱 올리기** 화면을 사용했다. 이름은 ‘무무레이싱 · MUMU CIRCUIT’, 카테고리는 휴게시간, 전체공개, 제작 도구 코덱스, 사용환경은 실제 검증 근거가 있는 PC로 등록했다. 대표 이미지는 블로그 15번 현재 차고 이미지를 그대로 첨부했다. 학년별 학습 앱으로 검증한 것이 아니므로 학년 태그를 임의로 넣지 않았다.

저작권·IP·키 미노출·학생 개인정보·스크립트 안전성 및 제작자 책임/이용약관 제6조 동의는 실제 등록 화면에서 사용자가 확인·동의·등록을 명시적으로 허용한 뒤 처리했다. 제출 후 홈의 최신 앱 카드, 상세 페이지의 제목·설명·대표 이미지·실행 링크를 확인했다. 링크 목적지는 공식 게임 루트다.

초기 요청 해석을 잘못해 로컬 별도 체크아웃에 작성했던 무무클래스 메뉴·게임 창 변경은 사용자의 정정 직후 해당 변경만 원복했다. 무무클래스 추적 파일 diff 0, 커밋·푸시·배포 0이다. 사이트 코드나 DB 구조를 변경해 등록을 우회하지 않았다.

게시 증거 이미지는 게임 자료 20장을 늘리지 않도록 작업 저장소 밖 `D:/racing/.work/mumu-app-published-20261016.png`에 저장했다. 등록 폼 임시 스크린샷도 같은 외부 작업 폴더에 있다.

## 실패와 수정

1. 이미지 정리 사전 검사에서 PowerShell JSON 날짜 자동 변환과 Node/Windows 수정 시각의 1ms 정밀도 차이를 발견했다. 이때 삭제는 하지 않았다. 모든 파일의 바이트·해시가 같음을 먼저 확인하고 정확한 UTC 시각 기준으로 다시 기록한 뒤 삭제했다. 기존 표본을 성공 수치로 고쳐 덮지 않고 시각 비교 원자료를 남겼다.
2. 임시 사본 삭제 도우미의 `Split-Path -LiteralPath ... -Parent` 조합이 지원되지 않아 사전 검사에서 중단됐다. 네이티브 .NET 경로 함수로 부모를 구한 뒤 동일한 경로·링크·해시 검사를 통과해 삭제했다.
3. 등록 페이지의 접근성 이름 ‘파일 선택’과 DOM의 실제 업로드 이름 ‘Choose File’이 달라 첫 첨부가 시간 초과됐다. 현재 DOM에서 실제 파일 입력을 확인해 정식 파일 선택 API로 첨부했다. 권한이나 업로드 제한을 우회하지 않았다.
4. 무무클래스 상단 창 추가로 해석한 것은 작업 범위 오해였다. 미게시 로컬 코드만 되돌리고 기존 앱 등록 기능을 사용했다.
5. 제작 문서 작성 중 선행 링크 검사에서는 아직 만들지 않은 마감 문서 링크가 발견됐다. 해당 문서를 작성하고 최종 검사를 다시 실행했다.

## 남은 위험·다음 작업

최우선은 실제 휴대폰과 다른 통신망에서 QR 초대 → 두 사람 출발 → 충돌·완주 → 재경기 흐름을 확인하는 것이다. 같은 PC의 두 브라우저 성공을 전체 네트워크 지원으로 확대하지 않는다. 차량은 실차 정밀 스캔이 아니고, 한국 코스는 지형 전체의 측량 복제가 아니다. 높은 품질의 장시간 성능과 사람의 운전 재미 평가는 계속 필요하다.

옛 문서의 일반 스크린샷 링크와 임시 비교 HTML은 요청에 따라 삭제된 사진을 가리킬 수 있다. 현재 블로그 경로를 사용하거나 필요한 옛 장면은 해당 Git 커밋에서 찾아야 한다. Git 이력 크기는 이번 작업으로 줄어들지 않는다.
