# 바람곶 해안길 — 짧은 공도 1단계

작성일: 2026-09-06  
요청: ‘1번, 짧은 해안 공도부터 만들기. 항상 비판적으로 판단.’  
범위: 도로·갈림길·전망대·회차·복귀. **2번째 스토리 미션은 이번 범위가 아니다.**

## 실행 방법

로컬 게임을 새로고침하고 차고의 **해안도로 드라이브 →**를 누른다. 기존 **첫 번째 호출 시작 →**, **GT 테스트 주행 →**는 별도 버튼으로 보존했다.

항만대로 → 완만한 해안 S커브 → 해안 갈림길 → 오른쪽 바람곶 전망대. 왼쪽은 솔숲 회차 쉼터다. 양쪽 끝에 넓은 회차 공간이 있다. 전망대에서 잠시 정차한 뒤, 왔던 길의 오른쪽 차로로 항구까지 돌아와 정차하면 왕복 안내가 완료된다.

- 새 도로망 길이: 공통 구간 약 1,006m + 전망대 가지 약 223m + 쉼터 가지 약 240m.
- 차량 출발점에서 전망대까지 중심선 기준 약 **1.14km 편도 / 2.28km 왕복**. 회차 동작·차로별 거리에는 차이가 있다.
- 권장 주행: 40–60km/h, 회차장은 더 천천히. 최고속 제한 수치는 기존 차량과 동일하고 가짜 속도 보정은 없다.
- **C / 도로 복귀**: 가까운 도로의 현재 진행 방향 차로로 차량을 정지 상태로 복귀. 낙하 시에도 이 복구를 사용한다.
- **R / 시작점 복귀**: 항구 출발점으로 돌아가 이번 방문/왕복 확인을 새로 시작한다.
- 차고 버튼은 UI 장면 전환이다. 실제 정비소 셔터를 운전해 통과하는 연결 장면은 아직 아니다.

## 설계 판단

1. 기존 직선에 곡선 장식만 얹지 않았다. 공유 경로에서 노면 메시와 물리 삼각형을 생성한다.
2. 기존 차고·첫 이야기·고속 시험을 보존하기 위해 새로운 자유 주행 모드로 분리했다. 스토리 장르를 다시 버린 것이 아니다.
3. 처음부터 입체 교차로·절벽 점프·고저차를 넣지 않았다. 이번 도로는 평면 곡선이며 먼저 길의 연결과 운전·복귀를 검증한다.
4. 폐쇄 서킷이 아니다. 양방향 중앙선이 있는 공도와 두 갈림길의 회차장이다. 끝까지 달린 뒤 되돌아올 수 있다.
5. 같은 데이터가 노면·차선·가드레일·바닥 충돌·가드레일 충돌·안내 지도·복구 위치를 결정한다. 화면만 바뀌고 물리가 옛 직선에 남는 오류를 막는다.

## 구현 파일

- `src/driving/coastRoute.js`: 곡선, 폭 변화, 회차장, 충돌 삼각형, 가드레일 위치, 최근접 도로/지도/방문 판정.
- `src/driving/coastWorld.js`: 기존 항구 디테일 재사용, 해안 식생·바위·표지판·레일 세부·전망 데크·작은 등표.
- `src/driving/physics.js`: 새 모드에서 실제 곡선 노면과 회전된 가드레일 충돌체 사용. 옛 시험장 장벽은 새 모드에서 생성하지 않음.
- `src/driving/createDriving.js`: 모드별 월드 생성/해제, 근처 도로 복귀, 방문/귀환 상태 보고.
- `src/driving/DrivingMode.jsx`: 위치를 표시하는 도로 지도, 오른쪽 전망대/왼쪽 쉼터 안내, 왕복/복구 버튼.
- `scripts/coast.test.mjs`: 생성·접지·충돌·양 갈림길 왕복·지도 방향·방문 판정.
- `scripts/verify-coast.cjs`: 실제 브라우저 키 입력으로 전망대 왕복 및 모바일 확인. 게임용 자동운전 기능이 아니다.

## 검증 결과

`npm run check`: **27개 시험 + 프로덕션 빌드 통과**.

새 공도 시험에는 다음이 포함된다:

- 곡선 샘플 연결, 양 끝 접속, 최소 도로 반폭 6m, 급격한 꺾임 제한.
- 삼각형의 위쪽 면/유한 좌표, 가드레일이 차로를 가로막지 않는지.
- 모든 가지의 양 차로와 회차장에 네 바퀴 접지 확인.
- 실제 물리로 전망대 왕복 약 **188.1초**, 쉼터 왕복 약 **192.2초**. 테스트 운전자가 가속·제동·조향만 입력하고 도중 차량 위치를 강제로 설정하지 않음.
- 중심선 이격 최대 약 3.90m / 4.51m, 노면 최소 반폭 6m 내 통과. 차체가 넘어지거나 바닥으로 떨어지지 않음.
- 곡선 가드레일의 약 115km/h 측면 충돌, 지도 좌우, 정차 기반 방문/복귀 판정.

첫 실제 브라우저 검증도 **항구→코너→갈림길→전망대 정차→회차→항구 정차**를 키 입력만으로 통과했다. 도로 복귀 후 접지, R 초기화, 모바일 화면, 단일 캔버스, 차고 복귀를 확인했다. 콘솔 오류·실패 요청·외부 요청 0건. 약 195초(스크린샷·UI 조작 포함), 관측 드로콜 최대 205회. 수정 후 최신 결과는 `artifacts/coastal-road/verification.json`에 덮어쓴다.

브라우저 검증 스킬의 화면/오류/탐색 기준을 따르며, agent-browser CLI가 없어 기존 Playwright + Chrome 경로를 사용했다. 소프트웨어 렌더링으로 검증한 결과이며 사용자 기기 60FPS 보증이 아니다.

## 아직 부족한 것 — 완료와 구분

- 이번 단계는 **연결된 공도 1차 플레이 구간**이다. 상용 수준의 완성된 월드라고 보지 않는다.
- 굽은 길의 보행로·생활 흔적·원경 실루엣은 항구 차고보다 단순하다. 다음 미술 작업은 그 차이를 줄이는 쪽이어야 한다.
- 곡선 도로의 양방향 주행은 가능하지만 통행 차량·보행자·신호 체계는 아직 없다.
- 바깥 풍경은 비주행 배경이다. 모든 바위·나무에 독립 충돌을 붙이지 않았다. 가드레일 바깥으로 나가면 C 복귀를 사용할 수 있다.
- 전망 데크는 차량으로 올라가는 공간이 아니다. 사람 하차/걷기 없음.
- 자동차 차고 재진입은 버튼 방식이며 전망대 방문 기록은 이번 주행 세션에만 남는다. 새 스토리 저장/보상/2장 컷신은 추가하지 않았다.
- 카메라는 기존 추적 카메라를 유지. 코너를 미리 바라보는 튜닝과 진짜 슬립 기반 연출은 별도 단계다.
- 새 자유 주행 모드의 사용자가 느끼는 코너 난이도는 직접 플레이 피드백이 필요하다. 자동 운전 시험 통과가 재미의 증명은 아니다.
- 빌드의 기존 대용량 Three.js/Rapier 청크 경고는 남음. 새 외부 에셋/패키지/음원은 없음.
- 로컬 변경만 적용. GitHub 커밋/푸시·Vercel 배포는 하지 않음.

## 다음 판단 지점

먼저 사람이 **코너를 놓치지 않고 갈림길을 고를 수 있는지, 전망대에서 차를 돌려 돌아오는 것이 자연스러운지** 확인한다. 그 뒤 이 도로 위에 ‘옛 해안길’ 이야기 한 편을 넣는다. 길을 더 길게 늘리거나 새 차량을 추가하는 것은 그 다음이다.
