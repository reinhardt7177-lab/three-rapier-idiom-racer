원본 probe의 사이드브레이크는0.3~1.2초에 당기고,1.2초 이후 가속한다. 따라서 위1.5초는 측정 시작 시점 기준이며 “당긴 뒤1.5초”와 구분한다. 사용자 설명의 약3km/h는 이번 실행에서2.0초에 관측됐다. 지속1.5초 당기기·보정 끔 비교와 새 단위 시험은 물리 후보 중단으로 미완료다.

### 시각 기울기 필터의 별도 측정

`visual-probe.mjs`는 실제 물리 상태를60Hz 시각 필터에 넣는다. 일반 모션 설정의 가속 피치-1.8°, 제동 피치+1.8°, 우회전/연속 선회 롤 최대3.0°를 확인했다. 회전 부호에서 X축 피치가 음수이면 차량 앞이 들린다. 수치상 극미량의 물리 롤은 최대약0.00000024°로, 시각 기울기를 물리 회전에 기록한 것이 아니다.

- 고유진동1.75Hz·감쇠비0.65의 정확한 스프링 해를 사용한다.
- 차 기준 속도 차이로 앞뒤/좌우 가속도를 구한다. 차체 메시만 별도 그룹에 넣어 회전한다.
- Wheel/Steering/Suspension 아래 메시·캘리퍼·타이어는 기울기 그룹에서 제외한다. 현재 차량8종 GLB의 동적 노드에 기울어질 메시 조상이 없음을 JSON 구조로 확인했다(`rig-ancestor-audit.json`).
- 라이벌5대에 같은 필터, 고스트에는 기존 저장 위치에서 계산한 속도를 적용한다. 고스트 저장 형식/기록은 바꾸지 않는다.
- 1인칭은 물리 루트만 따라가므로 추가 시각 기울기0°(요구 상한1° 이하). 실제 도로의 경사 자체를0°로 만드는 기능은 아니다.
- `prefers-reduced-motion`에서 기울기 상한을25%로 줄인다: 피치0.45°/롤0.75°. 검수 IAB는 이 설정이 **true**였으므로 그 화면을 일반3° 설정의 캡처라고 표현하지 않는다.

### 후보1에서 시도한 물리 변경(현재 적용되지 않음)

그립 파라미터의 진단 비교에서 기존2.99의 정상 선회30.36m/s²가1.70에서17.24m/s²로 줄었다. 후보는 플레이어 그립 상한1.70·포화 조향 시 타이어 마찰 저항, 보정 상태에서 약한 사이드브레이크·잔여 후륜 그립·옆으로 미끄러질 때 실제 노면 속도로 조향 상한을 계산하는 방식을 적용했다. 매 프레임 자세 고정/충돌체/물리 회전/거리 계산은 건드리지 않았다. 라이벌의 기존 그립을 별도 함수로 분리해 보존했지만 이후 접촉 결과까지 같지는 않아 후보 전체를 원복했다.

기존 `steering-turn.test.mjs`에는90km/h 회전 반경을15% 이상 줄이라는 옛 요구의 시험이 있다. 새로운1.5~1.8G 상한과는 목적이 달라 향후 시험 계약 정리가 필요하다. 이번에는 그 시험이나 통과 숫자를 바꾸지 않았다.

## 중단 직후 선택 기록(이후 사용자 결정으로 차체만 재개)

1. 최초 중단 당시에는 사용자 선택을 기다렸다. 이후 차체만 완성한다는 답변을 받았으며 물리 후보는 계속 보류한다.
2. 기울기를 우선 완성한다면 물리는 시작 상태로 유지하고, 모든 차량/고스트·두 시점 가속/제동/코너 캡처·남악 낮음30초 A/B·전체 회귀를 마친다.
3. 물리를 재개한다면 먼저 동일 해안 약870~897m의 실제 접촉/회피 경로를 재현하고, 기존 완주를 보장하는 조정 범위를 정한다. 실패 증거를 삭제하거나 판정 기준을 낮추지 않는다.
4. 그 뒤 남악/성삼재·4×3완주·지속/보정 끔 드리프트·충전·메달 가능성을 측정한다. 배포는 별도 요청 이후에만 수행한다.

실행 로그·수치·후보·화면은 `artifacts/vehicle-motion-20261012/`에 보존했다. 앞선 여수/교통 개발본의 중단 상태와 새 코스 메달 문제도 함께 남아 있다.

용량 비교는 양쪽 번들에 같은 Node `gzipSync`를 적용했다. 서로 다른 Python/Node 압축 결과를 섞은 계산은 비교 근거에서 제외하고 `bundle-size-mixed-compressors-rejected.json`에 보존했다.
