# HORIZON CLUB — 해안 레이싱 캠페인 제작 계획

작성: 2026-09-08 · 기준: 현재 로컬 프로토타입 · 상태: 첫 챕터 로컬 연결, 실제 검증은 [검수 기록](HORIZON_CLUB_CHECKS.md) 참조

## 1. 결론과 작업 범위

**밝은 해변 공도와 정비소의 자체 제작 미술을 유지하면서, “차고 → 출전 이유 → 운전 도전 → 결과 → 차고 성장”을 완성한다.** Need for Speed의 도시 규모나 자산을 복제하는 프로젝트가 아니다. 참고할 것은 경쟁, 성장, 재도전, 위험과 보상의 구조다.

이번 구현 대상은 **챕터 1 `first-light` — 「태양 아래 첫 기록」**이다. 챕터 2~6은 제작 계획이며 아직 플레이할 수 없다. 장차 해금될 콘텐츠와 실제로 실행 가능한 콘텐츠를 UI에서 구분한다.

기존 신호소 왕복 이야기, 프롤로그, 자유주행, 개인 최고 기록(PB), 차량·소리·접근성 설정은 보존한다. 기존 게임을 지우거나 저장 데이터를 초기화해서 새 캠페인을 만들지 않는다.

이 문서는 조사 사실과 신규 기획을 구분한다. 아래는 제작 방향과 기능 범위이며, 실제 실행 결과·실패 재현·한계는 [검수 기록](HORIZON_CLUB_CHECKS.md)에 따로 남긴다.

### 가져오지 않을 것

- 원작 인물, 대사, 도시·코스, 로고, 음악, 차량 도안과 시청각 자산.
- 경찰 추격, 대도시 교통, 다수 차량, 온라인 경쟁을 한 번에 만드는 범위.
- 빠른 차를 사기 위해 같은 짧은 레이스를 강제로 반복하는 경제.
- 보이지 않는 AI 순간이동, 과도한 고무줄 속도 보정, 화면 숫자만 올리는 최고 속도.
- 검증되지 않은 “AAA급”, “최고의 조작감”, “태블릿 60 FPS 보장” 표현.

## 4. 세계와 인물 — 신규 창작 제안

### 게임의 약속

**“작은 해안 차고에서 시작해, 자신만의 GT와 주법으로 수평선의 결승선에 선다.”**

주간의 청록 바다, 파스텔 건물, 야자수, 정비 흔적이 있는 BAY 01이 기본 미술이다. 긴장감은 반드시 어둡고 네온이 많은 도시에서만 만들 필요가 없다. 가까운 도로 구조물의 흐름, 제동 지점, 라이벌과의 간격, 엔진 부하와 조향 반응으로 만든다.

공도 특유의 차선·보도·상점·항구 구성을 유지한다. 이벤트의 이동 범위와 통제 조건은 명확히 표시하고, 교통 AI가 없는 상태에서 교통 기능이 있는 것처럼 홍보하지 않는다.

### 핵심 인물

- **민서:** HORIZON CLUB의 기록 담당 드라이버. 첫 주행의 기준을 제시한다. 플레이어를 계속 가르치는 설명봇이 아니라, 기록과 주법에 근거해 피드백하는 인물이다.
- **선우:** BAY 01 정비사. 출력만 높이는 대신 브레이크와 타이어 선택이 운전에 어떤 차이를 만드는지 함께 시험한다. 차고의 기능과 이야기를 연결한다.
- **해준:** 새로 만나는 라이벌. 과감한 진입과 강한 코너 탈출이 특징인 인물로 기획한다. 실제 물리 AI가 준비되기 전에는 대사와 검증된 기록만 등장하며, 가짜 AI 주행을 보여주지 않는다.

이름과 성격은 이 프로젝트를 위한 창작 설정이다. 전용 인물 모델, 음성 녹음, 장편 컷신이 구현됐다는 의미는 아니다. 초기에는 정차 중의 짧은 대화와 주행을 방해하지 않는 한 줄 무전으로 구현한다.

## 5. 여섯 챕터

### 챕터 1 — 태양 아래 첫 기록 (`first-light`)

**상태: 이번 구현 대상. 이후 챕터는 아직 실행 불가.**

- **이야기:** 민서가 해안 페스티벌에 앞서 첫 유효 기록을 요청한다. 선우가 점검한 GT로 출발해 HORIZON CLUB의 첫 라이선스를 얻는다.
- **도전:** 기존 해안 스프린트의 3개 게이트를 순서대로 통과한다. 기본 목표는 민서의 기준 **45초**, 여유 목표는 **60초**, 상위 기록 목표는 **36초**다. 수치는 초기 설계값이며 실제 주행 난이도 검증 전이다.
- **진행:** 차고의 챕터 진입 → 정차 브리핑 → 3초 카운트다운 → 주행 → 완주 후 자동 감속 → 결과 → 차고의 라이선스·기록 표시.
- **연출:** 현재 범위는 정차 브리핑과 카운트다운, 기존 주행 화면, 결과 UI다. 새로운 영화식 컷신이나 3D 보상 장식은 아직 구현하지 않는다.
- **보상:** 선택한 목표를 유효 기록으로 달성하면 라이선스를 **최초 1회** 부여한다. 반복 도전은 기록 개선에 집중하고 보상을 중복 지급하지 않는다. 기본·여유·상위 목표 달성 여부를 혼동 없이 표시한다.
- **성공 조건:** 순서에 맞는 3게이트 통과, 선택 목표 이내 완주, 유효성 판정, 결과·저장·차고 표시까지 연결되어야 한다. 기록을 무효화하는 복구·이탈 등 기존 규칙을 우회해서는 안 된다.

라이선스를 얻었다고 아직 없는 챕터 2를 플레이 가능한 것처럼 열지 않는다. 다음 챕터는 제목과 준비 상태만 안내한다.

### 챕터 2 — 라이벌의 라인

**상태: 계획.**

- **이야기:** 민서가 해준의 기준 기록을 소개한다. 처음에는 상대 차량과 부딪치는 경주가 아니라, 같은 길을 어떻게 다르게 달리는지 읽는 도전이다.
- **도전:** 실제 주행으로 기록한 고스트와 구간 차이를 비교한다. 녹화된 위치·시간·자세를 재생하며, 데이터 버전이 다른 코스나 물리 설정의 기록은 분리한다.
- **진행·연출:** 상대 기록 확인 → 출발 → 구간별 앞섬/뒤처짐 → 결승선 기록 차이 → 개선할 한 구간 안내. 고스트는 반투명 등으로 구별하고 “기록 고스트 · 충돌 없음”을 명시한다.
- **보상:** 개인 최고 기록과 라이벌 기록 비교 카드. 새로운 차량을 남발하지 않고 차고 기록 보드의 다음 단계로 연결한다.
- **성공 조건:** 고스트 재생과 실제 기록 시간이 일치하고, 일시정지·재시도·프레임 변화에도 시간축이 어긋나지 않는다. 상대 기록 갱신과 자신의 PB 갱신을 별도로 인정한다.

### 챕터 3 — 나만의 GT

**상태: 계획.**

- **이야기:** 선우가 “더 센 엔진” 대신 플레이어의 제동과 코너 탈출 습관을 함께 살핀다.
- **도전:** 브레이크·타이어 세팅을 같은 코스와 조건에서 비교한다. 기본 세팅도 완주 가능하게 유지하며, 수치를 모두 높이는 일방적 상위 호환만 만들지 않는다.
- **진행·연출:** 차고에서 두 세팅의 장단점 확인 → 짧은 비교 주행 → 구간 기록·제동 안정성 확인 → 선택한 세팅 저장. 주행 중 큰 튜닝 패널을 띄우지 않는다.
- **보상:** 검증된 세팅 선택권과 작업 내역. 전용 부품 모델·정비 애니메이션은 별도 미술 작업으로 분리한다.
- **성공 조건:** 동일 입력 시험에서 세팅 간 차이가 재현되고, 키보드와 터치 모두 제어 가능한 범위다. PB에는 세팅 정보를 남겨 비교 조건을 알 수 있게 한다.

### 챕터 4 — 해안의 동료들

**상태: 계획. 동일 물리 AI 검증이 선행 조건.**

- **이야기:** 기록으로만 알던 해준과 같은 도로에 서고, 민서의 작은 크루 이벤트에 초대받는다.
- **도전:** 우선 **AI 1대**와 경쟁한다. 같은 차량 물리·게이트·이탈 규칙을 사용하고, 곡률에 따른 제동·앞 차량 회피·정체 복구를 검증한 뒤 이벤트에 연결한다.
- **진행·연출:** 짧은 출발 소개 → 추월과 코너링 → 결과 비교 → 크루의 다음 제안. 큰 인물 팝업이나 긴 무전이 코너 시야를 가려서는 안 된다.
- **보상:** 크루 이벤트 참가 자격과 라이벌 관계의 진전. 온라인 크루나 멀티플레이가 구현된 것처럼 표기하지 않는다.
- **성공 조건:** 완주 안정성, 차량 충돌, 스폰 간격, 역주행 방지, 막혔을 때의 복구가 반복 시험을 통과한다. 순간이동·무제한 속도 보정으로 경쟁을 성립시키지 않는다.

### 챕터 5 — 뜨거운 해안

**상태: 계획. 위험·보상은 선택 기능으로 시작.**

- **이야기:** 연속 도전 행사에서 민서는 정산을, 해준은 한 번 더 달릴 기회를 제안한다. 어느 쪽이든 플레이어가 고른 결과가 명확해야 한다.
- **도전:** 확보한 성과를 정산하거나, **이번 연속 도전의 추가 보너스**를 걸고 다음 이벤트에 출전한다. 이미 저장된 라이선스·기본 차량·이전 보상을 몰수하지 않는다.
- **진행·연출:** 결과에서 위험 범위를 읽기 쉽게 안내 → 정산/추가 도전 선택 → 다음 이벤트 → 최종 정산. 시간 압박으로 버튼을 잘못 누르게 만들지 않는다.
- **보상:** 연속 도전 기록과 선택한 위험에 맞는 추가 보너스. 기본 진행은 높은 위험을 택하지 않아도 가능해야 한다.
- **성공 조건:** 정산·실패·중단·새로고침 경계에서 중복 지급이나 기존 재산 손실이 없다. **경찰 추격은 AI와 기기 성능 검증 후 별도 범위로 판단하며, 이 챕터의 초기 필수 요소가 아니다.**

### 챕터 6 — 수평선의 마지막 라인

**상태: 계획. 앞 챕터의 검증된 시스템만 조합.**

- **이야기:** BAY 01에서 시작한 GT로 해안 페스티벌 결승에 선다. 민서·선우·해준과의 관계가 주행 결과와 귀환 장면에서 마무리된다.
- **도전:** 고속 구간, 제동이 중요한 기술 구간, 라이벌 결승을 연결한다. 마지막 챕터를 위해 갑자기 검증되지 않은 점프·추격·신규 물리를 넣지 않는다.
- **진행·연출:** 짧은 결승 소개 → 단계별 레이스 → 결승 결과 → 차고 귀환. 이 단계에서 전용 귀환 컷신과 3D 전시 보상을 제작할지 결정한다.
- **보상:** 캠페인 완주 기록, 최종 차고 전시, 원하는 이벤트의 자유 재도전. 새 계정을 만들지 않아도 다시 즐길 수 있도록 한다.
- **성공 조건:** 단계 간 상태와 기록이 정확하게 전달되고, 실패한 단계의 재도전 범위가 명확하다. 완주 이후에도 기존 자유주행과 저장 데이터에 접근할 수 있어야 한다.

## 6. 시스템 제작 순서

1. **챕터 데이터와 진행 상태:** 챕터 ID, 제작 상태, 선행 조건, 목표, 보상 ID를 분리한다. “계획”과 “해금되었지만 미완성”을 플레이 가능 상태로 취급하지 않는다.
2. **챕터 1 연결:** 기존 스프린트 판정을 재사용해 브리핑·카운트다운·주행·완주·결과·차고까지 한 번의 흐름으로 연결한다. 다른 이야기 모드가 같은 상태를 잘못 공유하지 않게 한다.
3. **저장과 중복 방지:** 기존 PB·설정은 유지하고 챕터 진행을 별도 버전으로 저장한다. 보상은 고유 ID로 최초 1회만 확정한다. 저장 실패·구버전·손상된 값의 처리도 시험한다.
4. **실제 기록 고스트:** 녹화·재생·시간축·코스/차량 설정 버전·일시정지를 먼저 검증하고 챕터 2에 연결한다.
5. **의미 있는 차량 세팅:** 브레이크/타이어 비교 계측을 만들고 챕터 3의 선택으로 사용한다. 불안정한 주행을 출력 증가로 덮지 않는다.
6. **동일 물리 AI 1대:** 단독 완주 → 다른 차량 회피 → 접촉 → 복구 → 경쟁 순서로 시험한다. 이후 챕터 4를 연다.
7. **선택 연속 도전과 정산:** 플레이어가 잃을 범위를 명시하고 저장 경계 시험을 먼저 작성한다. 이후 챕터 5를 연다.
8. **결승과 전용 연출:** 검증된 이벤트를 조합하고 차고의 보상 장식을 만든다. 이후 챕터 6을 연다.

챕터마다 “문구 작성 완료”와 “플레이 가능”을 구분한다. 조건을 통과하지 못한 챕터는 잠긴 계획 상태로 남긴다.

## 7. 품질 통과 기준

### P0/P1 — 기능 확대 전에 반드시 막을 문제

AGENTS 기준으로 데이터 손실·실행 불가는 P0, 조작 고착·진행 차단은 P1이다. 아래는 출시 전 해결해야 할 실패 경로를 함께 나열한다.

- 시작·카운트다운·일시정지·완주·차고 귀환 중 입력이 고착되거나 차량이 의도치 않게 움직이는 문제.
- 게이트 건너뛰기, 역주행, 복구를 통한 유효 기록 획득, 두 번 완주 처리.
- 라이선스 중복 지급, 기존 PB/설정 소실, 새로고침으로 보상 복제.
- 결과 상태와 차고 표시 불일치, 아직 없는 챕터로 진입해 막히는 문제.
- 소리 기본 음소거·일시정지/종료 시 정리·실패 시 안내의 회귀.

### P1/P2 — 운전과 이해 가능성

- 기본 45초·여유 60초·상위 36초 목표는 실제 키보드/터치 주행으로 각각 검증한다. 상위 목표를 필수 진행에 섞지 않는다.
- 왜 성공 또는 실패했는지 결과에 표시한다. 자동 감속 중에는 결과 UI의 조작과 차량 입력 우선순위가 충돌하지 않는다.
- 결과에서 빠르게 재도전하거나 차고로 돌아갈 수 있다. 반복 시 브리핑과 연출을 다시 강제하지 않는다.
- 화면 중앙의 도로·코너·앞 차량 시야를 유지한다. 터치 조작과 음소거/메뉴 버튼이 겹치지 않는다.
- 코너 진입 전 판단할 수 있는 거리, 제동 정보, 카메라 안정성을 확인한다. 최고 속도 숫자만 기준으로 삼지 않는다.

### 저장·회귀 시험

- 기존 프롤로그, 신호소 왕복, 자유주행, 단독 스프린트와 PB를 각각 다시 확인한다.
- 목표 선택 → 중단 → 재시작, 완주 → 즉시 재도전, 완주 → 새로고침, 결과 → 차고 → 재입장의 상태 조합을 시험한다.
- 실패한 기록이 성공 기록을 덮지 않고, 여유 목표의 성공을 기본 목표 성공으로 잘못 표시하지 않는지 확인한다.

### 기기·성능·재미 시험

- 실제 삼성 기기의 **모델명, 운영체제, 브라우저, 화면 방향**을 기록한다. “삼성 표준”이라는 표현만으로 인증하지 않는다.
- 가속+조향 동시 터치, 손가락이 버튼 밖으로 나가는 경우, 앱 전환 후 복귀, 회전, 음소거를 시험한다.
- 동일 구간의 프레임 시간·메모리·렌더 호출을 변경 전후 비교한다. 목표 프레임률과 화면 품질은 기기 확인 후 정하고, 자동 화면 크기 검사만으로 실기 성능을 선언하지 않는다.
- 처음 보는 플레이어에게 목적과 다음 행동을 설명 없이 확인한다. 첫 완주 이후 자발적으로 다시 달리는지, 실패 이유를 이해하는지 관찰한다.
- 자동 시험 통과는 규칙과 회귀의 증거이지 재미·청음·장시간 안정성의 증명이 아니다.

## 8. 이번 작업의 완료 보고에 포함할 것

- 실제 구현한 챕터와 플레이 가능한 범위.
- 목표 시간과 보상 규칙, 기존 저장 보존 방식.
- 실행한 자동 시험 및 브라우저 검증의 실제 결과와 증거 경로.
- 실패한 시험, 미실행 항목, 실제 삼성 기기 확인 여부.
- 로컬 반영인지 운영 배포인지의 구분.

**현재 기록:** 챕터 1의 정차 브리핑, 3초 카운트다운, 3게이트 주행, 자동 감속, 결과, 차고의 라이선스·기록 표시가 이번 연결 범위다. 새 컷신·3D 보상 장식·고스트·물리 AI·경찰·다음 챕터는 완료 범위가 아니다. [검수 기록](HORIZON_CLUB_CHECKS.md)에 이번에 실행한 범위만 구분해 보고한다.
