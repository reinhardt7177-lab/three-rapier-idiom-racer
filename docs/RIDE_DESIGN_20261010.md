# 주행 설계 적용 · 2026-10-10

## 결과

[레포 비교 설계](RACING_REPOSITORY_COMPARISON_20261010.md)를 따라 **기존 Rapier 주행 기반을 수정했다.** Blender 차량8종·맵·차고는 유지했다. 새 엔진으로 이전하거나 참고 레포의 모델·코드를 복사하지 않았다. 현재 로컬 웹은 [5191](http://127.0.0.1:5191/)에서 확인한다.

반복 흔들림의 주된 원인은 타이어/차체 지지 계산 뒤에 차체와 도로의 충돌 계산이 다시 차를 밀어 올리는 것이었다. 실제 산길의 접지 전환에서 큰 충격이 발생했다. 단순히 화면에 보이는 차체의 각도나 카메라만 고정해서 해결한 것은 아니다.

## 적용 내용

### 1. 차체를 지지하는 계산을 하나로 정리

- 네 바퀴의 실제 접점으로 차 아래의 도로 평면을 추정한다. 접점이 한 평면에 맞지 않으면 도로 표면의 법선을 함께 사용해, 한 바퀴가 연석에 올라갔다고 차 전체의 도로 경사가 바뀌지 않도록 한다.
- 실제 접지가3개 이상이면 지지를 시작하고, 이미 지지 중일 때는2개로 유지한다.0~1개, 뒤집힘, 급경사, 실제 점프 조건에서는 지지를 해제한다. 접지를 잃은 상태에서 차량을 도로에 붙이지 않는다.
- 수직 보정을 제한된 합산 충격량으로 적용한다. Rapier의 타이어 수평 힘·독립 서스펜션·바퀴 회전은 유지한다.
- 지지 중인 **현재 바닥 충돌체와 차체 사이**의 중복 충돌 반응만 제외한다. 벽·다른 차·공중 낙하·뒤집힌 지붕의 바닥 충돌은 계속 Rapier가 처리한다. 차량의 충돌체 크기와 CCD는 유지했다.
- 공유 월드와 단독 시험 모두 `stepVehicleWorld`를 사용한다. 설치된 Rapier0.20은 이벤트 큐를 전달하는 경로에서 접촉 필터를 적용하므로, 외부 큐가 없는 단독 시험도 내부 큐를 사용한다. 차량을 제거하면 내부 큐와 등록을 해제한다.

[차체 지지](../src/rebuild/activeRide.js) · [월드 충돌 처리](../src/driving/vehicleWorld.js) · [차량 물리](../src/driving/physics.js)

**범위:** 바퀴가 지지하는 바닥 메시에 대한 차체 충돌 반응을 생략하는 아케이드 방식이다. 같은 메시에 바닥과 벽이 합쳐진 새 맵을 도입하면 이 필터를 다시 검증해야 한다. 현재의 분리된 벽 충돌 검사와 기존 맵 검사를 통과했다. 현실 차량의 모든 밑바닥 접촉을 재현하는 방식은 아니다.

### 2. 차량 설정이 실제 힘에 반영되도록 연결

| 설정 | 실제 반영 |
| --- | --- |
| 접지력 | 타이어 마찰 한계·횡방향 힘, 실제 코너 궤적 |
| 앞뒤 구동 배분 | 각 바퀴의 엔진 힘; GT-R40:60, Huracán35:65로 조정 |
| 앞뒤 제동 배분 | 각 바퀴의 제동 충격량 |
| 조향 응답 | 속도별 앞바퀴 조향 한계 |

배분과 수치는 게임 조정값이며 제조사의 실제 차량 시뮬레이션 데이터라는 뜻은 아니다. 기존8종의 접지 안정화와 겹쳐 실행되지 않던 안티롤·다운포스·차체 댐핑 값은 현재8종 설정에서 제거했다. 이 기능을 임의로 켜서 두 지지 계산이 다시 경쟁하게 만들지 않았다.

### 3. 프레임과 물리 시간을 분리

렌더링 간격이100ms일 때도120Hz 물리12단계를 처리한다. 매 프레임 시간을50ms로 자르던 처리로 인한 누락을 제거했다. 한 프레임의 작업은12단계, 누적 지연은250ms로 제한한다. 그보다 큰 멈춤에서 버린 시간은 기록하며, 일시정지·재출발 시 누적 지연을 초기화한다. 모든 긴 멈춤에서 실제 시간을 완전히 보존한다는 뜻은 아니다.

DOM의 기존 `data-telemetry`에 차체 지지 상태·접점 평면 오차·수직 보정·실제 프레임 간격·누락 시간·카메라 포즈를 추가했다. 화면 HUD에는 진단 값을 추가하지 않았다.

## 실제 맵 계측

수프라1대, 원래 맵의160개 충돌체, 같은 자동 경로 추종 방식·시작 위치·차량 설정으로6.84km 한 바퀴를120Hz 시뮬레이션했다. 변경 후 주행 궤적·접지 전환이 달라져 샘플 수가 조금 다르다. 브라우저 FPS나 사람의 승차감 점수가 아니며, 수직 가속도에는 정상 경사 변화·점프·착지도 포함한다.

| 구간 | 최대 수직 가속도 전→후(m/s²) | 수직 가속도 RMS 전→후(m/s²) |
| --- | --- | --- |
| 항구 | 9.88→1.27 | 2.39→0.51 |
| 해변 | 0.81→0.29 | 0.21→0.07 |
| 도심 | 22.60→14.19 | **1.54→1.82** |
| 산길 | **392.66→38.65** | **6.78→1.34** |
| 등대 | 3.10→1.13 | 0.72→0.36 |
| 다리 | 8.18→1.50 | 1.09→0.32 |

산길 최대 충격은 약90% 줄었다. 차체 위쪽 방향으로 계산한 최대 기울기 변화 속도는12.39→1.92rad/s, RMS는0.319→0.079rad/s였다. 물리 각속도만 읽으면 직접 적용되는 지지 회전을 놓치므로 실제 차체 자세의 변화도 계측했다.

도심은 최대 기울기 변화3.51→0.50rad/s, RMS0.088→0.049rad/s, 접지 변화7→0회로 개선됐다. **수직 가속도 RMS는 약18% 증가했다.** 모든 구간·모든 지표가 개선된 것은 아니다. 연석 구간의 실제 운전 체감과 같은 고정 구간 반복 검수를 다음 우선순위로 둔다. 산길1310~1311 부근의 짧은 접지 해제와 물리 착지 충격도 남아 있다. 완전한 무진동을 선언하지 않는다.

## 설계의 다음 단계

이번 적용은 계측·기본 컨트롤러 지지 책임·실효성 있는 설정·프레임 처리까지다. ecctrl식 타이어 각속도/미끄러짐 곡선과 형태 캐스트를 사용하는 새 타이어 모델은 제품에 넣지 않았다. 위 도심·산길 구간을 고정한 A/B 시험을 먼저 만들고, 운전 감각과 CPU 비용에서 이점이 확인된 경우에만 확대한다. 현재 변속 RPM은 도로 속도 기반 근사이며 독립적인 엔진/타이어 회전 관성을 구현한 것은 아니다.

공개 GitHub Pages는 갱신하지 않았다. 모델·Blender 원본 삭제, 커밋·푸시·운영 배포도 이번 변경에 포함하지 않는다.
