# 여수 밤바다 · 위성/현장 사진 기반 도로 주변 제작

2026-10-13 맵별 병렬 작업의 여수 담당 결과다. 기존 8.90km 주행 경로·도로·충돌·원본 GLB/Blender는 그대로 두고, **실제 OSM 해안선의 부두와 산책로, 두 교량의 하부/난간 구조, 공식 좌표의 하멜등대**를 새 Blender 모델로 제작했다. 기존 야경 조명/반사를 사용하는 별도 시각 레이어이며 런타임 통합·전체 회귀·GPU 프레임과 주행 화면 검증은 부모 작업의 별도 결과를 따른다.

**후속 화면 검사에서 발견된 육지 부재도 보완했다.** 최종 독립 GLB는 **4,830,744bytes /117,560tri**, 관련 시험은 **8/8 통과**다. 아래 2.899MB·6개 시험은 장식 레이어 완료 시점의 이력이며, 건물을 받치는 육지층 추가의 최신 결과는 마지막 절을 따른다. 기존 3MB 장식 예산을 수정해 문제를 숨기지 않고, 육지층은 제작 전에 별도 2MB/80,000tri 예산을 정했다.

## 장식 레이어 구현과 재생성 · 육지 추가 전 이력

- 생성기: `scripts/blender/build_yeosu_roadscape.py`
- 편집 가능한 원본: `assets-sources/yeosu/roadscape.blend` (**448,610 bytes**)
- 게임 에셋: `public/assets/rebuild/yeosu-roadscape.glb` (**2,898,940 bytes**, Draco 불필요)
- 생성 근거: `artifacts/roadscape-20261013/yeosu/asset-report.json`
- 실행: Blender 5.2의 `--background --python scripts/blender/build_yeosu_roadscape.py`.

부두는 원본 해안선을 최대12m 구간으로 나눈 192개 옹벽/덮개와 191개 기초/산책면, 97개 계류 말뚝·고무 완충재로 구성한다. 바다 아래까지 내려가는 기초가 산책로를 받친다. 해안선 방향의 육지 쪽으로만 폭5.3m 산책면을 두며, 도로와 너무 가까운 후보는 생성하지 않는다. 하멜 방파제 끝은 새 위성 영상/공식 위치를 대조해 포함했다.

돌산·거북선 교량은 기존 경로의 높이와 방향을 따라 데크 옆면, 하부 플랜지/보강판, 수면 아래까지 내려가는 교각·받침, 도로 바깥 난간/발광 표식을 추가한다. 원래 주탑/케이블/아스팔트를 겹쳐 복제하지 않는다. 수평 해안선/등대는 실제 좌표를 사용하지만 **교량 높이·폭, 부두 높이, 난간/세부 치수는 기존 레이스에 맞춰 제작한 값**이다.

192개 부두가 각각 렌더 객체가 되는 방식은 피하고 **128m 공간 셀 × 공유 재질 × 품질 tier**로 합쳤다. 최종 전체맵 **189개 메시·8개 재질·51,952삼각형**이며, 실제 화면 호출은 부모의 거리/시야 제한으로 측정해야 한다. `roadscapeVisualOnly=true`, `roadscapeCell=[x,z]`, `roadscapeTier=1/2` extras를 넣었다. 루트 world 위치/회전/스케일은 identity이며, `Road_Asphalt`/`Terrain`/`RaceBarrier`와 충돌 annotation을 새 파일에 넣지 않는다. 새 이미지 텍스처·실시간 광원·그림자 패스는 모두 **0**이다.

통합 권장 거리: 높음300m·보통180m·낮음비표시. tier1은 옹벽/산책로/교량 주구조와 등대, tier2는 난간/줄눈/볼라드 등 세부다. 생성 보고서의 보통 tier1은 제작 시 최소안이며, 부모 런타임에서 보통 tier1·2를 표시하더라도 거리 예산과 실제 프레임 검수로 판정한다. 낮음에서는 새 모델의 네트워크 요청도 늦추거나 생략할 수 있다.

원본 변경 전 해시/파일 존재 기록은 `before/`에 남겼으며 수정 시작 시 담당 파일은 모두 새 파일이었다. 제작 중간본도 별도 파일로 보존했다. 공유 runtime/package/기존 제작 스크립트 수정, 커밋·푸시·PR·배포는 담당 작업에서 수행하지 않았다.

## 후속 · 건물이 바다 위에 떠 보이는 원인과 지면 보완

부모의 실제 렌더 `final-yeosu-846-after.png`, `final-yeosu-1811-after.png`를 직접 읽고 원본 제작 코드를 대조했다. 기존 `korea_course.py`는 여수 `Terrain` 전체를 y=-5 바다 평면으로 만들며, OSM 건물을 y=2부터 올리지만 육지 면을 만들지 않았다. 따라서 건물 위치를 정확하게 배치해도 7m 아래 바다만 보여 건물이 떠 보였다. 새 폭5.3m 호안도 받쳐 줄 넓은 육지가 없어서 독립된 판처럼 보였다.

또한 기존 `build-yeosu-map-route.py`는 해안선의 **전체 중심점**이 도로에서600m 넘으면 해당 해안선 전체를 제외했다. 그 결과 돌산 해안501노드의 way845239874와 북동쪽22782620, 서쪽559741849가 `mapped-scenery.json`에서 빠졌다. 이 원본10개 해안선은 `yeosu-osm-20261012.osm`에 남아 있었으므로 새 helper `scripts/blender/yeosu_land_geometry.py`가 원본 세그먼트를 직접 읽는다. 기존 파생 데이터나 주행 경로를 다시 쓰지 않는다.

OSM의 ‘육지는 진행 방향 왼쪽’ 규칙과 동쪽 방향의 첫 해안선 교차를 사용해 각 지점의 육지/바다를 구분한다. 기존 건물 범위190m를 포함하는 도로 주변270m를 만들고, 실제 육지로 판정된 곳만 y=1.98 평면으로 연결해 기존 건물 바닥2와 접합한다. 내부16m·해안/도로 가장자리4m 격자를 사용하므로 해안 경계의 세부는 최대 한 격자 수준으로 단순화된다. 산 고도/절벽/토양의 측량 재현은 아니다. 도로 전체 반폭+1.2m 후보 여유와 최종삼각형 최소1m 시험은 유지한다.

지면은 다른 장식과 같은128m 셀로 나누고 공유재질1개를 사용한다. `roadscapeFoundation=true`로 표시해 부모 런타임에서 건물보다 먼저 사라지지 않도록 별도로 거리 관리한다. 장식의 낮음 비표시와 달리 기반 육지는 낮음에서도 필요한 거리까지 유지하는 대상이다. 실제 적용 거리와 프레임 비용은 부모 통합 결과를 따른다.

사전 예산은 **장식3MB/65,000tri 유지 + 육지2MB/80,000tri**, 합5MB 이내다. 최초 육지 포함본은6,002,484bytes로 초과해 `land-initial-oversize-report.json`을 보존했다. 동일 셀에서 위치가 정확히 같은 지면 정점을 공유하도록 용접하여 도로/경계/삼각형 표면을 바꾸지 않고4,307,856bytes로 줄였다. 중간 8개 시험은 전부 통과했고 기존 장식189개 메시의 정점/인덱스는 바이트 단위로 같았다. 원래 제작되는 **건물360개 중심 전부 지면 지원**을 실제 GLB 수직 레이로 확인했다.

지면 가장자리에 y=-6까지 내려오는 옆면을 추가하자5,147,060bytes로 육지2MB 예산을 다시 초과했다. 이 실패는 `land-sealed-oversize-report.json`, `land-sealed-unmerged-report.json`, `blender-build-land-final.log`에 보존했다. 추가 수출 전에 실제 POSITION/NORMAL float32와 uint16 인덱스 구조로 바이트를 계산했다. 같은128m 셀 안에서 동일 평면의 연속 옆면을 합치면10,134개가4,860개로 줄며 외곽 선과 노면 여유는 유지된다. 버퍼 절감 계산의 예상4,830,620bytes 대비 최종 파일은124bytes 큰 **4,830,744bytes**였다. `land-budget-before-final.json`에 계산 근거를 남겼다. 검사 기준을 변경하지 않았다.
