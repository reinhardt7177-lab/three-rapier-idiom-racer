# 온라인 1:1 대전 · 2026-10-12

## 결과와 공개 범위

사용자가 선택한 **두 사람이 온라인으로 대결**하는 모드를 구현했다. 차고에서 온라인 1:1 → 방 만들기 → 초대 링크 전달 → 두 사람 준비 → 출발 순서다. 먼저 만들었던 AI 1:1은 연습 모드로 남겼다. 기존 6대 레이스와 챔피언십은 별도 모드다.

최신 요청에 따라 같은 `codex/korea-circuits-progression-20261011` 브랜치를 GitHub에 올리고 Vercel에 배포한다. 기존 해안 회귀 실패와 미완료 여수 교통·메달 검증 때문에 이번 공개는 **테스트 Preview**로 분류한다. main 커밋·병합·PR 생성은 하지 않는다. 배포 주소와 최종 전체 검사 결과는 아래 배포 기록에 추가한다.

## 구현

- PeerJS 1.5.5는 방 생성·참가 때만 읽는다. 공개 PeerServer는 연결을 중개하고 실제 경기 데이터는 WebRTC 채널로 전달한다.
- 방장이 두 대의 실제 Rapier 차량을 같은 세계에서 계산한다. 참가자는 페달·조향·니트로 입력만 보낸다. 참가자의 좌표·완주 시간·진행 거리 주장은 받지 않는다. 두 차는 같은 플레이어 튜닝을 사용하며 기존 물리·조향 상수는 바꾸지 않았다.
- 입력·화면 상태는 최대 20Hz다. 오래된 입력은 350ms 후 해제하고 약하게 제동한다. 표시 좌표는 0.1mm 수준으로 줄여 보내지만 완주·랩 시간은 반올림하지 않는다. 전송할 프레임에서만 상태를 묶고 초대 URL을 캐시한다.
- 코스 버전·차량·메시지 순서를 검사하고 세 번째 참가자를 거부한다. 두 사람 준비와 렌더 준비가 끝나야 출발한다. 공유 일시정지, 결과, 대기실 복귀, 재경기를 연결했다.
- 상대 응답이 8초간 없으면 입력을 지우고 중단한다. 임의 승리로 기록하지 않는다. 연결 중개 서버만 끊기고 실제 WebRTC가 살아 있으면 경기를 유지한다.
- 온라인 최고 기록은 방장/참가자 자리별로 분리한다. 메달·해금·싱글 기록·고스트·챔피언십 데이터를 덮어쓰지 않는다. 온라인에서는 일반 교통·AI 경쟁자·고스트를 만들지 않는다.

## 실제 검증

계산은 사용자 지시에 따라 **로컬 Windows CPU / Rapier WASM**에서 실행했다. Colab/GPU를 사용하지 않았다.

### 관련 시험과 실제 물리

- 차체 모션·대전 설정·온라인 프로토콜/연결 관련 25시험 통과. 방 준비, 버전 불일치, 세 번째 참가자, 오래된 입력, 기록 분리, 중개 서버 연결 상실 후 실제 채널 유지 등을 검사했다.
- 온라인 세계의 헤드리스 5레이스/10차량 모두 완주했다. 두 봇은 사람 대신 페달을 조작하며 두 차량 모두 플레이어 튜닝을 쓴다. 이 시험 자체에는 WebRTC가 없다.

### 실제 브라우저 연결

이 PC의 두 IAB 탭을 실제 PeerServer/WebRTC로 연결했다. 실제 사람이 장시간 두 기기에서 운전한 검수가 아니라, 보이는 DEV 자동 페달과 일부 실제 키보드/포인터 조작으로 확인한 결과다.

| 첫 성공 대전·수프라 2대 | 77.908333초 | 84.341667초 | 양쪽 결과 시간 동일·복귀0 |

참가자 메뉴로 두 창이 멈추고 입력 throttle/brake/reverse/steer가 0, handbrake/boost가 false인 것을 확인했다. 키보드 W+D와 GAS 포인터 후에도 해제됐다. 재출발 준비 도중 참가자 탭을 닫은 검수에서는 방장에게 응답 없음·재개 불가, result=null·입력0이 표시됐다. **주행 도중 탭 종료 검수와는 구분한다.**

### 화면 크기

온라인 대기실과 주행 HUD는 1280×720, 1024×768, 844×390, 667×375의 실제 DOM 경계를 확인했다. 16:9 게임 영역은 각각 1280×720, 1024×576, 약694×390, 약667×375이며 측정한 버튼/카드 잘림·겹침0이다. 온라인 결과 화면은 최종 667×375에서 확인했다. 네 크기 결과 캡처 시 도구가 배포 탭을 조절해 게임이 667에 머문 표본은 보존하되 네 크기 통과 근거로 쓰지 않는다. 같은 결과 컴포넌트의 AI 연습 모드 네 크기 검수는 별도다. 휴대폰 실기기 검수는 아니다.

## 실패·수정·성능

첫 연결 시도는 실패했으며 원인을 확정하지 못했다. 다음 연결과 이후 최종 연결은 성공했다. 재경기 대기실에서 PeerJS의 `network / Lost connection to server` 사건이 실제 WebRTC까지 닫던 오류를 재현했다. 중개 서버 오류와 실제 채널 종료를 분리하고 기존 8초 감시 기준을 유지했다. 단위 시험에서 같은 사건 후 준비/출발/입력 전달을 확인했고 최종 실제 대전·재경기도 완료했다.

한 PC에서 1280×720 두 클라이언트를 동시에 돌린 첫 대전의 최근240프레임은 평균124.17/p95 350/최대1800.1ms, >50ms 182회였다. CPU 렌더 제출 평균17/p95 51.8ms, 물리 평균47.83/p95 136.4ms다. 이 표본은 보존했으며 20ms 목표 통과로 보고하지 않는다. 서로 다른 PC의 네트워크 지연이나 한 클라이언트 A/B 성능으로 해석할 수 없다. 이후 압축/캐시 수정과 작은 참가자 화면 검수의 조건이 달라 성능 개선의 인과 근거로 쓰지 않는다.

AI 연습의 같은 단일 클라이언트 남악 낮음 30초 A/B/A는 6대 A1 평균20.34/p95 33.4ms, 2대 B 평균17.62/p95 17.4ms, 6대 A2 평균19.07/p95 33.4ms다. B의 최대100ms·>50ms5회도 남겼다. 이 결과를 온라인 대전 성능으로 대신하지 않는다.

## 남은 위험과 다음 작업

1. 기존 해안의 엄격한 노면 아래 값과 쉬움3랩 SLK 정체, 새 여수의 교통 포함 완주·옛 메달 기준을 먼저 해결해야 정식 출시 판정이 가능하다. 이번 대전 구현에서 물리·라이벌·메달 기준을 바꾸지 않았다.
2. 서로 다른 실제 PC/휴대폰과 서로 다른 통신망에서 연결·지연·장시간 운전·충돌을 검수해야 한다. TURN 서버가 없으므로 일부 NAT/회사망에서 연결하지 못할 수 있다. 방장의 창을 열어둬야 한다.
3. 공개 중개 서버 의존, 방장의 계산을 신뢰하는 친구 대전이다. 순위 경쟁용 서버나 부정행위 방지 체계로 간주하지 않는다. 참가자 엔진 소리·음악 장시간 재생과 고지연 시 시각 보간도 추가 검수 대상이다.
4. 온라인 결과 화면의 네 크기 검수를 올바른 뷰포트 대상으로 다시 수행한다.
