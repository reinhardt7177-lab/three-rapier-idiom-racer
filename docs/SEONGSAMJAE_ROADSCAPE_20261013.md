## 실제 실행한 시험

로컬 Windows CPU에서 Blender 5.2로 생성기를 실행하고, Node 실제 GLTFLoader로 최종 **6/6 통과**, 실패·skip 0, 총 **8,691.62ms**. 원자료는 `build-chevron-fixed.log`, `build-report.json`, `static-tests-chevron-fixed.log`이다. 부유선 수정 후의 5/5·14,471.52ms는 `static-tests-seam-final.log`, 최초 부유선이 남았던 후보의 4/4·10,720.75ms는 `static-tests.log`에 보존하며 최종 검증과 구분한다. 실행 시간은 같은 조건 성능 비교가 아니다. 큰 레이스 물리 계산이나 Colab/GPU 모델 계산을 했다고 표현하지 않는다.

1. 모델 크기·삼각형 상한, 편집 원본 존재, 공유 불투명 정점 색 재질, culling 가능한 공간 셀, 추가 조명·카메라·충돌 없음.
2. **32,582개 모든 삼각형**과 기존 **2,913개 모든 경로 선분**의 후보 공간 영역을 정확한 선분/삼각형 거리로 검사해 12.5m 이상 유지.
3. **1,068개 모든 지지점**을 원본 GLB의 실제 지형 삼각형과 대조해 높이 오차 2cm 미만. 모든 데크 지주·가드레일 지주·절개면 시작점이 실제 지표에 연결됨.
4. 새 실제 기하에 절개면/낙석망/배수로/W가드레일/방향판/거울/전망데크/정자가 모두 있고 개수·출처 모드 metadata가 유지됨.
5. **252개 모든 층리선**이 실제 수출된 암반 삼각형의 경계를 따라 놓였는지 검사. 해당 삼각형이 GLB에 실제 존재하며 선분의 양끝·중간점이 면에 1mm 이내로 닿는다.
6. **24개 모든 방향판**의 실제 GLB 화살표 끝과 꼬리를 경로의 접근 방향 카메라로 투영하고 앞뒤 접선으로 얻은 커브 방향과 일치함을 검사. 좌회전·우회전 모두 포함.

새 원본 생성 중 예산 초과나 도로 침범으로 실패한 후보는 없었다. 외부 사진·위성 URL 일부의 접근 실패는 위에 기록했다. 실제 렌더링의 첫 후보 검수에서는 아래의 부유 층리선을 발견했으며, 정적 도로 이격·지지점 검사만으로 모든 장식의 시각적 지지가 보장되지 않음을 확인했다. 새 모델은 표시 전용이므로 충돌 기준이나 도로 이음매를 바꿔 수치 검사를 통과시킨 것이 아니다.

## 첫 실제 화면에서 발견한 오류와 수정

통합 담당의 `artifacts/roadscape-20261013/initial-seongsamjae-250-after.png`, `initial-seongsamjae-1350-after.png`, `initial-seongsamjae-1980-after.png`를 직접 확인했다. index250 암벽 위에 길쭉한 층리선이 떠 있었다. 첫 생성기의 층리선은 도로 높이에서 일정하게 3.6/7.3/10.8m 올라가도록 했지만, 절개면 양끝의 낮아지는 높이를 따르지 않았다. 실제 암반보다 높아지는 부분이 하늘에 떠 보였다. 초기 렌더와 `before/seam-fix/`에 첫 후보 생성기·모델·시험·보고를 보존했다.

수정본은 층리선 양끝을 실제 절개 면의 공유 경계 정점에 놓고 그 선분 전체가 암반 삼각형 표면에 닿도록 만들었다. 회귀 시험은 생성 보고의 접촉면이 실제 GLB에 존재하는지, 선분의 시작·끝·중간 지점들이 해당 면에 놓이는지 검사한다. 암벽 색은 밝은 중성 회색의 무작위 면 구분에서 어두운 회녹색·갈색 풍화층·이끼의 층별 색으로 바꿨다. 사진 속 모든 암석의 정확한 색 측정이라고 표현하지 않는다.

새 접촉 시험의 첫 실행은 실제 모델 결함이 아닌 시험의 좌표 정규화 문제로 실패했다. Float64 생성 보고와 Float32 GLB를 각각 1mm 단위 문자열로 반올림하면 경계에서 서로 다른 문자열이 나왔다. 실제 최근접 삼각형의 최대 좌표 차이는 **0.00001964m**였다(`seam-float32-diagnostic.json`). 수출 자료의 실제 저장 형식인 Float32로 양쪽 좌표를 정규화해 **정점 동일성**을 비교하도록 수정했으며 도로 이격이나 접촉 허용 거리를 넓히지 않았다. 실패 로그 `static-tests-seam-fixed.log`와 첫 검사 코드를 보존했다.

1350 화면의 가드레일·반사경에서 같은 부유 오류는 관찰하지 않았다. 1980의 진행 방향 화면에는 전망대가 보이지 않았으므로 이 화면을 전망대 검수 성공 근거로 사용하지 않는다. 전망대는 `(x=-70.94, y=154.34, z=782.08)`에 있으며 경로 index1900 근처의 접근 방향 또는 해당 좌표를 보는 측면 카메라로 추가 확인해야 한다. 최종 화면·프레임 판정은 통합 보고를 따른다.

## 추가 실제 주행 방향 검수: 커브 방향판

`final-seongsamjae-250-after.png`에서는 부유 층리선 제거가 확인됐다. 이어 `final-seongsamjae-880-after.png`를 직접 확인하면서 좌회전 곡선의 신규 노란 방향판이 오른쪽을 가리키는 별개의 오류를 발견했다. 원본 맵 표식이 아니라 이 작업에서 새로 추가한 `chevron-arrow`였다. 원인은 판의 도로 배치 측면 부호를 화살표 방향에도 사용한 것이었다. 생성기의 가로축 `(dz, 0, -dx)`은 접근 운전자에게 화면 왼쪽인데 이를 오른쪽으로 해석했다.

수정본은 각 방향판의 앞뒤 경로 접선으로 실제 커브 방향을 계산해 화살표를 회전한다. 도로 안쪽/바깥쪽의 설치 위치와 안내 방향을 별개의 값으로 처리한다. 새 회귀 시험은 24개 화살표의 실제 GLB 끝점·꼬리점을 확인하고, 경로 진행 방향의 화면 오른쪽 축 및 실제 PerspectiveCamera 투영 양쪽으로 길의 회전 방향과 일치하는지 검사한다. 좌회전·우회전 사례를 모두 포함한다. 도로·원본 표식·충돌 데이터는 바꾸지 않았다.

수정 전 생성기·GLB·Blender·보고는 `before/chevron-fix/`에 보존한다. 이 문제는 첫 부유선과 다른 원인이며, 실제 시야 검수로 발견한 방향 안내 결함이다. 기존의 단순 구성요소 개수 시험을 통과했더라도 올바른 안내 방향이 보장되는 것은 아님을 기록한다.
