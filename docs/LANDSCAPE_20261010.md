# 가로 화면 고정과 운전석 하단 수정 · 2026-10-10

## 사용자 문제와 수정

세로로 긴 Codex 브라우저 창에서 게임과 운전석이 세로 비율로 표시되고, 대시보드 아래로 도로가 보여 실내가 떠 보였다. **게임과 모든 HUD를 같은 16:9 가로 화면에 배치**했다. 창보다 큰 부분을 잘라 내거나 화면을 늘리지 않고, 남는 공간에 여백을 둔다.

- PC의 좁고 긴 창에서도 가로 게임을 표시한다.
- 터치 기기의 세로 화면은 회전 안내로 가리고 게임 UI를 `inert` 처리한다. 주행과 음악을 정지하고 모든 입력을 해제한다. 가로로 돌아와도 자동 가속·자동 재개하지 않는다.
- 전체 화면 버튼을 차고와 일시정지 메뉴에 추가했다. 실제 버튼 클릭에서 전체 화면 전환 후 `screen.orientation.lock('landscape')`를 요청한다. 잠금 거절·API 부재를 성공으로 표시하지 않는다.
- 화면 회전은 바깥 창의 방향으로 감지한다. 게임 화면 자체가 항상 가로이므로 게임 화면 크기만 감지하면 휴대폰의 회전을 놓치는 문제를 방지했다.
- HUD는 브라우저 창이 아닌 게임 영역의 크기에 반응하는 container query를 사용한다. 낮은 가로 화면에서는 터치 버튼을 한 줄로 정리하고, 메뉴는 영역 안에서 스크롤한다. 버튼의 최소 높이는 44px이다.

## 실내 모델과 레퍼런스

[GT7 공식 Racing Views](https://www.gran-turismo.com/us/gt7/manual/race/03)의 실제 운전석 이미지를 브라우저로 확인했다. 연결된 실내 하단, 계기판 덮개, 가장자리의 HUD 배치를 참고했다. Forza 관련 공식 사이트도 검색했지만 이번 수정의 확인 가능한 화면 기준은 GT7이다. 게임 모델은 직접 만든 공통 커스텀 실내이며, 해당 게임의 에셋을 복사하거나 브랜드 실내를 정확히 재현한 것은 아니다.

Blender 원본에 발밑 바닥, 문 안쪽 패널·팔걸이, 연속된 대시보드, 곡면 계기판 덮개, 스티어링 칼럼과 패딩 허브를 추가했다. 짧은 막대처럼 끝나던 창틀을 위쪽 프레임까지 이어지도록 수정했다. 가죽과 금속의 밝기·거칠기, 실내 보조광을 낮췄다. 실제 물리 조향·속도·RPM 피벗과 웹 수출 구조를 유지한다. GLB는 17개 메시, 655,612바이트다.

편집 원본: `assets-sources/cockpit-v1/cockpit.blend` · 재생성: `scripts/blender/build_cockpit.py` · 게임 모델: `public/assets/rebuild/cockpit.glb`.

이전 원본·수출 모델·스크립트·사용자 스크린샷은 `artifacts/landscape-20261010/before/`에 보존했다. 정리 도구도 이번 원본과 검증 자료를 보존하도록 갱신했다. 삭제·커밋·배포를 실행하지 않았다.

## 실패 증거와 검증

- 수정 전 실제 GLB에 카메라 광선을 쏘는 검사가 실패했다. 하단 왼쪽으로 실내 밖의 도로가 보였다. `check-initial.log`에 보존했다.
- 덮개를 여러 막대로 만들었던 중간 모델이 실제 화면에서 부채꼴로 보였다. `canopy-initial-failure.png`에 남기고 연결된 곡면 메시로 수정했다.
- 160개 기존/신규 회귀 검사와 웹 빌드 통과: `check-final.log`. 곡면 덮개 수정 후 관련 검사 10개도 다시 통과: `check-final-cockpit.log`. 마지막 CSS 버튼 높이 수정 후 별도 최종 빌드: `build-final.log`.
- 신규 검사는 16:9 맞춤·회전 차단·두 손가락/키보드 입력 해제·수동 재개·전체 화면 및 잠금 실패를 확인한다. 실제 GLB에서 일반/작은 가로 카메라의 하단 9개 지점이 실내로 가려지고 위쪽 중앙 유리창 시야가 열리는지 확인한다.
- 로컬 IAB에서 좁은 기본 창, 1280×720, 844×390 크기의 가로 화면, 키보드·터치 가속 후 입력 해제, 메뉴·화면 크기 변경 후 정지, 두 음악 선택, 전체 화면 진입·종료, 차고 복귀를 확인했다. 마지막 빌드의 화면·DOM 치수는 같은 폴더의 이미지와 `browser-proof.json`에 기록한다.

## 한계와 남은 작업

화면 크기 에뮬레이션은 실제 휴대폰 검증이 아니다. IAB의 PC 전체 화면 전환은 확인했지만 실제 휴대폰의 회전 잠금·멀티터치·앱 전환은 아직 확인하지 않았다. [MDN 회전 잠금 설명](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock)에 따라 지원되지 않는 브라우저에서는 회전 안내가 필요하다. 가로 비율 고정과 기기 자체의 회전 잠금은 구분한다.

전체 차량·환경의 AAA급 시각 품질이나 출시 완료를 의미하지 않는다. 다음은 실내 소재·문과 창틀의 연결·주행 중 전방 시야를 실제 화면으로 검수하고, 실제 휴대폰에서 회전·입력·성능을 확인하는 작업이다. 공개 GitHub 사이트는 이번 변경을 반영하지 않았다.
