# 남은 결함 재개 · 2026-10-12~13

사용자의 “나머지 다시 작업 들어 가세요” 요청으로 같은 작업 브랜치 `codex/korea-circuits-progression-20261011`에서 재개했다. 시작 HEAD는 `549a270`, 추적 파일 변경은 없었다. 변경 전 파일/시각/해시는 `artifacts/release-repair-20261012/before/`와 `session.json`에 보존했다. 이전 증거·사용자 진행도·비밀 파일은 삭제하거나 출력하지 않았다.

## 범위와 우선순위

1. 해안 보통 맑음/비의 노면 이탈과 쉬움 3랩 미완주를 고친다.
2. 실제 지도 여수의 일반 교통 뒤 긴 따라가기와 잘못된 메달 기준을 고친다.
3. 실제 브라우저 흐름·입력 해제·네 화면 크기·성능을 확인한다. 브라우저 제어가 세 번 연속 응답하지 않은 뒤 사용자가 “화면 검수는 나중에”로 결정해, 이후 화면/프레임 검수는 보류한다.

물리 접지·조향·충돌체·activeRide 자세 고정과 난이도/니트로 설정은 유지한다. AI는 실제 페달/조향만 사용하며 위치나 진행 거리를 보정하지 않는다. 전체 검사가 통과한 단위만 다음 구현으로 진행한다. PR/main 병합은 하지 않으며 이번 재개 요청을 새 배포 완료로 표현하지 않는다.

계산은 이전의 사용자 지정 “연결없이 하셈”에 따라 로컬 Windows CPU/Rapier WASM에서 실행한다. Colab/GPU 활용이라고 표현하지 않는다.

## 해안 원인과 첫 수정

기준 실행을 현재 코드로 재현했다. 포르쉐는 도로 중심에서 -30.86m, 수프라는 -21.63m까지 이탈해 실제 잔디를 밟았다. 바퀴 지지면과 아래 방향 레이 검사로 경로 높이 오차만의 문제가 아님을 확인했다.

앞에서 추월 중인 RX-7이 빠르게 접근하는 뒤차 때문에 차선 변경을 계속하지 못하면, 도로 가운데서 정지 페달을 내보냈다. 뒤차가 충돌해 큰 회전 속도로 밀려났고 다음 차량도 같은 상황에 걸렸다. `rivalPlanner.js`는 이미 시작한 횡이동의 충돌 원인이 뒤차뿐일 때 현재 아스팔트 차선을 유지하며 앞으로 진행하게 바꿨다. 앞차/옆에서 끼어드는 차의 예측 충돌 검사와 평소 전방 제동은 유지했다. 정지 상태를 다른 숫자로 판정하거나 충돌을 끄지 않았다.

쉬움 3랩의 SLK도 기준 실행에서 산길 벽을 바라본 채 가속만 하며 멈췄다. 앞선 충돌 판단 수정 이후 이 정체가 재발하지 않아 별도 후진/복귀 기능은 추가하지 않았다.

## 첫 전체 회귀와 추가 실패

첫 `npm run check`는 **348개 중 347통과/1실패**였다. 기존 해안 완주 실패는 재발하지 않았고 맑음 24레이스/144대와 비 14레이스/84대가 모두 완주했다. 실패는 정지한 뒤차의 기존 판단 `defer-crossing`을 새 후방 양보 판단 `yield-rear`가 가로챈 단위 시험이었다. 기존 기대값을 바꾸지 않고, 실제로 빠르게 접근하며 횡이동을 막는 뒤차만 새 분기로 처리하도록 조건을 좁혔다. 관련 5개 시험이 통과했고 두 번째 전체 회귀를 시작했다. 첫 검사는 실패 때문에 빌드 단계가 실행되지 않았다.

첫 실행기 경과 65,996.79초에는 PC가 작업을 진행하지 않은 밤 사이의 공백이 포함되어 있다. 이를 연속 코딩/연속 계산 시간으로 주장하지 않는다. 실행 로그와 모든 실패 표본을 보존했다. 검사 중 입력 해시 변경은 0개였다. 옛 시험이 덮어쓰는 증거 12개는 새 사본을 보존하고 원래 내용으로 복구했다.

여수의 첫 이동 앞차 재선택 후보는 보통 1랩/일반 차량 6대에서 6/6을 281.63~302.44초에 완주시켰지만, 쉬움에서 포르쉐가 420초에 7,133m로 미완주했다. 이 실패는 `candidate-yeosu.json`에 남겼다. 추락/오프로드는 없었으며 제한 시간을 늘리지 않았다.

추가 추적으로 차간 거리가 약 8.59m까지 좁아졌는데도 기존 속도 계산이 음수 간격 오차를 0으로 잘라 앞차와 같은 속도만 유지하는 것을 확인했다. 그래서 9m 이상이 필요한 추월을 시작할 공간이 생기지 않았다. 일반 교통이 있는 레이스에 한해 기존 12m 목표 간격을 회복하도록 시험한다. 추월 중에는 이 보정을 적용하지 않고, 기존 무교통 레이스/정지 앞차 제동은 그대로 유지한다. 이 후보와 느린 이동 앞차 재선택은 별도 스크립트로 검증하며 제품 소스에 아직 합치지 않았다.

## 브라우저에서 실제로 확인한 범위

- 정적 개발 QA 빌드 차고의 요청 크기 1280×720/1024×768/844×390/667×375에서 잘림/겹침은 각각 0개였다. 제품의 기본 조작부와 임시 자동 페달 버튼 1개를 함께 측정한 결과이며, 정확히 같은 제품 빌드 전체 UI의 통과로 표현하지 않는다. 실제 게임 내용은 가로 비율을 유지한다. `clean-garage-ui.json`과 네 캡처에 수치를 남겼다.
- 남악 정적 QA 빌드에서 6대 실제 완주와 수프라 85.183333초/5위/동메달/복귀0을 확인했다. 나머지 시간은 81.433333, 84.066667, 84.316667, 84.733333, 85.525초였다. 자동 페달을 사용한 개발 QA 빌드이며 사람이 운전한 결과/배포 빌드 결과로 표현하지 않는다.
- QA 빌드의 별도 출력 폴더에는 기존 Vite 설정 때문에 GLB가 복사되지 않아 로딩 오류가 났다. 해당 QA 폴더에 기존 공개 에셋을 복사한 뒤 로딩과 위 완주를 확인했다. 기본 제품 출력 폴더의 결함으로 단정하지 않는다.
- 결과 화면의 네 크기 검사는 브라우저 도구 응답 실패로 끝나지 않았다. `result-1280x720.png` 한 장은 저장됐지만 전체 화면 통과 근거로 사용하지 않는다. 이후 사용자가 화면 검수를 보류했다.
- 새 고정 조건 30초 프레임 A/B, 온라인 서로 다른 기기/통신망, 휴대폰 실기기는 검증하지 못했다. 동시 CPU 검사 중의 프레임 표본을 제품 성능 기준으로 쓰지 않는다.

## 진행 중 / 아직 통과하지 않은 항목

- 좁힌 후방 양보 조건의 전체 회귀가 진행 중이다. 검사 중 소스 해시를 고정하고 옛 시험이 쓰는 보고서 사본을 이번 작업 아래 보존한 뒤 원본 증거를 복구하는 실행기를 사용한다.

- 개발 `qaPerf`의 임시 버튼 4개가 짧은 두 화면에서 차 선택과 겹친 표본을 `garage-ui.json`에 보존했다. 이를 제품 UI 통과 표본으로 사용하지 않는다. 위 제품 조작부 검사는 해당 패널을 끄고 별도로 실행했다.
- 첫 해안 브라우저는 산길 87.60초/복귀0까지 확인했지만 화면 변경 정지와 검수 탭 정리로 중단됐다. 완주 증거가 아니며 정지 화면 캡처도 코너 주행 검수로 사용하지 않는다.
