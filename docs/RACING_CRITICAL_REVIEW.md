# 레이싱의 재미와 GT 디자인 재점검

검토: 2026-09-07–08 (한국 시간). 목표는 ‘최고’라는 선언이 아니라, 다시 달릴 이유와 차를 조작하는 만족감을 검증 가능한 단위로 만드는 것이다. 외부 모델·차고 스타일·기존 저장 기록을 바꾸지 않는다.

## 냉정한 진단

| 문제 | 확인 근거 | 플레이어에게 생기는 문제 | 우선 대응 |
| --- | --- | --- | --- |
| 레이싱보다 이동 의뢰에 가까움 | `journey.js`는 시간제한 없이 40–60km/h 권장, 정차와 귀환으로 완료. 상대·PB·구간 기록 없음 | 완주 후 운전 실력을 개선할 이유가 약함 | 기존 이야기와 별도로 짧은 기록 모드 추가 |
| 표현이 심심한 차량 후면 | 이전 추적 화면의 후면은 큰 도색판, 단순 붉은 막대, 막힌 배기관 | 가장 오래 보는 방향에 차의 개성과 구조가 부족함 | 후미등 하우징·2단 램프·플레이트·디퓨저·배기구 보강 |
| 휠 아치 때문에 보닛까지 휘어짐 | 기존 `gt.js`는 아치의 bottom 값으로 링 전체 높이를 바꿈. 종단 캡 없음 | 위에서 보면 보닛·스트라이프가 물결치고, 일부 방향에서 속이 빈 느낌 | 휠 포켓을 차체 바깥쪽으로 한정, 앞뒤 캡과 연속 중앙 바닥 추가 |
| 잔부품마다 렌더링 | 휠 스포크·금속 막대가 개별 Mesh | 디테일 추가가 태블릿 부담으로 이어짐 | 재질별 정적 병합, 조향 피벗과 회전 휠은 독립 유지 |
| 코스가 충분히 검증된 ‘레이스 코스’는 아님 | 긴 항만 직선과 S커브, 갈림길 기반 공도. 고저차·추월·브레이킹 선택지는 제한적 | 장식이 늘어도 반복 주행의 깊이에는 한계 | 우선 기존 구간의 기록 경쟁을 검증, 이후 코너별 리듬을 재설계 |
| 자동차 물리를 조작감의 전부로 취급하면 안 됨 | Rapier·조향·속도 시험은 있으나 사람의 반복 플레이 평가 없음 | 시험 통과와 ‘운전이 맛있다’는 다른 문제 | 동일 구간 3회 기록·조향 피로·감속 판단·재도전 의사로 평가 |
| 소리와 차량 상태 피드백이 약함 | 엔진/바람 합성은 있지만 기본 음소거이고 메뉴 안에 있음. drifting은 실제 슬립 계측이 아님 | 제동·접지 회복·탈출 가속의 차이가 밋밋함 | 출발 전 소리 선택, 실제 슬립 기반 제동/타이어 음색·자국을 다음 단계로 연결 |
| 저프레임에서 실제 시간과 게임 시간의 차이 | `createDriving.js`는 프레임 dt를 0.1초로 제한. 이번 기록도 물리 시뮬레이션 시간 기준 | 심하게 느린 기기에서는 실제 플레이 시간이 늘고 기록 비교의 의미가 달라짐 | 실시간/물리시간 비율·긴 프레임을 계측하고, 공정한 온라인 기록 정책 전에는 로컬 PB로만 사용 |

이 표의 렌더링 구조는 코드에서 확인한 사실이다. ‘심심함/개성/재도전 의사’는 시각 비교와 디자인 판단이며 사용자 플레이 테스트로 검증할 가설이다. 독립 전문가 평가나 실제 삼성 기기 시험을 수행했다고 주장하지 않는다.

## 이번 수정: 비교할 수 있는 한 단위

### GT 01 차체

- 실제 4.6m 길이, 휠베이스·윤거·휠 반지름은 유지. 물리 제원을 임의로 바꾸지 않음.
- 외측 휠 포켓 + 닫힌 종단 캡 + 중앙 하부 바닥. 휠 아치 안에는 어두운 휠하우스 배면.
- 평탄한 중앙 보닛과 도로에서 읽히는 후미등·금속 번호판·배기구·디퓨저. 문 경계·보닛 통풍구·와이퍼·브레이크 디스크 추가.
- 페인트 반사 강도를 줄임. 게임 미술과 다른 사실적 외부 모델로 교체하지 않음.
- 바퀴 안에서만 회전 부품 병합, 차체는 별도 병합. 좌우 조향 피벗과 회전 중심 유지.
- 남은 빈 부분: 운전석 내부/운전자, 타이어 트레드, 비회전 캘리퍼, 실제 광원을 가진 전조등, 손상 표현은 아직 없음. 실내는 가까운 카메라를 도입할 때 별도 설계하는 것이 효율적이다.

### 해안 스프린트 01

- 항구 출발부터 갈림길 전까지 약 770m. 직선 → S커브 → 피니시의 3개 계측선.
- 3초 카운트다운, 실제 물리 주행 시간, 순방향·순서·접지·도로 폭을 검사하는 구간 통과 판정.
- 개인 최고 기록과 그 기록 대비 누적 구간 시간 차이. 첫 주행에는 가짜 비교 기록을 표시하지 않는다.
- 피니시는 통과 순간 기록을 확정하고 실제 브레이크로 감속한다. 고속 주행 중 정지 화면으로 순간 전환하지 않는다.
- 노면 이탈/도로 복귀/비연속 이동은 해당 주행을 기록 대상에서 제외한다. 완주/연습은 가능하다. 순간이동·복귀로 PB를 만들지 않는다.
- 결과 → 바로 재도전 → 카운트다운. 기록 저장 키는 `mumu.coast.sprint.v1`; 기존 이야기·차고 설정과 분리.
- 경량·표준·키보드·터치에서 동일한 차량 물리 사용. 가상 공도의 단독 타임어택이며 AI 레이스라고 부르지 않는다.
- ‘금메달 45초’ 같은 임의 난이도는 넣지 않았다. 사람의 플레이 분포를 모은 뒤 목표 기록/메달을 정한다.
- 벽 접촉에 대한 시간 벌점은 아직 없다. 접촉 충격 이벤트를 따로 계측하기 전에 속도 급감만으로 충돌을 추정해 잘못된 벌점을 주지 않는다. ‘노면 이탈 없는 기록’이 ‘무충돌 기록’과 같은 뜻은 아니다.

## 후속 순서와 통과 기준

1. **이번 구간의 운전 재미 평가:** 동일한 사람이 세 번 달린다. 완주 시간, 이탈/복귀 횟수, 어디에서 브레이크를 놓쳤는지, 자발적 재시작 여부를 기록한다. 기록을 줄이는 방법이 보이지 않으면 고스트보다 먼저 코너/조향/브레이크 피드백을 수정한다.
   이때 [기존 체감·연출 계획](DRIVING_EXPERIENCE_PLAN.md)의 P0(실시간/게임시간 계측)와 P2/P3(물리 상태에 동기화된 카메라·타이어·소리)도 이어서 적용한다. 단순 기본 속도 상향으로 대체하지 않는다.
2. **자기 기록 고스트와 피드백:** 유효한 PB의 위치·회전 샘플만 기록해 비충돌 고스트 재생. 버전 변경/저장 차단/용량 상한을 먼저 설계한다. 실제 타이어 슬립·제동을 계측해서 소리·타이어 자국을 연결한다. 핸드브레이크 키를 눌렀다는 이유만으로 ‘드리프트 성공’을 주지 않는다.
3. **대표 1구간의 코스 미술/리듬:** 항구 출발 10초 안에 속도 대비와 첫 판단이 보이도록 조명·가로등 간격·원경·감속 표지를 재배치. 블라인드 코너나 화면 흔들림으로 난이도를 만들지 않는다. 지형 변경 시 시각 노면과 충돌체를 같은 데이터에서 생성한다.
4. **경쟁 차량:** 자기 기록 경쟁의 재미와 코스가 확인된 뒤 AI 1대를 추가. 같은 물리/체크포인트/이탈 규칙으로 검증한 뒤 추월·차간 충돌로 확대한다.
5. **컬렉션/스토리 확장:** 그 이후 차량과 사건을 늘린다. 차고의 정비 일지는 스토리, 차량 선택은 운전 성격, 기록 도전은 실력 향상으로 역할을 분리한다.

브라우저 검증은 Headless Chrome 소프트웨어 GPU 환경이다. 최종 통과 실행에서 JS 오류·검사 실패는 없었지만 아래 초기 진입 지연과 실기기 미검증은 별도로 남긴다. 스프린트 화면은 계측 표지 추가로 최대 129개 호출이며 위 122는 기존 자유 주행 화면끼리의 비교다.

### 검사 범위와 남은 제한

- `scripts/gt-design.test.mjs`: 차체의 모든 인덱스 모서리가 두 면에 연결, 외향 앞뒤/상하 면, 중앙 바닥/보닛 높이, 병합 후 휠 피벗·색상·메시 수 확인.
- `scripts/sprint.test.mjs`: 카운트다운, 순서/방향/접지, 피니시 후 정차, 이탈·복귀·텔레포트 무효화, PB 갱신/저장 차단/오염 데이터.
- `scripts/capture-gt-audit.cjs`: 동일 구도의 전/후/측면과 실제 항구 화면 비교. `artifacts/gt-audit`에 보존.
- `scripts/verify-sprint.cjs`: 런타임 위치 조작 없이 실제 키 입력으로 주행하고 터치 화면·메뉴·복귀·저장을 검증. 자동 시험 운전자이지 게임 AI가 아니다.
- 첫 브라우저 실행의 새 모드 진입은 60초 타임아웃. 별도 진단 캡처에서는 화면이 렌더링되었고 JS 오류가 없었음. 같은 제한으로 재검증하며 원인이 확정되기 전 ‘해결’로 적지 않는다.
- 후속 시도에서 차고 버튼 탐색 30초 타임아웃도 발생. 첫 WebGL 프레임 준비를 확인한 뒤 조작하도록 검증 준비 절차를 보완했으며 기존 30/60초 제한은 늘리지 않았다. 이후 실제 키 주행을 완주했다. 초기 로딩 안정성은 실기기에서 계속 관찰해야 한다.
- 초기 검증 스크립트의 ‘속도는 정확히 0’ 조건은 Rapier 안정화 뒤 남는 약 `3.7e-8 km/h` 때문에 실패했다. 임의 허용 오차 대신 카운트다운 전후 속도·위치가 **변하지 않음**과 기록 시간 0을 정확 비교하도록 수정했다.
- 삼성 기기의 발열·장시간 FPS·실제 엄지 조작과 사람의 재미 평가는 미검증.
- 기존 Three.js/Rapier 번들 경고는 이번 차체/기록 작업으로 해결되지 않는다.
