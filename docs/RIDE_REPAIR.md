# 주행 흔들림·전복·복귀 재검수 · 2026-10-09

## 현재 판단

**로컬 수정본이며 출시 준비 완료가 아니다.** 앞 단계의 시험 통과는 사용자가 겪은 전복·반복 꿀렁임을 충분히 검증하지 못했다. 새 콘텐츠보다 주행 품질 검수를 우선한다. 현재 실행 주소는 <http://127.0.0.1:5191/>다.

## 확인한 원인과 수정

- 모델 원점을 물리 원점보다 항상 세계 Y 방향으로 0.6m 내리던 오류: 차가 기울면 위치가 어긋났다. 보간한 차체 회전에 맞춰 **차량의 로컬 방향**으로 오프셋을 적용한다. 바퀴·배기구·카메라·그림자 기준을 같은 좌표계에 맞췄다.
- 안정화 카메라가 차체의 기울어진 전방 벡터를 그대로 쓰던 문제: 앞뒤로 기울면 추적 거리의 수평 성분이 줄었다. 수평 방향을 정규화했고, 이 레이스 카메라에서는 추가적인 사인파 충돌 흔들림을 사용하지 않는다. 실제 차체 회전·충돌·음향·불꽃은 유지한다.
- 도로 복귀 높이가 도로 +1.1m였던 문제: 정지 높이보다 약 0.6m 위에서 차를 떨어뜨렸다. 실제 스프링 평형 높이와 바퀴 반지름을 쓰고 노면 경사에 차체를 맞춘다.
- 복귀 지점에 빠른 AI가 접근하면 즉시 재충돌: 현재 위치뿐 아니라 **향후 1초 이동 구간으로부터 6m** 여유가 있는 후보를 찾는다. 현재 지점의 양쪽 차선부터 뒤쪽 32개 경로 점까지 탐색한다. 모두 막혔으면 강제 겹치기 대신 복귀를 보류한다. 뒤로 이동한 만큼 진행도도 차감하며, 복귀가 니트로를 충전하거나 레이스 시간을 초기화하지 않는다.
- 전복 후 플레이어가 계속 조작 불능: 차체 위쪽 방향이 세계 위쪽과 크게 어긋난 상태가 1.5초 지속되면 자동 복귀한다. 경로 높이보다 6m 이상 아래에 0.5초 머무르는 경우도 복귀한다. 정상적인 경사·점프와 일시정지는 복귀 타이머를 진행시키지 않는다. 복귀 후 가속 재입력 안내를 표시한다.
- v4 바퀴 구멍 절삭이 차체 X 전체를 통과해 중앙 바닥까지 잘린 문제: Blender에서 닫힌 중앙 하부 메시를 추가했다. 원래 v4 파일은 보존했고 수정 원본은 `assets-sources/vehicles-v4-road-repair/`다. 이전 웹 GLB는 검수 폴더의 `pre-underside/`에 보존한다.
- 보이는 어깨 부분보다 충돌 차체가 낮고 좁았다. 제작 차체 기준으로 하부 충돌 높이를 0.8m, 폭을 수프라 1.96m·SLK 1.90m·머스탱 2.04m로 맞추고 쿠페의 유리 하단 보호 폭도 넓혔다. 이는 제작 메시의 충돌 근사이며 실차 제조사 제원 주장과 다르다.
- 작은 화면의 하단 버튼을 좌우로 나누고 중앙을 비웠다. 작은 세로 화면의 속도계는 오른쪽 위로 옮겼다.

## 검증과 관측

동일한 약 6.9도 경사면에서 복귀 후 1초의 노면 수직 방향 이동 범위를 비교했다. 이 값은 **복귀 때 낙하·출렁임**이며 전체 코스의 진동 감소율이 아니다.

| 차량 | 기존 복귀 | 평형 높이·경사 정렬 복귀 |
| --- | ---: | ---: |
| Supra | 59.7cm | 1.27cm |
| SLK | 60.4cm | 1.27cm |
| Mustang | 59.6cm | 1.57cm |

관련 시험은 실제 물리 엔진으로 경사 복귀·빠른 AI의 접근·나란히 겹친 차체의 분리·가속·제동·고속 충돌·6대 전체 코스를 확인한다. 표시 시험은 세 차종의 180도 전복에서도 바퀴 중심이 물리 서스펜션 중심과 일치하는지 확인한다. 카메라 시험은 기울기·반복 충격이 추가 줌이나 흔들림을 만드는지 검사한다.

최종 `npm run check:rebuild`는 **76개 시험 통과·실패 0·웹 빌드 성공**이다(`check-verified.log`). 표는 최종 충돌 영역을 적용한 같은 차에서 복귀 방식만 비교한 값이다. 첫 단계 로그의 약 63cm 수치는 이전 충돌 영역을 쓴 중간 계측이다.

충돌 영역 수정 후 비스듬한 230km/h 벽 충돌 시험이 한 번 실패했다(`check-final-body.log`). 수프라는 접지 4륜 상태에서 벽 반대 방향으로 돌아섰고 후진 입력은 벽으로 향했다. 시험은 충돌 후 실제 방향에 맞춰 벽에서 탈출한 뒤 반대 구동 방향으로 전환하는지를 검증하도록 수정했다. 속도·10도 충돌 각도·벽 관통 허용 6cm는 유지하고 충돌 범위 투영은 실제 콜라이더 치수를 사용한다. 정면 충돌 후 후진 탈출 시험도 유지한다. 실패를 감쇠 수치 변경이나 임계값 완화로 숨기지 않았다.

브라우저에서는 세 차량의 선택 → 출발 → 가속 → 제동 → 도로 복귀 → 차고 복귀를 확인했다. 수프라의 별도 로컬 시험 장면에서 전복 버튼으로 실제 차량을 뒤집은 뒤 자동 복귀와 4륜 접지를 확인했다. 실제 앱에서는 길게 가속한 뒤 노면 아래로 내려간 차량의 자동 복귀도 관측했다. 844×390과 375×812는 화면 크기 에뮬레이션이며 모바일 실기기 검증이 아니다.

SLK 검수 중 **기존 복귀 직후 56km/h로 다시 밀리고 충돌 1회**가 발생했다. 실패 증거 `slk-flow.json`을 보존한다. 위치 탐색 수정 후 같은 출발·가속·제동·복귀 순서에서 즉시 0km/h, 이후 후진 입력을 주는 동안 충돌 0회·접지 4륜이었다(`slk-safe-recovery.json`). 머스탱도 복귀 직후 0km/h·충돌 0회·4륜 접지를 확인했다.

증거: `artifacts/ride-repair-20261009/`의 시험 로그, Blender 로그, 실패/수정 후 JSON, `underside-inverted.png`, `automatic-recovery.png`, 가로/세로 화면 캡처. `slk-portrait.png`와 최초 `final-drive.png`는 각각 복귀 충돌과 근접 차체 검수를 위한 중간 기록이다. 최종 충돌 영역 적용 후 근접 주행 화면은 `final-verified.png`, 복귀 후 다시 출발한 화면은 `final-road.png`다. 이 마지막 흐름에서는 0km/h 복귀 후 다시 가속해 약 96km/h에 도달했다.

## 남은 범위

- 전체 코스를 사람이 세 차종으로 계속 운전하며 코너·연석·충돌 후 탈출을 평가해야 한다. 이전 45초 AI 비교만으로 꿀렁임 해결을 선언하지 않는다.
- 도로 밖의 거친 경사에서는 실제 서스펜션·차체 움직임이 남는다. 차량의 물리 회전을 고정하거나 지형을 평지로 바꾸지 않았다.
- 복귀 공간 예측은 1초의 직선 이동 근사다. 복귀 이후의 일반 충돌까지 막는 무적 기능은 아니다.
- 하부 메시와 충돌체는 근사 모델이다. 실차 수준의 하부·변형·타이어 접촉 시뮬레이션은 구현하지 않았다.
- 실기기 동시 터치·장시간 성능·최소 사양 검증은 남아 있다. GitHub와 공개 서비스에는 반영하지 않았다.
