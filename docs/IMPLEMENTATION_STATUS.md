# MUMU CIRCUIT 구현 상태

## 2026-08-12 최신 검증

- 네온 에이트를 제거하고 하버 링·알파인 스프린트 2개 서킷 체제로 정리했다.
- Kenney 차량 컬러맵을 강제로 지우던 안전 우회 코드를 제거했다. 차체 패널·유리·램프·범퍼·휠 대비를 보존하고 텍스처가 없을 때만 단색 틴트를 사용한다.
- Rapier의 가속·제동·후진·조향을 실제 WASM 월드에서 실행하는 `check-drive-dynamics.mjs`를 추가했다. APEX GT 기준 220km/h 가속, 0km/h 제동, -47km/h 후진 제한, 18.3도 조향을 검사한다.
- `BRAKE` 입력은 휠 브레이크와 속도 감쇠를 결합해 고속에서도 실제 정지가 가능하며, 정지 후 후진은 약 54km/h로 제한한다.
- Rapier 0.20의 전방 축 API가 브라우저와 Node에서 메서드/세터로 다르게 노출되는 경우를 모두 처리한다.
- FRONT 쇼룸을 대칭 정면으로 교정하고, 피트 크루를 차량 뒤쪽으로 이동해 전시 실루엣을 가리지 않게 했다.
- 런타임 프레임 계측과 적응형 그래픽을 추가했다. 단일 390×844 탭에서 차고 59fps, 6종 연속 전환 후 48.2fps, 레이스 45.7fps를 기록했다. 숨겨진 탭은 240ms 절전 루프로 전환한다.
- `check-bundle-budget.mjs`로 앱 JS·CSS·Three.js·Rapier·전체 배포 크기를 제한한다. 현재 전체 dist는 약 11.17MB다.

## 이전 구현 기록

- 차량 컬렉션 10종과 `mumu-circuit-profile` 저장을 구현했다. 기본 3종은 즉시 사용하고, 완주·우승 조건으로 나머지 차량을 해금한다.
- 차량별 가속·최고속도·접지력·질량을 Rapier 차량 컨트롤러에 연결했다. 선택 차량과 AI 차량이 같은 물리 생성 경로를 공유한다.
- 최고속도 스탯을 실제 속도 제한에 연결하고, 접지력은 휠 측면 마찰과 드리프트 감쇠에 반영했다.
- GLB 내부의 바퀴 노드를 자동 수집해 주행 속도에 맞춰 시각적으로 회전시킨다.
- GLB를 URL별 Promise 캐시로 재사용하고, 트랙 장식은 차고지 이후 지연 로딩한다.
- 첫 3D 프레임 전에는 `BOOTING CIRCUIT` 레이어를 보여 초기 빈 화면을 숨긴다.
- Vite에서 React·Three.js·Rapier를 별도 청크로 분리해 앱 초기 청크를 약 273KB로 줄였다.
- `NEON TECH`와 `CLOUD RUN`에 별도 하늘·지면·안개·조명 팔레트를 적용해 회로 선택이 실제 분위기 차이로 이어진다.
- 카탈로그에 조향·제동·드리프트 제어값을 추가하고 플레이어와 AI의 동일한 주행 경로에 반영했다. VOLT X 선택 레이스까지 브라우저에서 확인했다.
- 결과 화면에 트랙·차량·순위·PB·골드 보상·커리어 누적·신규 해금 차량을 묶은 리캡 패널을 추가했다.
- 차고지에 브랜드 사인, Bay 01 디스플레이, Bay 02 정비 베이, 타이어 랙, 서비스 라인, Kenney 도로 프롭을 배치했다.
- `scripts/check-vehicle-assets.mjs`로 카탈로그 GLB의 glTF 헤더·메시·노드·바퀴 노드를 자동 검증한다.
- `npm run check`는 CC0 에셋 167개와 차량 카탈로그 10종 검증 후 Vite 빌드까지 수행한다.
- localhost 브라우저에서 차고지 → 회로 선택 → 레이스 진입을 확인했으며 최신 로그 기준 오류·경고가 없었다.
- 런타임 종료 시 Rapier `World.free()`를 호출하도록 정리해 페이지 재진입·StrictMode 재마운트에서 WASM 물리 리소스가 남지 않게 했다.
- `LINE` 주행 보조와 `CRUISE` 입력을 실제 브라우저에서 함께 확인했으며, 알파인 스프린트 진입 후 40 km/h대 주행과 오류·경고 0건을 확인했다.
- 차고지에 PIT CREW 온라인 상태, 보유 차량 수, 선택 차량 번호, 수치형 스탯, 차량별 해금 진행 문구를 추가해 컬렉션 화면의 판단 비용을 줄였다.
- 레이스 HUD에 세션 상태·라이브 표시·키보드 힌트·카메라 접근성 라벨을 추가하고 트랙별 포인트 컬러를 선택 화면에 반영했다.
- 데스크톱과 390×844 모바일 뷰포트에서 차고지·회로 선택·주행 HUD가 모두 렌더링되고 새 UI 로그 오류가 없는 것을 확인했다.
- Rapier를 레이스 진입 시점의 동적 import로 전환해 차고지·회로 선택 화면이 물리 WASM 청크를 선행 로딩하지 않도록 분리했다.
- 차종별 질량·접지력에 따라 휠 마찰, 서스펜션 강성·감쇠·최대 하중을 매핑하고, 신규 탭에서 알파인 스프린트 61 km/h 주행과 오류·경고 0건을 확인했다.
- 피트 장식 지연 로더에 Kenney 콘·배리어·교차 조명·상세 표지판과 배송차·트럭·소방차·구급차 서비스 플릿을 추가해 레이스 화면의 실제 구역감을 강화했다.
- `scripts/check-vehicle-assets.mjs`가 GLB 원본 POSITION 범위와 런타임 정규화 배율을 함께 검사하고, 차종마다 최소 4개 휠 노드가 있는지 확인하도록 강화했다. 현재 10종 모두 허용 범위 안에서 통과한다.
- 차고지 선택 패널에 차량 역할 힌트를 추가했다. 예를 들어 VOLT X는 `TOP SPEED · LONG STRAIGHTS`, RALLY R은 `GRIP · TECHNICAL CORNERS`로 트랙 선택 전에 운용 의도를 바로 판단할 수 있다.
- 새 브라우저 탭에서 RALLY R 선택 → 하버 링 진입까지 회귀 테스트를 다시 수행했고, 레이스 HUD·입력 버튼·동적 Rapier 로딩이 정상 렌더링됐다.
- 차고지 전시 턴테이블에 자동 궤도 카메라, 첫 프레임 프리밍, 차량 미세 바운스, 무빙 포인트 라이트, 청록·황색 플랫 링을 추가했다. 링은 돌출 튜브 대신 바닥 발광 메시로 바꿔 차량을 가리지 않게 했다.
- 새로고침 직후 차고지 전시 화면을 캡처해 차량·턴테이블·브랜드 벽·선택 패널이 한 화면에 잡히는지 확인했고, 이후 하버 링 레이스에서 LINE·CRUISE 입력과 HUD가 정상 동작하는 것을 다시 확인했다.
- 차고지에 `FRONT / ORBIT / SERVICE` 쇼룸 프리셋 버튼을 추가했다. SERVICE는 Bay 02 작업 구역을 향하고, 트랙·레이스 화면에서는 컨트롤이 자동으로 숨겨진다. 세 버튼의 `aria-pressed` 상태와 시각 프레이밍을 브라우저에서 모두 확인했다.
- `handlingProfile()`을 추가해 차종별 최고속도·가속·조향·브레이크·드리프트 수치를 하나의 Rapier 튜닝 프로파일로 묶었다. 속도에 따라 조향 권한과 엔진 힘이 자연스럽게 감쇠하고, 브레이크는 전륜 바이어스, 드리프트는 후륜 슬립으로 적용된다.
- AI도 동일한 튜닝 프로파일과 `applyDrive()` 경로를 사용한다. 짧은 브라우저 주행에서 APEX GT·VOLT X·RALLY R의 LINE/CRUISE 주행이 멈춤 없이 진행되고, HUD 속도·순위·랩 상태가 갱신되는 것을 확인했다.
- 튜닝 과정에서 발견한 아이들 제동 과다 회귀를 수정했다. 입력이 없을 때는 낮은 롤링 저항만 적용하고, 실제 BRAKE 입력에만 차량별 제동력이 올라가도록 분리했다.
- 완주 시 평균 속도·최고 속도·드리프트 시간을 telemetry로 집계해 결과 화면에 추가했다. 하버 링 RALLY R 완주 결과에서 `AVG SPEED 33 KM/H`, `PEAK SPEED 39 KM/H`, `DRIFT TIME 0.0 SEC`를 실제 브라우저로 확인했다.
- GLB 정규화 후 실제 높이를 차고지 카메라 스케일에 반영했다. REDLINE 6 소방차를 FRONT 프리셋으로 선택해 중앙 구조물에 가리지 않는 3/4 전시 구도를 확인했다.
