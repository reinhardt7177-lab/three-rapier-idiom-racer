# 네 코스 길안내·주행 가독성·CPU 작업 절감 계획

**현재 Goal (2026-11-04 사용자 축소 결정):** 좌/우 반전 버그만 실제 카메라/도로 좌표로 수정·검증한다. 아래 연속 코너/반복 계산 작업은 원래 계획과 철회 경위를 보존한 것이며 완료 범위가 아니다.

**Architecture:** 기존 Three.js/Rapier와 DOM HUD를 유지한다. 안내는 경로의 시각적 곡률과 운전자 좌우를 사용하며, AI/물리에서 분리한다. 정적인 코너 탐색을 캐시하고, 장식 거리 판정에서 불필요한 작업만 제외한다.

**Tech Stack:** Three.js, React DOM, Vite, Node test, 실제 브라우저 IAB.

## 설계와 판단

- 현재 좌표는 위쪽+Y/차량 진행+Z다. 뒤에서+Z를 보는 운전자 화면에서는+X가 왼쪽이다. `atan2(dx,dz)`의 증가를 오른쪽이라고 표시한 공통 코드가 반대이며, 기존 heading-only 시험도 이 가정을 반복했다. 새 시험은 실제 좌표와 카메라 투영으로 방향을 독립적으로 검증한다.
- 사용자는 즉시 수정·전체 코스 개선을 요청했다. 별도 신규 모드/물리 재설계 대신, 방향 교정→연속 커브 예고/속도에 맞춘 사전 안내→정적 탐색/장식 CPU 절감 순서로 이행한다. 이는 구현자의 범위 선택이며 새로운 코스 측량/전체 아트 리메이크를 뜻하지 않는다.
- 도로·충돌·경로·접지·AI 페달·교통량·메달은 보존한다. 이전 보류 물리를 복원하지 않는다. 품질별 장식 거리/삼각형 예산을 낮추어 성능 개선으로 표시하지 않는다.
- 같은 브랜치에서 진행한다. 변경 전 사본은 `artifacts/all-course-navigation-20261103/before/`에 두고, 최신 파일 시각을 확인한다. Colab·Kiro·새 커밋/푸시/PR/main/운영 배포는 이 구현 작업에 포함하지 않는다.
