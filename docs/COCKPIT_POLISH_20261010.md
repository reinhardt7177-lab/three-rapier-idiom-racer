# 운전석과 주행 UI 폴리싱 · 2026-10-10

## 이번 수정

기본 창의 게임 영역 약830×467에서 1인칭 속도 패널이 위아래로 길게 늘어나 실내를 가리고 있었다. 이전 짧은 화면 규칙의 `top`과 1인칭 규칙의 `bottom`이 동시에 적용되는 것이 원인이었다. 위치를 명시적으로 초기화하고 높이550px 이하의 가로 게임에서는 페달을44px 한 줄로 배치했다. 순위 글자도7px에서9px로 키웠다.

일시정지 메뉴는 왼쪽에 재개·재시작·차고·시점 전환, 오른쪽에 사운드·음악 선택·볼륨을 배치했다. 전체 화면 버튼은 머리글에 두었다. 기본 게임 영역에서 모든 설정이 스크롤 없이 보인다. 더 낮은 화면에서는 안내 문장을 줄이고 메뉴 자체 스크롤을 유지한다.

Blender 운전석을 수정해 계기판 사이에 실제 속도·기어·RPM 화면을 추가하고 센터 콘솔에는 선택한 음악 제목과 재생 상태를 표시했다. 숫자 속도는260km/h를 넘겨도 실제 값을 표시하고 아날로그 바늘은 기존 눈금 상한까지 움직인다. 표시 화면은256×256 공유 텍스처 한 장, 갱신은 최대10Hz이며 3인칭에서는 갱신하지 않는다. 음악 화면의 막대는 장식이며 실제 음량 분석기는 아니다.

대시보드 하부의 단면, 스티어링의 카본 스포크·금속 인레이, 얇은 부분 조명 몰딩을 다듬었다. 가죽·대시보드·카본에는 작은 공유 표면 노멀맵을 붙이고 Blender의 생성 패널에도 UV를 부여했다. 표면 질감은 매 프레임 변하지 않는다. 공통 커스텀 운전석이며8종의 실제 브랜드 실내를 복제한 모델은 아니다.

## 실패와 실제 검증

첫 표시 화면이 뒤집히고 음악 콘솔에 계기판 절반이 나타나는 문제를 실제 화면에서 발견했다. Blender 수출 과정이 이미 glTF UV 원점을 변환하기 때문에 CanvasTexture의 `flipY=false`로 수정했다. `atlas-flipped-failure.png`에 중간 실패를 보존했다. 브라우저 재로딩 중 관찰 요청이 일시적으로 타임아웃됐으나 같은 탭으로 다시 연결해 차고·레이스를 확인했다. 원인까지 확정하지 않았고 로딩 지연 문제를 해결한 것으로 간주하지 않는다.

- 실내·가로 화면·음악 선택·레이스 입력·라이벌 속도 관련33개 자동 검사 통과: `related-tests.log`.
- UV 방향 수정 후 실내6개 검사 재통과: `cockpit-final-tests.log`. 하단 도로 비침과 상단 시야, 독립 피벗과 자산 예산, 실제 숫자·후진 표시, 숨긴 실내의 갱신 중단,10Hz 갱신 제한, 공유 텍스처의1회 해제를 확인한다.
- 최종 웹 빌드 통과: `build.log`. 큰 Three.js/Rapier 청크 경고는 남아 있다.
- IAB 실제 약830×668 창 /830×467 게임에서 HUD 높이 약84px, 페달44px, 일시정지 메뉴335px(스크롤 높이 동일)를 확인했다.
- 포인터 가속 후 해제, 키보드 동시 가속·조향 후 해제, ESC 정지·재개, 두 음악 변경,1/3인칭 전환, 레이스 재시작, 차고 복귀를 확인했다. 최종 화면과 상태는 같은 폴더의 이미지와 `browser-proof.json`에 기록한다.
- 화면 크기 변경을 요청했지만 실제 게임 DOM의 크기는830×467로 유지됐다. 따라서559×668 등 다른 크기의 실제 렌더링 검증을 통과했다고 보고하지 않는다. 크기·방향 차단의 자동 검사는 별개다.
