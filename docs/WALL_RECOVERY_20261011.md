# 남악 벽 관통·도로 복귀 수정 · 2026-10-11

## 문제와 원인

사용자가 벽 밖으로 튕겨 나가 복귀하지 못한 화면을 보고했다. 실제 열린 브라우저에서 차량은 도로 중심에서 18.70m 떨어진 보도 위에 똑바로 서 있었고 타이어 4개가 접지하고 있었다. 기존 자동 복귀는 전복·추락만 감지해 이 상태를 복구하지 않았다.

Blender에서 수출한 벽 충돌체는 두께 없는 면이었다. 보이는 벽은 그대로 유지하고 런타임 충돌체를 수정했다. Blender 원본을 다시 제작한 작업은 아니다.

## 변경

- `namakBarriers.js`: 기존 위치·높이에 45cm 두께의 닫힌 벽 충돌체를 만든다. 벽 24개, 전체 환경 충돌체 48개를 유지하며 렌더링용 메시를 추가하지 않는다. 반발 0, 마찰 0.15로 벽 접촉 시 튕김을 줄인다.
- 남악에서 차량 중심이 도로 중심으로부터 12m를 넘은 상태가 1초 지속되면 자동 복귀한다. 잠깐의 가장자리 접근·일시 정지는 복귀 시간을 진행시키지 않는다. 개방형 해안 코스에는 이 조건을 적용하지 않는다.
- 복귀 후보는 기존 약 64m 대신 남악 기준 약 180m까지 뒤쪽을 탐색한다. 주변 차량의 다음 1초 이동 경로와 6m 간격을 확인한다. 안전한 후보가 없으면 복귀를 보류하고 다시 시도한다.
- 벽 밖에서는 레이스 진행 거리를 얻지 않는다. 복귀는 앞쪽 진행을 주지 않고 사용한 니트로를 보존한다.
- 페달 버튼에 키보드 포커스가 남아 있어도 `C` 복귀가 동작한다. 메뉴·문자 입력 중에는 동작하지 않는다.

## 실행한 검증

증거: `artifacts/wall-recovery-20261011/`.

- 관련 검사 47개 통과: 충돌·복귀·주행 안정성·입력·난이도·니트로·기록.
- 최종 집중 검사 29개 통과. 새 벽 검사 7개 포함.
- 남악 경로 1,464지점 양쪽의 벽과 연결 경계를 레이로 검사했다.
- 차량 8종을 양쪽 벽으로 230km/h 측면 충돌시켰다. 차량 중심 최대 이탈 10.60~10.68m로 벽 중심 11.85m를 넘지 않았다.
- 실제 물리 맵에서 보도에 멈춘 수프라를 도로로 복귀시켜 4바퀴 접지·속도 초기화·소모 니트로 보존을 확인했다. 6대 정지 차량 뒤쪽의 복귀 공간도 확인했다.
- 수프라 자동 주행으로 남악 2.93km를 109.95초에 완주했다. 최대 도로 중심 이탈 4.94m, 종료 접지 4개, 자동 복귀 발생 없음. 사람이 직접 운전한 완주 기록은 아니다.
- 처음 벽 레이 검사에서 Rapier 정적 충돌체의 쿼리가 갱신되기 전 검사해 실패했다. 정적 환경을 한 단계 진행한 뒤 같은 검사를 다시 통과했다. 첫 실패 로그를 보존한다.
- 웹 빌드 통과. 기존 Three.js·Rapier 번들의 500kB 초과 경고는 남아 있다.
- 새 빌드를 5191 브라우저에 반영했다. 실제 키보드 가속·조향으로 벽에 접근해 충돌 3회, 중심 이탈 약9.61m, 접지4개, 벽 안쪽 정지를 확인했다. 버튼에 포커스를 준 뒤 `C`와 화면 복귀 버튼을 각각 실행해 복귀 횟수1→2를 확인했다. 복귀 후 차선 위치는 중심에서2.2m, 접지4개, 입력0이었다.
- 일시정지·재개·재시작·차고 복귀를 확인했다. 재시작은 경과 시간과 복귀 횟수를 초기화했다. 브라우저 오류 로그0개. 최종 화면은 차고에 두었다. 실제 벽 바깥 상태의 자동 복귀는 기록한 브라우저 위치와 물리 시험으로 검증했으며 새 브라우저에서 공중 관통을 강제로 재현하지는 않았다.

## 한계

모든 점프·공중 충돌에서 벽을 넘지 않는다고 보장하지 않는다. 벽 밖 이탈 시 자동 복귀를 함께 적용해 갇힘에 대비한다. 실기기·장시간 반복 충돌 검수는 남아 있다. 공개 배포는 이번 작업에서 갱신하지 않았다.
