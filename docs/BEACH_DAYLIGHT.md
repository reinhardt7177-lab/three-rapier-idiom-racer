# 밝은 해변 공도 — 미술 전환

작성: 2026-09-08. 사용자 요청은 마이애미 비치처럼 밝은 전체 분위기다. 실제 도시 복제, 새 맵·물리·교통 규칙 변경이 아닌 기존 항구 세계의 미술 개선이다.

## 방향과 판단

- 유지: 자체 코드로 만든 GT, 공구·배관·석재 줄눈이 있는 차고, 해안 공도, 기존 이야기·스프린트·저장 설정.
- 변경: 녹색 안개와 올리브색 환경 → 푸른 하늘/청록 바다/아이보리 석재/산호·민트·파스텔 건물.
- 참조 요소: Tropical Deco의 파스텔 외벽, 수평 차양, 계단형 지붕선, 원형 창. [마이애미 관광청의 아르데코 안내](https://www.miamiandbeaches.com/hotels/art-deco-architecture-boutique-hotels)를 참고하되 실제 호텔 이름·로고·모델을 복제하지 않았다.
- 어두운 아스팔트와 밝은 차선을 유지한다. 흰 도로·과도한 블룸으로 밝은 분위기를 만들지 않는다.
- 항만 건물 한 곳은 정비 창고로 유지하고 나머지 여섯 곳을 해변 상점/스튜디오 형태로 바꾼다. 세계의 정체성이 전부 리조트로 바뀌지 않게 한다.

## 구현

- `src/scenery/beachPalette.js`: 공통 미술 색상. 실제 주행 제원과 분리.
- `beachScenery.js`: 그라데이션 하늘, 꺾인 줄기와 접힌 잎을 가진 야자수, 차양·원형 창·파스텔 외벽, 파라솔/선베드. 모두 Three.js 코드 생성.
- `src/driving/beachLayout.js`: 야자수를 도로 바깥에 배치하고 갈림길과 회차 공간을 비운다. 잎 크기를 포함한 여유 공간을 검사한다.
- 도로의 시각 노면/충돌체/폭, 조향/가속/브레이크, 스프린트 게이트·PB 키는 변경하지 않는다.
- 차고 조명 옵션·색상 선택·바닥 반사·동작 감소·저장 데이터를 유지한다. 환경이 밝아져도 설정을 강제로 초기화하지 않는다.
- 주행 HUD의 작은 제목과 차고의 배경 없는 글자는 밝은 배경에서 읽히는 어두운 청록색으로 변경한다. 버튼 크기·화면 중앙 시야 영역은 유지.

## 비판적 검수 기준

1. 밝기만 올려 차고 줄눈·공구·도색 반사가 날아가면 재질부터 조정한다.
2. 건물의 도로 쪽 면뿐 아니라 주행 중 먼저 보이는 측벽도 검사한다.
3. 야자수와 파라솔은 장식이다. 도로로 튀어나오거나 충돌체 없는 장애물처럼 보이면 배치를 수정한다.
4. 정지 사진과 실제 추적 카메라, 가로/세로 터치 화면을 구분해 확인한다.
5. 야자수는 개수에 관계없이 네 개 인스턴스 메시로 그린다. 그리기 호출 수와 실기기 FPS는 같은 지표가 아니다.

## 검증 기록

첫 렌더 비교에서 차고 바닥의 지나친 밝기와 건물 측벽의 빈 면을 발견했다. 차고 바닥/벽 재질의 명도를 낮추고, 건물 양쪽 측벽에 창·차양을 연결했다. 첫 시도는 `artifacts/beach-daylight/`, 최종 검증은 `artifacts/beach-final/`에 분리한다.

| 최종 검사 | 실제 결과 |
| --- | --- |
| 자동 시험·빌드 | 60개 통과, Vite 빌드 및 `git diff --check` 통과. 기존 큰 번들 경고 유지 |
| 배치·기하 | 공도 야자수 61개, 높이 7.4–9.2m. 도로/갈림길/회차 패드 여유 검사와 유한 정점·4개 인스턴스 메시 검사 통과 |
| 기록 주행 | 실제 키 입력 3개 구간 완주, PB 저장·재도전·복귀 무효화·재접속 통과. [기록](../artifacts/beach-final/sprint/verification.json) |
| HUD·터치 | 스프린트 4화면 + 기존 HUD 6화면, 두 손가락 가속/조향·취소·메뉴/회전 시 고착 방지 통과. [기록](../artifacts/beach-final/tablet-hud/verification.json) |
| 차고 | 색상·카메라 4개·셔터·조명·반사·포토 모드·모바일·설정 저장 및 저장 차단 통과. [기록](../artifacts/beach-final/garage-evolution/verification.json) |
| 기존 이야기 왕복 | 키 입력 출발 → 신호소 접지 정차 → 장면/세로 화면 → 귀환 정차 → 완료 저장 → 차고 재접속 및 재시작 통과. [기록](../artifacts/beach-final/signal-journey/verification.json) |

| 변경하지 않은 영역 | 물리·도로 경로·조향·차고 설정 스키마·이야기 진행·차량 제원 파일의 diff 없음 |

최종 통과한 위 브라우저 실행에서 JS 오류/검사 실패 없음. 그리기 호출은 동일 항구 자유 주행 화면에서 **122 → 132**, 스프린트 최대 **129 → 139**로 각각 10개 증가했다. 새 하늘·야자수·해변 장식의 비용이며 프레임 성능 향상이라고 해석하지 않는다. 브라우저 시험은 Headless Chrome 소프트웨어 GPU이며 실기기 성능 보장은 아니다. 기존 어두운 버전의 증거는 유지한다.

## 남은 한계와 다음 작업

- 미술 변경이 조향·제동 피드백과 반복 플레이의 재미를 해결한 것은 아니다. [레이싱 비판적 재점검](RACING_CRITICAL_REVIEW.md)의 운전 평가 → 타이어/소리 → 고스트 우선순위는 계속 유효하다.
- 지금은 출발부 해변 대로와 전체 팔레트의 1차 통일이다. 내륙 쉼터·신호소·멀리 보이는 지형까지 같은 밀도의 건축/소품을 채운 것은 아니다.
- 보행자·관광객·교통 AI·새 이벤트는 추가하지 않았다. 해변은 배경이며 새 자유 탐험 구역이 아니다.
- 실제 삼성 태블릿/휴대폰 발열·프레임 유지·야외 화면 밝기는 미검증이다.
- 기존 대형 Three.js/Rapier 번들과 초기 로딩 안정성 문제는 별도 과제다.
- 이번 작업은 로컬 반영이다. GitHub 푸시·Vercel 배포·공유 이미지 교체는 하지 않는다.
