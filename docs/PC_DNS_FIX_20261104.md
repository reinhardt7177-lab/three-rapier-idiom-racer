# 이 PC의 공식 주소 직접 접속 복구 · 2026-11-04

**`https://racing.mumuworld.com/`의 이 PC 직접 접속을 복구했다.** Windows hosts에 이 단일 호스트의 정상 Vercel 주소만 추가하고 DNS 캐시를 갱신했다. 이후 일반 Windows/Node 이름 해석·기본 HTTPS·실제 IAB 차고/주행이 성공했다. 서버 배포나 다른 앱의 설정을 변경한 작업은 아니다.

## 원인 조사

- 기존 hosts에 `racing.mumuworld.com` 또는 부모 도메인을 지정한 항목은 없었다. 해당 도메인의 기존 캐시 항목/관련 NRPT 규칙도 발견되지 않았다.
- Windows 조회와 독립 nslookup이 여러 DNS 서버를 명시해도127.0.0.1을 반환했다. 응답에는 A127.0.0.1/TTL3600, AAAA NOTIMP가 관측됐다. 따라서 DNS 서버 주소를 무작정 바꾸거나 Chrome 캐시만 비우는 것으로 해결됐다고 판단하지 않았다.
- 같은 운영 배포의 기본 Vercel 호스트는 정상 IP를 반환했고, 그 정상 edge에 공식 호스트명/SNI를 유지한 HTTPS 요청은 인증서 검증을 켠 상태에서200이었다.
- 정확히 어느 네트워크/필터 구성요소가 잘못된 DNS 답변을 만드는지는 확정하지 못했다. 조직 정책을 해제하거나 전체 DNS 서버를 변경하지 않았다. 이번 조치는 **단일 PC의 호스트 이름 해석 보정**이며, 외부 DNS 서버 자체를 수리했다는 주장이 아니다.

## 적용한 변경

- 관리자 권한의 Windows PowerShell에서 검토한 스크립트의 SHA를 확인하고 실행했다. 스크립트 실행 정책·방화벽·인증서 검증·브라우저 정책은 바꾸지 않았다.
- 기존 hosts 원본1021바이트를 그대로 보존하고 `BEGIN/END MUMU CIRCUIT DNS REPAIR 20261104` 표시 안에 아래 두 항목만 추가했다.

```text
216.198.79.131 racing.mumuworld.com
64.29.17.131 racing.mumuworld.com
```

- 위 주소는 적용 직전 같은 운영본 `mumu-racing.vercel.app`의 A주소이며, 각각 공식 호스트의 정상 TLS/HTTP200을 확인하고 골랐다. 오래된 CNAME 참고 주소에서 나온 다른 IP 두 개는 TLS 검사에 실패해 사용하지 않았다. 인증서 검증을 낮추어 통과시키지 않았다.
- 적용 뒤 기본 Windows 해석과 정상 HTTPS200을 스크립트가 확인했다. 이 건강 검사가 실패하면, 다른 편집이 없음을 확인한 뒤 원본으로 자동 복구하도록 구성했다. 실제 적용은 한 번에 성공했으며 자동 복구 경로가 이번에 실행된 것으로 주장하지 않는다.
- 원본 hosts와 복구 기능은 아래 로컬 전용 경로에 보존했다. 복구 모드는 추가한 정확한 표시 블록만 제거하므로 나중에 생긴 다른 hosts 항목을 전체 덮어쓰지 않는다.

## 실행한 검증

- 일반 .NET/Node OS lookup: 정상 Vercel 주소2개, loopback 없음.
- 접속 IP 강제 지정·프록시·인증서 무시 없이 **공식 주소 HTTPS200**.
- 공식 도메인37파일 모두HTTP200,35파일 바이트/SHA 일치+2파일 CRLF/LF 차이만, 설명되지 않은 내용 차이0. 네 코스 HTML200/올바른 새 JS·CSS/없는GLB404.
- 공식 도메인의 실제 IAB 차고 로딩, 여수 레이스 출발과 키보드 가속 약33km/h, 키 해제/일시정지 입력0, 차고 복귀를 확인했다. 최종 탭은 쿼리가 없는 공식 기본 주소로 남겼다.
- 게임 코드/물리/UI를 바꾸지 않았으므로 전체539시험이나 장시간 레이스·FPS 검사를 다시 돌리지 않았다. 실제 네이티브 Chrome/Edge 각각의 별도 프로필·다른 기기 검증으로 확대하지 않는다.

## 백업·복구와 남은 한계

로컬 작업 폴더: `D:/racing/.work/pc-domain-fix-20261104/`.

- `before/hosts`: 원본 바이트 사본. 사용자 PC의 기존 설정이므로 GitHub에 올리지 않는다.
- `preflight.json`, `apply-result.json`: 원본/스크립트 해시와 적용 성공·정상 HTTPS 결과.
- `repair-hosts.ps1`: 적용 및 `-Rollback` 모드. 실행 시 `-ExpectedScriptSha`에는 preflight의 scriptSha를 전달하며 Windows 관리자 권한이 필요하다.
- `official-verification.json`, `browser-flow.json`, `completion.json`, `screens/`: 이번 정상 접속의 검증·화면.

이 보정은 해당 PC에만 적용된다. Vercel이 나중에 IP를 변경하면 표시 블록의 주소를 재검증/갱신하거나, 원래 DNS 경로가 정상화된 뒤 이 블록을 제거해야 한다. 원래 DNS 서버에 직접 질의하는 nslookup은 hosts를 사용하지 않으므로 여전히127.0.0.1을 보일 수 있다. 일반 앱/브라우저의 OS 이름 해석 및 직접 HTTPS 성공과 구분한다.

복구가 필요하면 PowerShell에서 다음처럼 검토된 동일 스크립트의 복구 모드를 실행한다. 전체 hosts나 다른 DNS 설정을 초기화하지 않는다.

```powershell
$taskRoot = 'D:\racing\.work\pc-domain-fix-20261104'
$taskConfig = Get-Content "$taskRoot\preflight.json" -Raw | ConvertFrom-Json
Start-Process "$env:WINDIR\System32\WindowsPowerShell\v1.0\powershell.exe" -Verb RunAs -WindowStyle Hidden -ArgumentList @('-NoProfile','-NonInteractive','-File',"$taskRoot\repair-hosts.ps1",'-Rollback','-ExpectedScriptSha',$taskConfig.scriptSha)
```

다음 작업은 사용자가 평소 쓰는 브라우저에서 공식 주소로 접속해 확인하는 것이다. 사이트를 열어둔 오래된 탭에 캐시된 실패 화면이 남으면 해당 탭을 새로고침한다.
