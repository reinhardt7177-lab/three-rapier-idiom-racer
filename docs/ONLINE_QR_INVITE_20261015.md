# 온라인 1:1 · QR 초대

## 변경

- 방을 만든 뒤 **QR로 초대**를 누르면, 친구가 휴대폰 카메라로 읽을 수 있는 큰 QR을 표시한다.
- 친구는 링크를 열고 **방 참가 → 준비 완료**를 누른다. 방장은 QR 화면에서 **뒤로 → 준비 완료 → 두 사람 출발**을 누른다.
- 친구가 참가하면 QR 화면에도 참가 알림을 표시한다. 링크 복사와 기존 초대 코드 입력도 유지한다.
- QR은 브라우저에서 생성한다. 초대 주소를 외부 QR 생성 서버로 전송하지 않는다. 기존 방 식별자와 연결 프로토콜은 변경하지 않았다.
- QR 라이브러리는 QR 화면을 열 때만 불러온다. 주행 중 QR을 만들거나 반복 계산하지 않는다. 불러오기·생성 실패 시 링크 복사 안내를 표시한다.
- 4자리 코드는 이번 범위에 포함하지 않았다. 사용자가 요청한 두 대안 중 QR 방식을 구현했다.

## 검증

- 관련 자동 시험 **30/30**: QR 8개, 기존 온라인 상태·연결 22개. 별도 QR 판독기로 SVG 도형을 읽어 네 코스·다른 방·로컬 경로의 원래 초대 주소와 일치하는지 검사했다. 빈 주소·잘못된 주소·위험한 URL·잘못된 방 코드도 검사했다.
- 실제 IAB 화면 캡처의 QR을 별도 판독기로 읽은 뒤, 그 주소로 두 번째 IAB 창을 열었다. 방 참가 → 양쪽 준비 → 동시 출발 → 키보드 주행 **53km/h** → 공유 일시정지 → 대기실 → 차고를 확인했다.
- 정지 중 W+D를 입력해도 **00:16.92 / 52km/h**가 유지됐다. QR 화면의 참가 알림도 확인했다.
- 1280×720, 1024×768, 844×390, 667×375에서 QR·대기실 잘림과 가로/세로 스크롤 초과가 없었다. QR은 큰 화면 224px, 작은 가로 화면 192px이다. 최종 QR은 추가 390×844 세로 창에서도 잘림·스크롤 초과 0이었다.
- Tab/Shift+Tab 순환, Escape로 대기실 복귀, QR 버튼으로 포커스 복귀를 확인했다. 링크 복사는 성공 표시까지 확인했지만 자동화의 별도 클립보드 읽기는 빈 문자열을 반환해 OS 클립보드 내용 일치는 주장하지 않는다.
- 로컬 브라우저 실행 오류 0. 방장 창에 기존 Three.js 셰이더 정밀도 경고 1, 참가 창 경고 0을 기록했다.
- **npm run check 전체 475/475**, 실패·취소·건너뛰기 0, 전체 실행 864.454초, 시험 853.983초, Vite 빌드 4.31초. 전부 로컬 Windows CPU/Rapier WASM으로 실행했다. 검사 시작 시 해시를 남긴 248개 실행 입력의 변경은 0이었다. 기존 결과 13개를 복원하고 이번 결과를 별도로 보존했다.
- 저작권 안내는 실행 코드가 없는 정적 문서로 추가했다. 첫 빌드가 public 루트 파일을 복사하지 않는 설정임을 확인해 기존 배포용 assets/rebuild 폴더로 옮기고 빌드를 다시 실행했다. UI·물리·연결 코드는 전체 검사 이후 변경하지 않았다.
- 배포 파일 증가분은 QR 코드·UI·정적 안내에 한정된다. 실제 초기 로딩 시간이나 주행 프레임을 이번 수치로 대신하지 않는다. 운영 검증은 아래에 추가한다.
- 최종 빌드 **37파일 / 80,107,952B**, 이전보다 **27,344B 증가**. 메인 JS는 349,157→351,617B(+2,460B), QR 전용 청크는 **21,742B / gzip 8,035B**다. 생성기는 대기실 QR 버튼을 누른 뒤 불러온다.

## 발견과 수정

1. 개발 서버에서 새 의존성의 첫 로딩 시 Vite 재최적화가 페이지를 새로고침했다. 갱신 후 새 방에서 다시 검사했으며 제품 빌드 검증도 별도로 수행한다.
2. 세로 창은 게임의 16:9 영역이 작아 QR 하단이 잘렸다. QR 화면을 전체 창의 별도 레이어로 옮기고 세로 창은 한 열로 배치했다. 실패 화면을 보존했다. 이 수정 전 전체 검사는 128.102초에 중단했으며 완료로 세지 않는다. 기존 시험 결과 파일을 복원한 뒤 최종 소스로 다시 실행했다.
3. 대기실 복귀 후 대기실 열기 버튼을 누르지 않고 QR 버튼을 찾은 검수 도구 오류가 있었다. 화면을 확인해 정상 순서로 재검사했다. 제품 결함으로 세지 않는다.

## 남은 한계

- 화면 크기 검사는 데스크톱 IAB의 크기 변경이다. 실제 휴대폰 카메라, 두 실제 기기·서로 다른 통신망의 연결은 미검증이다.
- QR은 친구 초대를 편하게 하는 기능이다. 임의 상대 자동 매칭이나 전용 중계 서버 보장은 추가하지 않았다.
- 이번 변경은 대기실 UI 범위다. 새로운 주행 FPS 개선이나 장시간 프레임 기준 통과를 주장하지 않는다.
- 의존성 감사에서 기존 개발 도구의 취약점 6건(높음 4/보통 1/낮음 1)을 확인했다. 해당 6개 패키지 버전은 변경 전 lockfile과 같다. 추가한 QR 생성기·시험 판독기에 대한 감사 항목은 없었다. 기존 도구 업데이트는 별도 범위로 남긴다.
- 다음 최우선은 공식 주소에서 실제 휴대폰으로 QR을 읽고 다른 통신망 기기와 1:1을 시험하는 것이다.
