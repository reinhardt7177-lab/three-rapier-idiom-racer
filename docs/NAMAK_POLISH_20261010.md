# 남악 도로 주변 밀도·재질과 조향 개선

## 적용 범위

- 남악 전용 Blender 맵을 다시 수출했다. 상가를 도로 쪽으로 배치하고 1층 쇼윈도·금속 창틀·차양·층간 띠·옥상 설비를 추가했다. 높은 기단에 가려졌던 상가 유리는 기단 높이를 낮춰 드러냈다.
- 보도 폭과 높이, 포장 줄눈, 점자 유도선, 연석, 배수구, 버스 정류장 4곳, 화단 82개, 벤치 62개, 볼라드 244개, 배수구 122개를 추가했다. 식생의 수관을 여러 덩어리로 나누고 수변·광장 조경을 보강했다.
- 기존 모델을 공유하는 주차 차량 4대를 도로 밖에 배치했다. 카메라 160m 밖에서는 표시를 끄며 주행 차량·물리 충돌 대상으로 등록하지 않는다.
- 남악에 보도 줄눈·벽돌·목재·물결·표면 미세 요철을 적용하고 조명·노출·안개를 조정했다. 미세 요철은 셰이더의 빛 반응만 바꾸므로 도로 충돌 표면은 평평하게 유지된다. 64px 공용 텍스처는 16,384바이트이며 추가 사진 텍스처를 다운로드하지 않았다.
- **플레이어 차량의 조향 각도 배율은 1.3**이다. 두 코스에 적용되며 AI는 기존 1.0을 유지한다. 기존 입력 보간과 속도에 따른 각도 제한은 유지하고 저속 최대 중앙 조향각 0.52rad는 넘기지 않는다. 따라서 최대 각도에 이미 도달한 저속 영역까지 무조건 30% 더 꺾는 것은 아니다.
- 브라우저 확인 중 발견한 터치 `BRAKE`의 후진 전환을 수정했다. 전용 제동 입력을 사용하므로 오래 눌러도 정지 상태를 유지한다. 키보드 `S/↓`의 제동 후 후진 조작은 유지한다.

## 실제 검증

- 관련 회귀 검사 46개 통과. 최종 맵을 다시 수출한 뒤 남악·폴리싱 검사 10개를 재실행해 통과했다. 터치 제동·화면 전환 검사 15개도 통과했다. 중복을 제외하면 53개 검사 범위다.
- 수출된 도로의 위쪽 면·연속 접지·차량 통과 공간과 상가 유리의 직접 가시성을 검사했다. 새 장식 때문에 충돌용 노면이 변하지 않았는지 검증했다.
- 실제 Rapier 차량 6대의 남악 자동 완주와 정차 플레이어를 지나가는 라이벌 5대의 완주를 확인했다.
- 100·180km/h 좌우 물리 조향에서 앞바퀴 각도, 1.3 배율, 바퀴 4개 접지와 자세를 확인했다. 기존 230km/h 조향 및 기본 조향 회귀 검사도 통과했다.
- 공유 주차 모델의 바닥 높이·도로 밖 배치·거리 표시 제어·배치 최적화 제외·GPU 자원 1회 해제를 검사했다.
- `npm run build` 성공. 기존 Three.js/Rapier 묶음 크기 경고는 남아 있다.

### 브라우저 확인과 성능

Windows Codex 내장 브라우저에서 가로 830×467 게임 화면, 픽셀 비율 1.25로 확인했다. 남악 → 해안 → 남악 전환, 차고·출발·재시작·도로 복귀·운전석 전환, 약120km/h 짧은 동시 가속/조향과 입력 해제를 확인했다. 터치 브레이크10초 유지 후0km/h·N기어와 후진 입력0을 확인했다. 최종 페이지의 브라우저 오류 기록은0개다.

240프레임 표본에서 출발 부근은 평균16.94ms·95백분위16.8ms·최대33.7ms였다. 도로 주변의 한 표본은 평균16.67ms·95백분위16.9ms·최대17.2ms, 그리기756회·삼각형1,295,097개였다. 다만 마지막 주행/화면 캡처를 포함한 표본에는 평균21.18ms·95백분위19.2ms·최대750.7ms,50ms 초과3프레임도 기록됐다. 끊김 원인을 이번 변경에서 확정하지 않았으며, 짧은 표본을 장시간 안정성이나 휴대폰60FPS 보장으로 표현하지 않는다.

## 발견과 한계

- 첫 수출은 20MB를 조금 넘었다. 작은 화단 꽃의 면 수를 줄여 기존 크기 제한 안에 맞췄다. 기준을 올리지 않았다.
- 목재 셰이더의 변수 선언 순서 오류를 실제 브라우저에서 발견해 수정했다. 로그는 `shader-failure.json`에 보존했다.
- 최초 검사에서는 합쳐진 재질 메시의 이름, Draco가 필요한 차량 파일, 물리 적분 전후 속도의 차이를 시험이 잘못 가정했다. 최종 검사는 수출된 상가 가시성·배치/자원 소유·실제 물리 조향 단계에 맞게 검증한다. 압축된 차량의 외관은 브라우저에서 확인한다.
- 터치 제동 시험의 초기 기본 실험 차량은 멈추는 순간 작은 역방향 반동이 있었다. 현재 게임의 실제 수프라·주행 설정으로 검증해 제동 유지 시 역주행하지 않는 것을 확인했다. 최초 로그도 보존했다.
- 브라우저 자동 입력 사이에 차가 계속 굴러가 첫 코너를 이탈한 경우가 있었다. 도로 복귀와 재시작을 확인했으나 사람이 전 코스를 검수한 것으로 간주하지 않는다.
- 실제 휴대폰 장시간 발열·메모리·두 손가락 주행 및 차량 8종의 조향 체감 평가는 남아 있다. 이번 변경은 로컬 빌드에 적용했으며 공개 사이트 배포를 진행하지 않았다.

최종 브라우저 화면과 계측은 `browser-flow.json`, `namak-frontage-clean.png`, `namak-cockpit.png`, `track-overview.png`에 기록한다.
## 남악 색감 보정 · 2026-10-10 추가

- `src/rebuild/namakColors.js`에 역할별 sRGB 팔레트를 정의하고 실제 렌더링에서 선형 색으로 변환한다. 가로수·잔디는 짙은 초록, 상가·유리는 청록/파랑, 벽돌은 구리색, 꽃·안전 표시는 분홍/노랑/빨강으로 구분한다. 밝은 건물 외벽은 중성색을 유지한다.
- 남악의 하늘 산란·푸른 안개와 하늘 색 보정을 연결했다. 환경 반사도 같은 하늘에서 생성한다.
- 남악 도시 재질은 조명과 ACES 톤 매핑 후 채도1.24·대비1.10을 적용한다. 자동차 도장은 채도1.20을 적용하고 원래 도장 색·맵과 중성 반사를 보존한다. 차고·라이벌·도로변 주차 차량에도 적용한다.
- 기존 표면 질감 셰이더를 먼저 호출하는 방식으로 보정을 덧붙였다. CSS 화면 필터나 추가 전체 화면 렌더링 패스를 사용하지 않는다.
- 색 보정은 남악 코스에 한정한다. Blender 원본·GLB 기하·물리·조향·UI 배치는 바꾸지 않았다. 팔레트는 웹 런타임에 적용되므로 Blender에서 단독으로 열면 기존 원본 색이 보인다.
- 변경 전 파일·스크린샷과 검증 로그는 `artifacts/namak-color-20261010/`에 보관한다. 이번 작업은 색감 검수이며 장시간 성능·휴대폰 검수의 기존 제한은 유지한다.
