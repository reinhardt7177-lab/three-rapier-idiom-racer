# Game Studio · 주행·그래픽 개선 설계

사용자 요청: 전체를 점검하고 그래픽, 차량 움직임과 조작감을 개선한다. 기존 선택인 Three.js + Rapier, 8종 차량, 4코스와 온라인 1:1을 유지한다. 새 엔진이나 콘텐츠로 교체하지 않는다.

## 방향과 대안

- **선택한 구현 판단:** 기존 안정 차체 지지 위에 사람용 조작 교정만 분리한다. 이전 56조건 수치를 같은 코드로 재측정한 뒤 회귀를 확인한다. 라이벌의 기존 교정은 보존한다.
- 전역 접지 변경은 AI까지 바뀌어 이전 완주 실패를 재발시킬 수 있다. 새 차체 물리/모델 전체 제작은 이번 원인과 직접 관련이 없고 검증 범위를 과하게 늘린다.
- 새로운 승인 절차를 요구하지 않고 사용자가 요청한 기존 게임 개선 범위에서 진행한다. 이번 새 운영 배포는 포함하지 않는다.

## 주행 범위

- 별도 `humanRaceTuning(id)`를 단독/AI 대전 플레이어에 적용한다. 현재 `playerRaceTuning`은 호환용 고접지 프리셋으로 보존한다. 보통/어려움 라이벌은 이전 값 그대로다.
- 온라인은 기존 프로토콜/양측 물리 계약을 유지한다. 새 사람용 교정의 온라인 확대는 별도 버전·두 기기 검수가 필요하다.
- 사람용 조향 상한은 실제 수평 이동 속도로 계산하고, 드리프트 보정은 옆으로 미끄러지는 중에도 유지한다. 후진·구동계는 부호 있는 앞 방향 속도를 계속 사용한다.
- 평지 실제 Rapier의 8종에서 80km/h 선회 약 1.5~1.8G, 보정 켠 90km/h 사이드브레이크 1.5초 뒤 45km/h 이상, 최고 yaw 110°/s 이하를 목표로 검증한다. 기존 차체 지지·충돌면·휠 접촉·메달 기준을 보존한다.
- 눈에 보이는 차체 스프링과 카메라는 이미 구현됐다. 현재 부호·한계·접촉·시야부터 재검증하고, 근거 없이 진동을 더하지 않는다.

## 그래픽 범위

- 여수의 레이스 반사는 차고의 흰 소프트박스 대신 청남색 하늘, 차가운 도로 윤곽광과 작은 따뜻한 수변 광원을 PMREM으로 한 번 구워 사용한다. 기존 두 환경맵 예산을 재사용한다.
- 기존 64px 공용 노면 그레인으로 다른 코스에도 작은 표면 요철과 거칠기 변화를 적용한다. 정점·충돌·경로·추가 텍스처·반사 패스를 늘리지 않는다.
- Blender 도장/유리/고무 계약과 모델, 지도·음원, 블로그 20장은 보존한다. 새 사진 텍스처를 무단 복제하지 않는다.

## 검증·중단

- 파일 시각과 Git 변경 확인, 수정 전 사본, 실패 원자료를 `artifacts/game-studio-20261103/`에 보존한다. 실제 캡처는 `.work/game-studio-20261103/screens/`에 둔다.
- 실패하는 원인 시험 → 최소 수정 → 관련 시험 → 격리본 전체 `npm run check` → 브라우저 검수 순서다. 기존 단언을 낮추지 않는다.
- 전체 레이스·교통·비·온라인 자동 검사를 포함한다. 기존 완주 악화 또는 같은 기능 4번째 실패면 새 확장을 중단하고 원인을 기록한다.
- 1280×720, 1024×768, 844×390, 667×375와 세로390×844에서 차고/메뉴/입력·시야를 검수한다. 실기기라고 부르지 않는다.
- 같은 조건 30초 프레임 평균/p95/최대/>50ms, CPU 제출·그림자/패스·초기 용량을 기록한다. 새 기능 때문에 남악 낮음 p95가 2ms 넘게 악화되면 원인을 고치거나 제외한다.
- 모든 결과는 새 보고서와 NEXT_STEPS에 실제 실행 범위대로 기록한다.
