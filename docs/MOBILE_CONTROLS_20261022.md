# 휴대폰·태블릿 조작 버튼 누락 수정 · 2026-10-22

## 문제와 원인

- **P1:** 터치 기기에서 주행 버튼이 없으면 키보드 없이 레이스를 할 수 없다.
- 기존 CSS는 작은 게임 화면에서만 `.touch-controls`를 표시했다. 1024×768 창의 16:9 게임 영역은 1024×576이므로 높이 550px 조건을 벗어나 버튼 6개가 DOM에 있어도 `display:none`이었다. 수정 전 브라우저에서 직접 재현했다.
- 세로 화면 차단은 기본 포인터의 `(pointer: coarse)`만 보았다. 마우스를 연결한 태블릿, 데스크톱 표시를 쓰는 터치 브라우저가 빠질 수 있는 구조였다. 이 부분은 코드 확인에 따른 원인 추론이며 해당 기기에서 직접 재현한 것은 아니다.
- 기존 `raceLayout`의 폭 1000px 제한도 최신 CSS의 높이 550px 이하 규칙과 달랐다. 버튼 표시 정책과 입력 해제 정책을 같은 함수로 맞췄다.

## 변경

1. 기본 포인터·보조 포인터의 coarse 여부와 `navigator.maxTouchPoints`를 함께 사용한다. 터치 기기는 큰 화면에서도 버튼을 표시한다.
2. 작은 화면의 키보드 브라우저도 기존처럼 버튼을 사용할 수 있다. 큰 키보드 전용 창은 자동 모드에서 버튼을 숨긴다.
3. **메뉴 → 터치 버튼 항상 표시**를 추가했다. 선택은 로컬에 저장하며 저장이 막혀도 현재 창에서는 작동한다. ‘자동’으로 돌아가면 기기·화면 조건을 따른다.
4. 버튼은 최소 44×44 CSS px, 태블릿에서는 최대 68×68px로 커진다. 노치·홈 표시 영역의 safe-area를 피하고, 속도계와 시점 전환 버튼을 페달 위로 이동했다. 도로 중앙에는 버튼을 놓지 않는다.
5. 버튼 표시 방식이 바뀌거나 화면이 회전하면 모든 입력 소유자를 해제하고 일시정지한다. 포인터 캡처·취소·놓침 처리, 가속·조향 동시 입력, 키보드 입력은 유지했다.
6. 조향·가속·제동 버튼에 한국어 접근성 이름을 달았다. 이번 변경에서 차량 물리·AI·도로·충돌·메달 기준은 수정하지 않았다.

## 검증

### 자동 시험

- 관련 시험: `node --test --test-concurrency=2 scripts/touch-controls.test.mjs scripts/landscape.test.mjs scripts/race-controls.test.mjs` **20/20 통과**, 2.18초.
- 새 시험 5개: 혼합 포인터/터치 인식, 큰 태블릿/수동 표시, 550px 경계와 1000px 초과 창, 버튼 표시 변경 시 입력 해제, 혼합 포인터 태블릿의 세로 회전 차단.
- 기존 시험의 표시 경계는 실제 CSS와 일치하도록 바로잡았으며, 입력 고착·충돌·안정성 통과 기준은 낮추지 않았다.
- 마지막 코드 정리 뒤 정책·회전 시험 **11/11 재통과**.
- 전체 `npm run check` 첫 실행: **491건 / 484 통과 / 7 실패**, 662.68초. 7건 모두 결과 보고서 저장 중 `UNKNOWN / errno -4094 / syscall open`으로 끝났다. 차량 완주·추락 조건의 실패와 구분한다. 실패 증거는 삭제하지 않았다.

### 실제 브라우저 화면 측정

Windows의 Codex 내장 Chromium에서 창 크기를 바꾸어 **여수 / 낮음 / 6대 레이스**를 렌더링했다. 태블릿 크기의 터치 스타일은 ‘항상 표시’로 검사했고, 휴대폰 크기에서는 ‘자동’도 확인했다. 하드웨어 터치·모바일 운영체제를 에뮬레이션한 것은 아니다.

| 창 크기 | 버튼 수 | 한 버튼 크기(px) | 잘림 / 중심 가림 / 버튼·HUD 겹침 |
| --- | ---: | ---: | --- |
| 1280×720 | 6 | 68 | 0 / 0 / 0 |
| 1024×768 | 6 | 57.6 | 0 / 0 / 0 |
| 1366×1024 | 6 | 68 | 0 / 0 / 0 |
| 1180×820 | 6 | 66.4 | 0 / 0 / 0 |
| 844×390 | 6 | 44 | 0 / 0 / 0 |
| 667×375 | 6 | 44 | 0 / 0 / 0 |

경계 상자와 `elementFromPoint`로 버튼 중심의 실제 클릭 대상을 검사했다. 숫자는 게임 캔버스와 창 경계를 모두 검사한 결과이며, 소수점 1px 이내의 브라우저 좌표 반올림을 허용했다. 속도계·시점 버튼과 페달 간격은 10px 이상이다.

- 1인칭에서도 6개 버튼 중심이 모두 클릭 대상이고 최소 크기를 만족했다.
- 마지막 자동 모드 확인: 1280×720 키보드 창은 숨김, 667×375 작은 창은 44×44px 버튼 6개 모두 표시·클릭 대상. 검사 뒤 ‘항상 표시’ 선택은 자동으로 돌리고 브라우저 크기 강제 설정도 해제했다.
- 실제 GAS 버튼 1.6초 누름 후 **48km/h**, 놓은 뒤 입력 전부 0. 메뉴 진입 시 일시정지·입력 전부 0.
- 포인터 GAS + 키보드 A 조합을 보낸 뒤에도 입력은 모두 해제됐다. 누르는 도중의 원격 관찰은 입력 명령 종료 후 도착했으므로 동시 입력 유지 자체는 단위 시험의 다중 소유자 검증과 구분한다.
- 화면을 768×1024 세로로 바꾸면 `pauseReason: layout`, 입력 전부 0. 터치 기기의 세로 회전 안내/차단은 단위 시험으로 확인했다.
- 차고 → 출발 → 메뉴 → 다시 시작 → 차고 복귀 → 새로고침 → 재출발을 확인했다. 표시 선택도 새로고침 후 유지됐다.
- 브라우저 콘솔 오류 0. 처음 한 번 복귀 버튼이 눌리지 않은 것은 포커스 상실로 일시정지된 상태였다. 상태 확인 후 재개하여 동일 검사를 완료했다.

## 남은 확인과 반영 상태

- **실제 iPhone/iPad Safari·Android Chrome에서** 두 손가락 가속+조향, 노치·주소 표시줄·회전·iframe 전체 화면을 확인해야 한다. 실기기 지원 완료로 표현하지 않는다.
- 이번 브라우저 검사에서 레이스 완주/결과 화면까지 다시 달리지는 않았다. 전체 자동 회귀 검사의 완주·온라인·물리 시험과 구분한다.
- 이번 UI 변경만의 고정 조건 프레임 A/B 측정은 하지 않았다. 새 물리 계산·조명·메시·매 프레임 루프는 추가하지 않았다.
- 최초 검증은 로컬 수정이었다. 후속 사용자 요청으로 `85a34ea`를 GitHub·Vercel Production에 반영했다. 공식 도메인 연결 확인과 이 PC의 DNS 접속 제한, 기본 운영 주소의 실제 버튼 검증은 [배포 보고서](DEPLOY_MOBILE_20261022.md)를 따른다.
- 가장 중요한 다음 작업: 빌드 배포 후 보고한 휴대폰·태블릿에서 실제 터치 검수.
