## 적용한 변경

1. **정지한 차고의 반복 렌더 제거.** 차고는 자동 회전하지 않으므로 OrbitControls 변경·감쇠·휠 확대·차종/품질/자원/화면 변경이 있을 때만 다시 그린다. 레이스 중에는 기존처럼 매 RAF 렌더하며 물리 120Hz를 유지한다.
2. **경로 검색의 불필요한 거리 계산 제외.** 힌트 지점의 정확한 거리를 상한으로 사용해 축 거리만으로 불가능한 후보를 건너뛴다. 최종 `Math.hypot`, 원래 순회 순서·동점 우선순위·35m fallback은 유지했다. 오래된 해안 생성 경로의 투영 검색에도 같은 제외 원칙을 적용했다.
3. **측정 범위 구분.** 의도적으로 기다리는 차고/일시정지를 주행의 긴 프레임으로 집계하지 않는다. 주행 표본을 제거하지 않으며, 일시정지/출발 때의 기존 측정 초기화 규칙을 유지한다.

물리 계수·충돌·AI 페달·라이벌 속도·메달·일반차 수·장식 거리·그림자/픽셀 비율·모델·음악은 이번 최적화에서 바꾸지 않았다. 변경 전 사본은 `artifacts/frame-optimization-20261103/before/`에 있다.

## 원인 확인과 검증 가능한 효과

- 같은 차고 높은 품질에서 기준본은 23.093초 동안 **877회** 그렸다. 수정본은 23.477초 동안 자동 draw **0회**(총 draw 2→2)였다. 실제 휠 확대 입력에서 카메라 위치가 바뀌며 draw 2→3으로 즉시 재개했다. 이는 차고의 렌더 절감이며 주행 FPS 향상 수치가 아니다. idle 동안 DOM 통계도 갱신하지 않으므로 DOM의 stale `skipped` 값을 실제 누적 skip 수로 해석하지 않는다.

## 실패·수정·한계

- 최초 새 시험은 거리 호출/idle 요구의 실패를 확인했다. 한 fixture 이름을 `world-route.json`으로 바로잡고 원래 실패 로그를 보존했다.
- 독립 코드 검토에서 **휠/핀치가 RAF 전에 카메라 update를 소비해 화면이 그대로일 수 있음**을 발견했다. 실제 설치된 OrbitControls로 RED를 재현하고 `change` 구독·dispose 해제로 고쳤다. 최종 관련40/40과 브라우저 휠 확대가 통과했다.
- 차고 대기를 주행 긴 프레임으로 표시할 수 있는 측정 문제도 검토에서 발견해 주행/idle 집계 범위를 분리했다.
- 첫 CPU probe의 상대 import 경로 오류와, 남악 A2 측정 전 이동해 미완료된 표본을 보존했다. 각각 경로 수정, 30초 전체 조건 재실행으로 정정했다. 완료된 불리한 표본을 버린 것이 아니다.
- 보존 검증 helper의 `activeRide.js` 위치를 잘못 지정해 처음 파일 확인이 실패했다. 실제 `src/rebuild/activeRide.js`로 수정한 후 핵심4파일·자산29개·제품/시험230입력 불변을 통과했다. 제품 파일 문제는 아니었다.
- 실제 휴대폰/태블릿, 두 기기 온라인 장시간, 여수 높은 품질 전체 랩의 프레임 안정성은 이번에 검증 완료하지 않았다. 다른 사용자 앱은 종료하지 않았고 OS/브라우저 보안 설정도 바꾸지 않았다. 비교용 서버만 종료했다.

다음으로 중요한 작업은 **여수 높은 품질의 장시간 긴 프레임을 사용자 실제 기기에서 구분 측정**하는 것이다. 이번에 확인한 차고 낭비 제거와 정확한 경로 계산 절감을 유지하면서, 그래픽 비용을 바꾸는 후속 작업은 같은 카메라/구간의 전후 측정과 시각 검수를 함께 수행해야 한다.
