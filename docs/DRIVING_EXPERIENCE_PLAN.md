# MUMU CIRCUIT — 레이싱 체감·연출 작업 계획

**2026-09-06 방향 변경:** 사용자가 공도·스토리·컷신을 요청했다. 장르/지도 방향은 [공도·스토리 전환안](STORY_PUBLIC_ROAD_PLAN.md)이 우선하며 이 문서의 주행 물리·카메라·코너 체감 계획은 이어서 사용한다. 폐쇄 서킷이 아닌 공도 코너와 선택형 주행 이벤트로 적용한다.

작성일: 2026-09-05  
상태: 사용자 방향 확인을 반영한 **계획 / 아래 신규 기능은 미구현**  
적용 기준: 이후 주행 경험 작업은 이 문서를 우선한다. 기존 해안 서킷·항구 차고 방향은 유지한다.

후속 실행 갱신: 사용자가 차고 수준의 도로 디테일을 재강조해 [출발부 항구 도로 400m 시안](HARBOR_ROAD_DETAIL.md)을 추가했다. 이는 미술 기준을 먼저 확인하는 제한된 구현이며, 아래 P1 코너 구간·P2/P3 상태별 연출이 완료됐다는 뜻은 아니다. 최신 자동 시험은 15개다.

## 1. 목표를 다시 정의한다

**우리 항구·해안의 미술 정체성은 유지하면서, 레퍼런스처럼 운전의 변화가 즉시 느껴지는 레이싱을 만든다.**

사용자가 원하는 것은 붉은 협곡·소나무·주황색 하늘의 복제가 아니다. 빠른 직진, 제동과 코너 진입, 미끄러짐 제어, 코너 탈출이 화면과 소리에서 구분되는 경험이다. 이전의 '협곡 스타일 장면부터 제작' 제안은 이 방향으로 수정한다.

첨부 이미지에서 확인 가능한 것은 코너/직선 구성, 타이어 흔적과 흰 연기, 강한 가속 장면의 흐림/빛, 작은 경기 HUD다. 원본의 카메라 수치·드리프트 물리·게임 실행 성능·효과 발생 조건은 스크린샷으로 검증하지 않았다. 아래 항목은 원작의 내부 구현 설명이 아닌 **우리 게임용 설계안**이다.

## 2. 유지할 것과 가져올 것

| 구분 | 방향 |
|---|---|
| 유지 | 항구 정비소, 같은 GT, 청록·크림·짙은 금속색, 바다와 산업 항구 소품, 재질 구분과 절제된 조명 |
| 가져올 경험 | 코너 전방이 읽히는 카메라, 근거리 풍경의 통과감, 미끄러짐과 접지 회복의 피드백, 조작에 동기화된 소리 |
| 우리식 해석 | 방파제 반사 표지·부두 울타리·노면 이음새로 거리감을 만들고, 타이어 흔적·낮은 연기·짧은 HUD 표시로 운전 결과를 전달 |
| 가져오지 않음 | 원작 지형/로고/UI 복제, 차량을 가리는 큰 발광 효과, 상시 화면 흔들림, 속도계만 부풀리기 |
| 보존 | 기존 차고 설정/색상/복귀, 좌우 조향 수정, 실제 미터 단위 차량 물리와 검증용 직선 |

차고는 머물며 감상하는 공간, 레이스는 전방 정보를 빠르게 읽는 공간이다. 두 장면은 재질과 색을 공유하되 차고의 높은 사선 카메라를 주행 카메라로 그대로 사용하지 않는다.

## 3. 현재 출발점

구현된 것:

- Rapier GT 1대, 가속·제동·후진·조향·접지·충돌, 120Hz 고정 물리 스텝.
- 약 232km/h 고속 주행 계측, 차고↔시험장 전환, 키보드/포인터 입력.
- 차량 상대 위치 기반 추격 카메라, 최대 6도 시야각 변화, 가까운 노면/도로변 시각 기준.
- 기본 꺼짐의 합성 엔진음·바람 소리, 볼륨/음소거, 일시정지 시 무음.
- 자동 시험 14개와 별도 브라우저 검증. 자세한 결과는 VEHICLE_STAGE1.md / SPEED_FEEL_STAGE2.md.

아직 부족한 것:

- 코너가 없는 직선이므로 코너 진입→탈출의 재미를 평가할 수 없다.
- 카메라가 차체 전방만 바라보며 실제 코스의 다음 진행 방향을 모른다.
- 현재 drifting 값은 핸드브레이크 입력과 속도 조건일 뿐, 실제 미끄러짐 검출이 아니다.
- 동적 타이어 흔적·연기·접지 회복음·제동/드리프트 소리가 없다.
- 소리는 속도 기반 합성 시안이며, 실제 변속기와 부하 모델은 아니다.
- 기기별 실시간/게임 시간 비율을 표시하지 않는다. 100ms 프레임 시간 제한 때문에 심한 저프레임에서는 느린 진행이 발생할 수 있다.

## 4. 먼저 만들 플레이 구간

기존 1.8km 직선은 회귀 시험용으로 보존한다. 별도로 **300~500m 코너 시험 구간**을 만들고 진입 가속로와 탈출 감속 공간을 연결한다. 300m 안에서 정지 출발→230km/h→급코너를 모두 강요하지 않는다. 필요한 접근 거리는 현재 GT의 가속/제동 계측으로 정한다.

플레이 흐름:

**직선 가속 → 제동 표식 → 완만한 코너 → 저속 헤어핀 → 접지 회복 → 짧은 탈출 직선**

- 첫 코너는 고속에서도 방향을 읽는지, 헤어핀은 제동·회전·후륜 미끄러짐을 제어할 수 있는지 평가한다.
- 모든 코너를 230km/h로 통과하도록 만들지 않는다. 직선의 빠름과 코너의 감속 사이에 차이를 둔다.
- 트랙 중심선·폭·곡률·누적 거리에서 노면, 충돌 경계, 진행 안내를 함께 생성한다.
- 시작 폭은 약 18~20m 후보. 급하게 도로를 좁혀 속도감만 높이지 않고 현재 차 크기/회전 반경을 기준으로 검증한다.
- 가까운 반사 표지/울타리만으로 거리감을 평가한다. 대규모 건물·절벽 미술과 AI는 뒤로 미룬다.
- 자동 가속/자동 조향을 정식 조작 대신 넣지 않는다. 테스트용 재현 입력은 별도 진단 기능으로만 사용한다.

## 5. 주행 상태별 연출 설계

아래 수치는 초기 튜닝 후보이며 완성 기준 수치가 아니다. 실제 입력 테스트로 확정한다.

| 상태 | 감지 기준 | 화면·소리 반응 | 피해야 할 것 |
|---|---|---|---|
| 가속 | 실제 종방향 가속도 + 구동 입력 | 작은 시야각 변화, 엔진 부하 변화, 속도에 비례하는 풍절음 | 가속 버튼만 누르면 정지 중에도 고속 효과 발생 |
| 고속 직진 | 실제 속도 + 접지 | 일정한 차 크기, 가까운 표지 통과, 안정된 수평선 | 카메라가 계속 멀어지기, 반복 흔들림 |
| 제동/코너 진입 | 실제 감속 + 다음 코스 방향 | 시야각을 부드럽게 회복, 코너 출구를 예측하는 시선, 제동음 | 과도한 앞뒤 흔들림이나 강제 카메라 회전 |
| 드리프트 | 차체 방향과 속도 방향의 차이 + 횡속도 + 접지 | 실제 접지 지점의 자국, 제한된 연기, 타이어 마찰음, 짧은 상태 표시 | 핸드브레이크 버튼만으로 드리프트 판정, 정지/공중 연기 |
| 탈출/접지 회복 | 슬립 감소 + 재가속 | 연기/마찰음 감소, 전방 시선 복귀, 엔진 부하 증가 | 갑작스러운 차체 정렬, 숨겨진 가속 보정 |
| 충돌 | 실제 접촉 충격량 | 짧은 둔탁한 충돌음, 필요할 때만 작은 반응 | 충돌마다 화면 전체를 가리는 효과 |

상태는 렌더 프레임이나 키 누름만으로 정하지 않는다. 물리 상태에서 감지하고, 진입/종료 임계값을 다르게 두어 경계에서 효과가 깜빡이지 않게 한다. 예: 드리프트 시작은 속도 40km/h 이상·슬립각 8도 이상이 0.2초 유지되는 조건부터 시험, 종료는 5도 미만 등으로 분리한다. 방향/접지/최소 속도 검증 후 수치를 조정한다.

핸드브레이크는 계속 후륜 제동 입력이다. '드리프트 진입 입력'과 '현재 실제 드리프트 상태'를 분리한다. 회복이 어려우면 타이어/조향 보조를 공개된 설정으로 검토하고, 모델을 강제로 돌려 물리 결과처럼 보이게 하지 않는다.

## 6. 단계별 작업 순서와 산출물

| 단계 | 작업 | 산출물 | 다음 단계로 넘어갈 조건 |
|---|---|---|---|
| P0. 기준 측정 | 실제 시간/게임 시간, 이동 거리, 프레임 간격, 카메라 거리, 입력 로그 수집 | 기존 직선 기준 영상/계측표, 재현 가능한 테스트 입력 | 정상 실행에서 시간과 거리 일치; 저프레임 차이는 별도 표시 |
| P1. 코너 시험 구간 | 직선+완만한 코너+헤어핀, 공유 트랙 데이터와 충돌 경계, 복귀 | 직접 운전할 수 있는 코너 데모 | 좌우 코너 통과/감속/복귀 가능, 경계 관통 없음 |
| P2. 상태·카메라 | 가속/감속/슬립/접지 이벤트, 코스 전방 예측, 차체·진행 방향 혼합 시선 | 같은 구간 연출 전/후 비교 | 코너 출구가 보이고 드리프트 중 차를 놓치지 않음 |
| P3. 타이어·소리 | 접지 기반 자국, 제한된 연기, 슬립 마찰음, 가속/감속 음색, 충돌음 | 직진·제동·드리프트·회복 구별 시연 | 정지/공중 오작동 없음, UI/차량 가림 없음, 음소거/정리 검증 |
| P4. 해안 정체성 결합 | 시험 구간을 방파제/항구/바다의 가까운 풍경으로 정리 | 실제 플레이 영상 + 기준 스크린샷 | 효과를 꺼도 우리 장소로 읽힘; 미술 추가 후 성능 재검증 |
| P5. 선택적 강한 연출 | 짧은 가속 강조, 약한 주변부 효과, 필요 시 별도 부스트 기능 | 켬/끔 비교 및 사용자 선택 | 사용자가 효과 강도를 선호하고 전방 시야·성능을 해치지 않음 |

**다음 구현 묶음은 P0 + P1이다.** 기존 카메라/소리를 붙인 코너 데모를 먼저 운전해 보고, P2/P3를 상태별로 추가한다. 미술 작업만 다시 길게 진행하는 순서로 돌아가지 않는다.

P5는 자동 확정하지 않는다. 특히 부스트는 단순 빛 효과가 아니라 추진력·최고속도·충돌 안전성에 영향을 주는 게임 규칙이므로 별도 결정 후 구현한다. 기본 약 232km/h를 몰래 높이거나 레퍼런스 화면의 304 숫자를 목표로 고정하지 않는다. 드리프트 점수/콤보·보상 경제도 1차 범위에서 제외한다.

## 7. 코드 작업 단위

파일명은 구현 시 조정할 수 있는 예정 구조다.

- `physics.js`: 현재 차량 규격/속도 검증 유지. 필요한 읽기용 가속도·횡속도·접지/충격 정보 노출.
- `trackPath.js`(신규): 중심선, 폭, 곡률, 진행 거리와 전방 샘플. 노면/충돌체/카메라가 같은 데이터를 사용.
- `drivingSignals.js`(신규): 물리 상태를 가속·제동·슬립·회복 이벤트로 정리. 임계값과 유효 시간은 한 설정에 모음.
- `chaseCamera.js`: 전방 코스/속도 방향을 반영하되 병진 추격 지연 제거는 유지. 뒤집힘·후진·리셋의 안전한 기본 시점.
- `tireFeedback.js`(신규): 고정 크기 자국/입자 풀, 실제 휠 접점 좌표, 수명·거리 제한. 매 프레임 새 객체를 누적하지 않음.
- `drivingAudio.js`: 동일 이벤트로 타이어/충돌/부하음 연결. 음소거·일시정지·Context 정리 유지.
- `DrivingMode.jsx`: 작은 상태 표시와 연출 강도 설정. 실시간 물리 계산은 React 렌더 밖에 유지.
- `scripts/`: 상태 전환 단위 시험, 좌/우 코너 회귀, 동일 입력 연출 ON/OFF 비교, 실제 브라우저 성능/오디오 검사.

카메라·자국·연기·소리가 각각 다른 드리프트 판정을 하지 않도록 하나의 주행 상태를 공유한다. 순수 연출 ON/OFF는 물리 결과를 바꾸면 안 된다.

## 8. 검수 기준

### 수치 검증

- 직선 230km/h 유지 구간은 초당 약 63.9m와 일치. 계기판 속도·좌표 변화·게임 시간·실제 시간을 따로 기록.
- 목표 기기의 정상 프레임 구간에서 10초 이상 측정한 게임 시간/실제 시간 비율 0.98~1.02를 우선 목표로 삼는다. 초기 로딩/명시적 일시정지는 구분한다.
- 30/60/120FPS 재현 입력에서 조향 부호·경로·가감속을 비교. 효과 OFF에서도 동일 입력에 같은 물리 결과.
- 저속·후진·공중·충돌·리셋에는 드리프트 효과가 잘못 남지 않아야 한다.
- 연기 최대 128개, 자국 최대 512세그먼트를 초기 상한 후보로 삼아 10분 주행 후 메모리/드로콜 증가 여부 확인. 기기 측정으로 조정.

### 실제 플레이 검수

- 같은 차/같은 색/같은 구간에서 직선→제동→좌우 코너→탈출을 촬영. 연출 전/후 비교는 조건을 맞춘다.
- 정지 이미지뿐 아니라 플레이 영상을 확인한다. 멋진 한 프레임만으로 속도감 합격을 선언하지 않는다.
- 사용자에게 확인할 세 항목: **속도가 읽히는가 / 코너를 예측할 수 있는가 / 미끄러진 차를 다시 잡기 쉬운가.**
- 390px 세로 화면과 데스크톱에서 전방 코너/차량/HUD 가림 검수. 실제 사용자 기기 결과와 헤드리스 테스트 결과를 분리한다.
- 기본은 화면 회전/강한 블러 없음. 움직임 줄이기·효과 낮음·소리 끔으로도 조작 정보가 유지되어야 한다.
- 소리는 정지/가속/미끄러짐에서 구별되되 효과 중첩으로 클리핑하지 않음. 사용자의 실제 청취 피드백과 파형 측정을 모두 사용.

### 성능 목표

기준 기기·해상도를 먼저 기록하고 60FPS를 목표로 측정하되 모든 기기에서 보장하지 않는다. 프레임 중앙값/상위 지연값, 100ms 초과 프레임, 시간 손실을 기록한다. 성능이 부족하면 입자→후처리→그림자 비용을 줄이며, 플레이 속도 자체를 낮추는 것을 품질 옵션으로 삼지 않는다. 기존 시간 제한을 무작정 제거해 큰 물리 스텝을 넣지도 않는다.

## 9. 범위와 결정 지점

- 이번 요청에서는 **계획 문서만 작성**한다. 런타임/물리/그래픽은 변경하지 않는다.
- 기존 코드 삭제, 새 외부 에셋 도입, 다른 엔진 전환, GitHub push/Vercel 배포는 포함하지 않는다.
- P1 시연 후 코너 폭·조향·제동감을 먼저 확인한다. P3 시연 후 연출 강도를 확인한다. 승인 전 AI/전체 맵/수집 시스템으로 확장하지 않는다.
- 일정은 확정 시간 약속 대신 위 단계별 통과 조건으로 관리한다. 현재 목표는 원작 복제가 아니라 **우리 차량이 우리 해안에서 재미있게 달리는 첫 구간**이다.
