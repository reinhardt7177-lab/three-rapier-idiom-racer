# 태블릿 주행 HUD · 시야 우선 개편

## 판단

기존 화면은 주행 안내·오디오 설정·복귀 버튼·물리 진단값을 상시 표시해 도로 소실점을 가렸다. 단순 축소는 작은 글씨와 작은 터치 영역만 만들기 때문에, **주행/메뉴/차량 점검** 세 상태로 정보를 나눴다. 항구의 청록·석재·브라스 미술과 차량 물리는 유지한다.

## 현재 구현

- 주행 중: 상단 가장자리의 한 줄 방향 안내와 메뉴 버튼, 하단 모서리의 속도·기어만 표시한다. 큰 안내판·물리 수치·키보드 설명·오디오 패널은 제거했다.
- 일시정지 메뉴: 목적지 지도, 무전 기록, 도로/시작점 복귀, 차고 이동, 그래픽, 터치 표시, 소리, 차량 점검을 모았다. 시작점 복귀 버튼은 확인 단계를 거친다. 기존 R 단축키는 유지한다.
- 메뉴가 열리면 물리와 이야기 시간이 정지한다. 네이티브 dialog의 키보드 포커스 제한, Escape 닫기, 닫은 뒤 캔버스 포커스 복귀를 적용했다. 긴 메뉴에서도 주행 재개 버튼을 찾도록 헤더를 고정했다.
- 정차 바퀴 점검은 메뉴에서 진입한다. 메뉴를 닫아 실제 바퀴 조향을 보되 가속/후진은 차단하는 기존 점검 규칙을 유지한다.
- 진행 중 이야기의 긴 무전은 메뉴의 무전 기록에서 확인한다. 컷신/결과 화면은 기존 흐름을 유지하고, 주행 목표는 상단 안내로 표시한다.

## 갤럭시 탭 기준

정확한 모델을 지정하지 않은 일반 삼성 태블릿을 대상으로 한 초기 설정이다. 특정 기기의 성능 인증이 아니다.

- 가로 우선, 세로와 좁은 분할 창도 지원한다. 카메라는 화면 방향/폭을 함께 보고 조정하며 고정 700px 기준만 쓰지 않는다.
- 조향·가속·제동은 64–80 CSS px, 메뉴·보조 핸드브레이크는 52px 터치 영역이다. 양손 조작 영역을 하단 양끝에 배치하고 중앙을 비운다.
- 터치 기기는 버튼 자동 표시, 키보드/마우스 기기는 자동 숨김. 메뉴에서 항상 표시/숨김으로 바꿀 수 있다.
- pointerId별 입력을 분리한다. 서로 다른 손가락의 가속/조향, 같은 버튼 위의 두 손가락도 독립적으로 해제한다.
- 메뉴·창 전환·큰 화면 크기 변화 때 입력을 지우고 일시정지한다. 단순한 주소창 높이 변화가 빈번한 정지를 만들지 않도록 높이 변화에는 여유를 둔다.

## 그래픽 옵션

| 옵션 | 최대 픽셀 배율 | 화면 픽셀 예산 | 태양 그림자 |
|---|---:|---:|---:|
| 경량 | 1.0 | 180만 | 1024² |
| 표준 | 1.5 | 320만 | 2048² |

해상도와 실제 기기 DPR에 따라 픽셀 예산 이하로 더 낮출 수 있다. 터치 기기 첫 방문은 경량, 비터치 기기는 표준이다. 옵션은 메뉴에서 런타임에 적용하며 물리의 120Hz 스텝, 최고속, 조향을 바꾸지 않는다. 설정은 별도 `mumu.coast.hud.v1` 키에 저장하며 기존 차고/스토리 저장값을 건드리지 않는다. 저장이 차단되면 현재 방문에만 적용하고 안내한다.

30FPS 안정화·여유 기기 60FPS는 실기기 검증 목표일 뿐, 현재 FPS 보장이나 자동 품질 조절/30FPS 고정 기능을 뜻하지 않는다. 초기 번들 크기 경고도 남아 있다.

## 검증

`npm run check`: 기존 물리/스토리/도로 시험과 HUD 설정·멀티포인터·화면 분류·렌더 예산 5개를 포함해 **40개 시험 + 빌드**.

`scripts/verify-tablet-hud.cjs`:

- 1280×800, 800×1280, 1024×600, 600×960, 390×844, 640×400 CSS viewport.
- 정한 중앙 보호영역(가로 25–75%, 세로 24–80%)과 상시 HUD의 교차 0개, 가로 넘침 0개. 이것은 장면의 모든 코너/카메라 각도에서 시야가 완벽함을 보증하지 않는 최소 검수 기준이다.
- 실제 Chrome 터치 프로토콜로 두 손가락 가속+조향, 취소, 손가락을 누른 채 메뉴/화면 회전, 해제 후 주행을 검증.
- 메뉴 물리 정지·포커스·Escape, 그래픽 옵션의 실제 DPR/그림자 변경, 터치 표시, 바퀴 점검/주행 복귀, 저장/새로고침 확인.
- 오류 0건. 결과와 스크린샷은 `artifacts/tablet-hud/verification.json` 및 같은 폴더에 저장.

기존 브라우저 스크립트도 `scripts/drive-ui.cjs`를 통해 새 메뉴에 접근하도록 갱신했다. 자동으로 차를 이동시키거나 스토리 완료값을 덮어쓰지 않는다.

새 UI로 `verify-story.cjs`(컷신·실제 의뢰 완료·저장·재진입), `verify-driving.cjs`(200km/h 이상·제동·후진·키/터치·일시정지), `verify-speed-feel.cjs`(225km/h 카메라·실제 소리 출력·음소거·소리 정리)도 순차 실행해 통과했다. 긴 해안길 브라우저 왕복은 이번 UI 변경 후 다시 실행하지 않았으며, 기존 검증 기록과 현재 자동 물리 왕복 시험을 구분한다.

## 남은 실기기 확인

1. 실제 갤럭시 탭의 Chrome과 Samsung Internet에서 가로/세로, 주소창, 앱 전환, 안전 영역 확인.
2. 경량/표준 각각 10분 이상 주행하며 프레임 시간·발열·배터리 상태 기록.
3. 실제 양손 엄지 조작에서 버튼 간격과 스티어링 연타 피로도를 확인.
4. 코너 주행과 무전 확인 시 정보량을 사용자 피드백으로 조정.

이번 결과는 Chrome 터치 에뮬레이션/소프트웨어 GPU 검증이다. 물리 삼성 기기, Samsung Internet, 장시간 성능·발열은 아직 검증하지 않았다. GitHub 추가 푸시나 운영 배포는 수행하지 않았다.
