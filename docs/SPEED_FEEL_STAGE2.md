# 속도감 개선 2단계 — 2026-09-05

## 변경 범위

실제 차량 속도와 물리 설정은 유지했다. 이번 작업은 카메라·노면/도로변 시각 기준·합성 주행음이며, 완성 해안 서킷의 미술 작업은 아니다.

### 카메라

- 기존 세계 좌표 보간은 230km/h에서 약 8m의 추가 추격 지연을 만들었다.
- 차량 위치는 즉시 따라가고, 차량에 대한 상대 오프셋만 보간한다. 차체 방향 전환은 부드럽게 따라간다.
- 데스크톱 후방 거리 9.4~9.8m, 높이 3.3m. 모바일 후방 거리 12~12.4m, 높이 4.4m.
- 속도에 따른 시야각 변화는 최대 6도. 화면 흔들림·모션 블러는 추가하지 않았다.
- 시스템의 움직임 줄이기 설정이면 동적 시야각/오프셋 보간을 끈다.

### 노면과 도로변

- 시각적 주행 띠 폭 28m → 20m. 시험장의 넓은 포장 공간과 기존 충돌체는 유지.
- 코드 생성 아스팔트 잔무늬와 미세한 종방향 흔적, 지면 높이의 가장자리 교대 도색.
- 콘 100m → 20m 간격, 반사 표지 12m 간격, 노면 반사 마커 6m 간격.
- 반복 소품은 InstancedMesh로 묶었다. 가까운 거리 변화가 보이도록 배치했으며 차량을 강제로 가속하거나 배경을 별도 속도로 움직이지 않는다.
- 콘·표지는 여전히 시각 가이드이고, 가장자리 도색은 물리 연석이 아니다.

### 소리

- 외부 음원 없이 Web Audio 오실레이터와 필터링한 노이즈로 엔진음·바람 소리 합성.
- 기본 꺼짐. 사용자가 `소리 켜기`를 누를 때만 AudioContext 생성/재개.
- 볼륨 조절, 음소거, 일시정지/창 이탈 시 페이드아웃, 차고 복귀 시 노드와 Context 종료.
- 엔진 회전수/변속 소리는 속도 기반 연출이며 실제 기어박스 모델은 아니다.
- 음색은 1차 합성 시안이다. 파형 검증은 했으나 사용자의 스피커/헤드폰 음량과 주관적 음질을 보장하지 않는다.

## 검증

- `npm run check`: 총 14개 시험과 빌드 통과.
- 기존 Rapier 가속 시험: 18초 가속 후 232.2km/h 유지.
- 30/60/120FPS 카메라 시험: 고속 직진 시 상대 거리 증가 없음, 리셋 즉시 이동, 움직임 줄이기 시 시야각 고정.
- Chrome: 225.1km/h에서 카메라-차량 3차원 거리 10.316m, 시야각 62.58도.
- 실제 오디오 그래프 RMS: 공회전 0.0065, 고속 0.0288. 일시정지·볼륨 0·음소거는 모두 0.
- 소리 토글 시 그래프 재사용, 차고 복귀 시 AudioContext closed, 주행 재진입 시 기본 무음 확인.
- 데스크톱 고속 화면과 모바일 화면을 캡처해 차량 가림/가로 넘침 확인.
- `agent-browser` 미설치 환경이라 기존 Playwright + Chrome으로 검증 절차를 실행했다.

검증 스크립트: `scripts/speed-feel.test.mjs`, `scripts/verify-speed-feel.cjs`, 기존 `scripts/verify-driving.cjs`.
증거: `artifacts/speed-feel/verification.json`, `high-speed.png`, `mobile.jpg`.

## 제한 및 다음 단계

저프레임에서 누적 시간을 100ms로 제한하는 기존 물리 루프는 변경하지 않았다. 실제 기기의 심한 성능 저하는 별도 계측/최적화 대상이다. 이번 검증은 헤드리스 환경으로 기기별 FPS/음질 보증이 아니다. 큰 Rapier WASM 청크의 빌드 경고도 기존대로 남는다.

다음 단계는 직접 주행한 체감 피드백으로 카메라 높이·소리 비율을 미세 조정한 후, 짧은 해안 구간에 목표 미술을 적용하는 것이다. 로컬만 변경했고 GitHub push나 Vercel 배포는 하지 않았다.
