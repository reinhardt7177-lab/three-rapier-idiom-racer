# 여수·성삼재 도로 주변 고도화 · 2026-10-13

## 범위와 고증 한계

사용자 요청: 위성 지도와 현장 사진으로 두 코스의 도로 주변을 고도화한다. 이번 단위는 기존 도로·경로·충돌을 보존하는 Blender 시각 모델이다. 새 게임 규칙·물리 튜닝을 넣지 않는다.

- 여수는 기존 OSM 도로 좌표 8.90km 경로를 유지한다. 교량 하부·난간·부두·호안과 하멜등대, 누락된 육지 지면을 다룬다. 실제 교량 폭·높이와 게임 치수는 다르고, 건물은 개별 실측 복제가 아니다.
- 성삼재는 5.83km 레이스용 순환 경로다. 실제 노고단로의 측량 복제나 자동차로 노고단 정상에 오르는 코스가 아니다. 사진의 절개면·낙석 방지 시설·가드레일·전망데크 특성을 반영했다. 게임 차고 설명도 이 구분에 맞게 수정했다.
- 위성·사진은 조사 자료로만 사용했다. 제3자 원본 사진과 Google Maps 화면은 공개 에셋·Git 커밋에서 제외한다. 자산은 생성 스크립트와 Blender 원본에서 자체 제작한다.

## 구현·보존

- 독립 `yeosu-roadscape.glb`, `seongsamjae-roadscape.glb`를 코스별로 로드한다. 기존 물리 월드를 만든 뒤 시각 그룹만 추가한다.
- 각 모델은 공간 셀로 묶는다. 높음 300m, 보통 180m 안쪽 장식 셀을 표시하고 낮음에서는 추가 장식을 끈다. 여수 기반 육지는 높음/보통900m·낮음200m까지 유지해 건물 바닥이 먼저 사라지지 않게 한다. 셀 경계는 중심뿐 아니라 경계 구 반지름까지 고려한다.
- 추가 그림자·실시간 조명·사진 텍스처 패스가 없다. 차고에서 숨기고 코스 전환 시 기존 자원 정리 경로에 포함한다. 코스 모델 다운로드는 낮음에서도 발생한다.
- 별도 남악 작업이 같은 폴더의 `assets.js`, `namakVisuals.js`, `package.json`, `docs/NEXT_STEPS.md`를 수정 중임을 파일 시각/diff로 확인했다. 해당 변경을 보존했다. 이전 391시험 결과를 이번 변경의 검사로 사용하지 않는다.
- `start.json`의 이전 검사 대비 차이 중 `runtime.js`는 부모의 이번 통합 변경이다. 최초 확인에서 외부 작업으로 바뀐 파일은 `assets.js`와 `namakVisuals.js`였다. 시작 문서와 변경 전 사본은 수정하지 않는다.

## 발견한 실패와 수정

1. 여수 초기 장식 후보 4.78MB가 정한 3MB 예산을 초과했다. 줄눈·중복 난간 기하를 최적화하고 실패 후보를 보존했다.
2. 성삼재 주행 화면에서 고정 높이의 암반 층리선이 공중에 떴다. 실제 암반 경계에 밀착하고 모든 층리선 접촉 검사를 추가했다. 테스트 도구의 Float32 비교 반올림 오류도 원자료를 남겨 수정했다.
3. 여수 원본에는 육지 지면이 없고 바다 평면만 있어 건물이 떠 보였다. 긴 해안선 전체 중심으로 필터링하면서 필요한 해안 구간도 누락된 것을 확인했다. 원본 해안선에서 별도 육지층을 복원했고 기존 건물360/360개의 중심을 지면이 받친다. 두꺼운 해안 마감 후보의 예산 초과는 같은 평면의 면을 합쳐 해결했으며 예산을 늘리지 않았다.
4. 성삼재 신규 방향판의 좌우가 뒤집혀 있었다. 도로 전후 접선으로 방향을 계산하고 24개 실제 GLB 화살표를 접근 카메라에 투영해 검증했다. 수정 후 index880 화면에서도 좌회전 화살표를 확인했다.
5. 중단된 턴의 임시 브라우저 탭이 닫혔다. 여수 미완주 회차를 성공으로 세지 않고 새 탭에서 다시 완주했다. 성능 결과 읽기의 200,000자 제한은 DOM 값을 분할해서 읽어 원자료 전체를 보존했다.
