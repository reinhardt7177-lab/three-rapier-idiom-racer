# 주행 입력과 충돌 후 재출발 · 2026-10-09

현재 Blender 차량 3종과 Three.js / Rapier 웹 레이스의 조작 안정성을 보강했다. 플레이어 1대와 AI 5대, 기존 6.84km 코스와 차량 원본을 유지한다. 이번 변경은 로컬 웹 제작본이며 공개 GitHub Pages에는 아직 반영하지 않았다.

## 수정 내용

- 키보드와 각 포인터가 누른 입력을 따로 관리한다. 한 손가락을 떼도 다른 손가락이나 키보드가 누른 같은 페달은 유지한다.
- 메뉴·차고·결과·도로 복귀·포커스 이탈·화면 방향 변경 때 입력을 해제한다. 재개 직후 아직 누른 키의 자동 반복만으로 가속이 다시 켜지지 않는다.
- 메뉴 버튼을 클릭해 포커스가 남아도 ESC로 주행을 재개할 수 있다. 메뉴 버튼의 기본 키보드 동작은 유지한다.
- 화면 방향이나 터치 배치가 바뀌면 일시정지한다. 모바일 주소 표시줄처럼 같은 배치 안의 작은 높이 변화는 일시정지하지 않는다.
- 작은 화면에 `복귀` 버튼을 추가했다. 정지 메뉴나 결과 화면에서는 주행 버튼을 비활성화한다.
- AI가 앞차와의 상대 속도·제동 거리로 감속하고 멈춘 앞차 뒤에서 대기한다. 정상적인 교통 대기를 고장으로 간주해 자동 복귀시키지 않는다. 완주 AI의 저속 자동 복귀도 막는다.

## 자동 검증

`npm run check:rebuild`: **34개 시험, 실패 0개 및 웹 빌드 통과**. 기존 여섯 차량의 실제 전체 코스 주행 시험도 포함한다.

실제 Rapier 강체로 정지한 머스탱 앞에 접근한 수프라를 검사했다. 수정 전 14초 동안 충돌 4회, 수정 후 충돌 0회이며 최소 차체 중심 간격 6.188m였다. 앞차가 다시 출발하면 뒤차도 가속한다. 차량을 서로 통과시키는 방식은 사용하지 않는다.

230km/h, 벽에 10도 비스듬히 진입한 뒤 후진하고 재출발하는 시험도 세 차종 모두 통과했다. 충돌체의 회전까지 반영한 벽 관통 검사와 바퀴 네 개 접지 검사를 수행했다.

| 차종 | 후진 이동 거리 | 재출발 속도 | 최대 벽 침투량 |
| --- | ---: | ---: | ---: |
| Supra | 18.77m | 62.83km/h | 5.19mm |
| SLK | 26.01m | 49.35km/h | 5.00mm |
| Mustang | 24.40m | 58.88km/h | 5.00mm |

이는 정해진 입력과 노면의 회귀 시험이며, 사람의 전 구간 운전 평가를 대신하지 않는다.

## 브라우저 검증과 한계

- 메뉴 클릭 후 ESC 재개, 정지 플레이어 뒤 AI 대기, 화면 배치 변경 후 일시정지·입력 해제, 가속 버튼과 키보드 조향 동시 입력, 해제 뒤 중립 입력 및 도로 복귀를 확인했다.
- 844×390 가로 화면과 320×740 세로 화면에서 여섯 터치 버튼이 표시됐다. 320px 화면의 버튼 폭은 약45.3px이며 오른쪽 끝은306px로 화면 안에 들어온다.
- 네이티브 입력을 누른 채 화면을 바꾸는 자동화는 도구 오류로 중단됐다. 이후 순차 입력·방향 변경은 확인했지만 이 결과를 실제 두 손가락 터치 검증으로 간주하지 않는다.
- 숨겨진 빈 탭을 여는 방법으로는 실제 포커스 이탈을 재현하지 못했다. 입력 해제 로직은 단위시험을 통과했으며, 실제 앱 전환·두 손가락 조작·포인터 취소·장시간 GPU 성능은 모바일 실기기에서 확인해야 한다.
- 기존 Three.js / Rapier 청크 크기 경고는 남아 있다.

증거: `artifacts/race-controls-20261009/`의 시험 로그·메뉴/배치/복귀 telemetry·작은 화면 버튼 측정·스크린샷. `focus-return.json`은 포커스 이탈 성공 증거가 아니라 위 재현 한계를 기록한다.
