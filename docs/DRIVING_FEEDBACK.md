# 주행 피드백 — 제동·타이어·탈출 가속

작성: 2026-09-08 · 로컬 구현 및 개발 환경 검증. GitHub 푸시·운영 배포는 이 작업에 포함하지 않는다.

## 문제와 판단

밝은 해변 미술은 유지하되, 페달을 밟고 코너에서 접지를 잃는 변화가 화면과 소리에서 구분되지 않는 문제를 다룬다. 기존 엔진음·바람 소리를 보강하는 범위이며, 물리 수치를 과장하거나 새로운 보상·차량·맵을 추가하지 않는다.

| 관찰한 부족함 | 원인 | 이번 수정 |
| --- | --- | --- |
| 제동·미끄러짐이 소리에서 구분되지 않음 | 엔진·풍절음 위주의 합성 | 실제 감속에 따른 마찰음, 바퀴별 횡방향 미끄러짐에 따른 타이어 소리 |
| 핸드브레이크를 누르면 곧바로 드리프트로 취급 | 기존 `drifting`은 입력·속도 조건 | 별도의 읽기 전용 계측기로 실제 속도 방향·회전·접지 확인 |
| 가속 입력과 차가 밀려 나가는 느낌이 약함 | 속도만 반영하는 카메라·소리 | 실제 가속량에 따른 작은 시야각/높이 반응, 구동 부하음·변속 시 짧은 음량 변화 |
| 미끄러진 위치를 알 수 없음 | 노면 흔적 없음 | 실제 바퀴 접점에 제한된 수의 짧은 타이어 자국 |
| 사운드가 메뉴 안에 있어 발견하기 어려움 | 기본 무음 + 설정 메뉴 필요 | 우측 상단 52×52 소리 바로가기, 메뉴 볼륨 조절 유지 |

접지·핸들링 재설계가 필요한 것으로 발견된 P1 결함은 이번 검사에서 없었다. 다만 자동 주행 성공은 사람에게 재미있는 운전이라는 증거가 아니다.

## 구현

### 1. 표현은 실제 물리 결과를 읽는다

- `physics.js`는 각속도, 바퀴 접점/법선/접지, 해석된 구동·핸드브레이크 상태를 추가로 내보낸다. 힘·접지력·차량 크기·경로는 변경하지 않았다.
- `drivingSignals.js`는 120Hz 물리 스텝마다 세계 좌표 속도 변화량을 차량 전방에 투영한다. 차가 제자리에서 방향만 바뀌었다고 감속 효과가 발생하지 않도록 했다.
- 바퀴 위치 속도는 차체 선속도 + 각속도 × 접점 오프셋으로 계산한다. 조향각에 맞춘 구름 방향과 횡방향 성분으로 접점의 미끄러짐을 읽는다.
- `sliding` 진입은 전진 6m/s 초과·차체 슬립각 약 8도 초과·횡속도 1.2m/s 초과가 0.12초 지속될 때다. 접지 회복에는 별도 이탈 문턱을 둔다. 바퀴 소리와 흔적은 이 차체 상태만이 아니라 바퀴별 계측값을 따른다.
- 기존 `drifting` 변수는 핸드브레이크용 후륜 접지력 처리에 남아 있다. 그것을 실제 드리프트 판정으로 표시하거나 소리 조건으로 재사용하지 않는다.
- 공중·저속·리셋·도로 복귀에는 효과를 해제한다. 정지한 채 페달을 눌러도 타이어 소리나 탈출 가속 효과를 만들지 않는다.

### 2. 오디오

- 원본 Web Audio 합성만 사용한다. 외부 차량 녹음·추가 음원 다운로드·마이크 접근이 없다.
- 엔진 기본음/배음, 풍절음, 제동 마찰음, 타이어 마찰음/절제된 고음층을 분리했다. `AudioParam.setTargetAtTime`으로 음량과 주파수 변화를 부드럽게 연결한다.
- 계기판과 같은 기어 번호를 사용하며 상향 변속 때 약 0.13초 동안 음량을 낮춘다. 이것은 실제 변속기·RPM 시뮬레이션이 아닌 소리 연출이다.
- 기본은 무음이다. 사용자가 **♪ 소리 끔**을 눌렀을 때만 오디오를 생성/재개한다. 다시 누르면 무음, 메뉴에서 볼륨을 조절한다.
- 일시정지·비활성화된 이야기 장면은 무음, 차고로 나가면 소스/컨텍스트를 해제한다. 재입장도 기본 무음이다. 빠른 켜기/끄기 또는 재개 대기 중 퇴장으로 소리가 되살아나지 않도록 요청 순서를 검사한다.
- 소리 버튼을 누른 뒤 키보드 초점을 주행 화면으로 되돌린다. 사운드 사용 실패는 짧은 안내로 표시한다.

### 3. 화면과 비용

- 추격 거리는 그대로 유지한다. 가속 시 최대 +1.8도 시야각·-0.12m 카메라 높이, 제동 시 최대 -0.7도·+0.16m를 기존 카메라 목표에 더한다. 실제 적용은 가감속에 따라 작아지고 보간된다.
- 화면 흔들림·롤·방사형 블러·차체 발광은 추가하지 않는다. ‘동작 줄이기’ 설정에서는 이 동적 카메라 효과를 끈다.
- `tireFeedback.js`: 최대 **512개 자국 조각**, **12초**에 걸쳐 사라짐, 재사용 버퍼 + 메시 1개. 흔적이 없거나 전부 사라지면 그리기를 끈다.
- 자국은 접지 법선이 위를 향하는 면에만 생성하며, 공중·급격한 위치 점프를 선으로 잇지 않는다. 회색 아스팔트 위 실제 타이어 경로를 따라 보이는 것을 캡처로 확인했다.
- 엔진 출력·속도 표시·노면 길이·코스 판정·개인 최고 기록을 바꾸지 않는다.

## 이번 검증과 증거

환경: Windows, 설치된 데스크톱 Chrome의 headless/SwiftShader, Playwright. 기본 피드백 검사 1280×800, 모바일 화면 390×844. 물리 상태를 직접 이동시키지 않고 키보드 및 브라우저 터치 입력으로 주행했다.

- `npm run check`: **66개 시험 및 빌드 통과**. 새 계측·자국 풀·오디오 비동기 수명·동작 줄이기 검사 포함.
- 실제 Rapier 차량 2대에 같은 입력을 1,100스텝 적용하고, 한쪽에서만 피드백을 계측해 **위치·회전이 동일함**을 확인했다.
- [가감속·타이어 브라우저 검사](../artifacts/driving-feedback/verification.json): 가속 시 부하 증가, 약 100km/h에서 제동, 핸드브레이크 회전의 접점 자국, 정차 후 마찰음 해제, 음소거·일시정지·재사용·퇴장 해제, 키보드 초점, 모바일 소리 버튼, 동작 줄이기.
- [주행 오디오 샘플](../artifacts/driving-feedback/drive-preview.wav): 게임의 합성 출력 버스만 녹음했다. 유효 파형과 디지털 클리핑 여부를 검사했으며 **사람의 청음·실제 스피커 음량 평가를 대신하지 않는다**.
- [기존 속도감 회귀](../artifacts/driving-feedback/regression/speed-feel/verification.json): 실제 약 225km/h, 추격 거리 약 10.3m, 가속 출력 증가, 메뉴/볼륨 0/무음 출력 0 확인.
- [태블릿 HUD 회귀](../artifacts/driving-feedback/regression/tablet-hud/verification.json): 6개 가로/세로 해상도, 소리 버튼 포함 터치 영역 크기·상호 겹침, 도로 중앙 보호, 실제 두 손가락 가속+조향·취소·화면 회전·메뉴 입력 해제 확인.
- [해안 스프린트 회귀](../artifacts/driving-feedback/regression/sprint/verification.json): 3개 계측선 완주·개인 기록·재도전·복귀 시 무효·저장/재입장. 이 주행에서 최대 139 draw calls로 이전 해변 버전과 동일했다. 미끄럼 자국이 살아 있는 장면에는 메시 1개가 추가되므로 모든 상황의 호출 수가 같다는 뜻은 아니다.
- [이야기 왕복 회귀](../artifacts/driving-feedback/regression/signal-journey/verification.json): 차고 출발→신호소 경유·2초 정차→귀환→완료 저장→차고 기록→재입장 확인. 게임 시간 약 196초, 벽시계 약 213초, 최대 132 draw calls. 오류·실패 요청·외부 에셋 요청 없음. 이 시간 비율은 자동 검증의 장면 대기/조작 시간도 포함하므로 FPS 지표로 해석하지 않는다.

## 남은 한계와 다음 판단

1. **실제 삼성 태블릿/휴대폰 청음·멀티터치·장시간 성능 검사**가 우선이다. OS/브라우저/볼륨·이어폰 여부와 10분 이상 구동 결과를 기록한다. 자동 파형 검사를 ‘좋은 엔진음’으로 판정하지 않는다.
2. 브레이크음은 실제 감속 기반 합성 마찰 연출이다. 실제 브레이크 디스크·ABS·노면/타이어 종류별 음향이나 휠 잠김을 모델링한 것은 아니다.
3. 타이어 감지는 횡방향 미끄러짐 중심이다. 종방향 휠 스핀/번아웃, 연기, 충돌 충격음, 고스트, AI 상대는 이번 범위 밖이다. 외연 확장보다 직선→제동→코너→탈출을 사람에게 반복 평가받는다.
4. 빌드의 큰 청크 경고는 남아 있다. 빌드 통과나 드로 콜만으로 모바일 다운로드 시간·프레임 시간·발열을 보장하지 않는다.
5. 이번 효과는 차의 궤적을 고치지 않는다. 사람이 느끼기에 조향/접지 회복이 여전히 어색하다면 해당 속도·입력·영상으로 물리를 다시 진단한다.

## 구현 확인에 사용한 1차 자료

- [Rapier 차량 컨트롤러 API](https://rapier.rs/javascript3d/classes/DynamicRayCastVehicleController.html): 바퀴 접점과 접촉 법선 조회.
- [MDN Web Audio 권장 사항](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices): 사용자의 오디오 시작 조작과 음량 제어.
- [MDN AudioParam.setTargetAtTime](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime): 부드러운 오디오 파라미터 변경.
