# COASTLINE GT — 공도·스토리 전환안

**후속 구현:** 사용자가 ‘짧은 공도 1번’을 요청해 [바람곶 해안길](COAST_ROAD_STAGE1.md)을 별도 자유 주행 모드로 추가했다. 공도 코너·갈림길·전망대·회차·귀환은 구현됐고, 아래 ‘옛 해안길’ 이야기 챕터는 여전히 미구현이다. 기존 프롤로그/고속 시험은 보존했다.

작성일: 2026-09-06  
상태: 방향 전환 + 첫 프롤로그 구현. 아래 장편 이야기·추가 이벤트는 제안이며 미구현.

## 결정과 범위

사용자 요청: 서킷이 아닌 **공도**, 스토리·컷신·다양한 이벤트를 운전에 연결한다. 기존 항구 차고와 해안 미술, 실제 미터 단위 Rapier 차량은 보존한다. 이전 문서의 ‘해안 서킷’ 방향보다 이 문서가 우선한다.

추천 장르: **스토리 기반 해안 드라이빙 어드벤처 + 선택형 레이싱 이벤트**. 차에서 내려 싸우거나 자원을 채집하는 게임으로 바꾸지 않는다. 운전·차고·사람과의 만남이 중심이다. 학습 문제·배달 반복 경제도 부활시키지 않는다.

공도는 장소의 성격, 레이싱은 그 장소에서 할 수 있는 여러 활동 중 하나다. 자유 주행과 이야기 임무가 기본이고, 스프린트·추월·라이벌 대결은 정해진 이벤트에서 제공한다. 고속 경기 때는 같은 공도의 일부를 행사 통제 구간으로 사용하는 방식이 미술 정체성을 유지하면서도 읽기 쉽다.

## 참고할 레퍼런스와 차용할 구조

게임 구매 추천이 아니라 설계 참고 대상이다. 아래 설명은 공식 페이지에서 확인한 특징과 우리 게임에 대한 해석을 구분한다. 원작 코드·이미지·차량·음원을 가져오지 않는다.

| 레퍼런스 | 공식 자료에서 확인한 구조 | 우리에게 적용할 아이디어 |
|---|---|---|
| [Pacific Drive](https://www.playstation.com/en-us/games/pacific-drive/) | 차고를 거점으로 차량을 수리·개선하고 반복 출행하는 운전 생존 게임 | **가장 좋은 차고 참고**. 의뢰 준비→출발→귀환 후 공간/대화 변화. 공포·생존·1인칭은 가져오지 않는다. |
| [Forza Horizon 5 — Horizon Stories](https://forza.net/news/forza-horizon-5-first-drive) | 이야기 미션이 여러 장으로 진행되며 사진 촬영·오래된 차량 찾기 같은 주행 활동 제공 | **가장 좋은 미션 참고**. 한 장소에서 짧고 서로 다른 목적의 주행으로 이야기를 만든다. 대규모 오픈월드부터 만들지 않는다. |
| [Need for Speed Heat](https://www.ea.com/able/resources/need-for-speed/need-for-speed-heat/pc/text-manual) | 스토리 이벤트, 차고, 낮/밤별 이벤트·위험·진행 구조 | **레이싱 연결 참고**. 인물과의 관계가 다음 대결의 이유가 되도록 한다. 경찰 추격·거대한 도시·두 갈래 경제는 초기 범위에서 제외한다. |

이 세 작품의 모든 기능을 합치는 것이 아니다. **Pacific Drive의 거점 감각 + Horizon Stories의 짧은 챕터 + NFS의 주행 동기**만 빌린다.

## 우리 이야기 가안 — ‘돌아온 엔진’

고향 항구로 돌아온 주인공이 오래 닫혀 있던 정비소를 다시 연다. 낡은 GT의 시운전에서 지역 라디오 진행자와 다시 연락이 닿는다. 주민의 부탁과 다른 드라이버들의 도전을 거치며, 예전 해안 주행 클럽이 왜 흩어졌는지 알아가고 작은 해안 행사를 함께 준비한다.

갈등은 악당·범죄를 강제로 붙이기보다 **오래된 길과 관계를 다시 잇는 것**에서 만든다. 서사의 정서는 따뜻하지만, 이벤트 안에서는 제동·추월·고속 주행이 확실히 긴장감을 만든다. 제목·인명·과거 사건은 승인 전 가안이다.

등장인물은 우선 무전 자막으로 소개한다:

- 주인공: 돌아온 정비소의 드라이버. 플레이어가 운전으로 성격을 보여준다.
- 서진: 정비소 동료. 차량 상태와 첫 시운전을 안내한다.
- 유나: 항구 라디오 진행자. 지역 사람과 이벤트를 연결한다.
- 라이벌 드라이버: 추후 코너 주행과 동행 AI가 검증된 뒤 도입한다. 현재 없음.

## 챕터와 이벤트 계획

| 단계 | 이야기 / 활동 | 플레이 핵심 | 상태 |
|---|---|---|---|
| 프롤로그: 첫 번째 호출 | 정비소 출발→라디오 쉼터에서 약속 | 공도 안내·실제 경유·정차 | 이번에 구현 |
| 1장: 옛 해안길 | 유나의 사진 기록 장소 찾아가기 | 코너·갈림길·랜드마크 탐색 | 계획 |
| 2장: 함께 달리는 법 | 지역 드라이버와 약속 장소까지 동행 | 속도 조절·차간 거리·AI 동행 | 계획 |
| 3장: 라이벌의 초대 | 통제된 공도 스프린트 | 추월·제동 지점·드리프트 | 계획 |

부가 이벤트 후보: 전망대 사진, 고장 차량 동행, 정비 후 차량 인도, 라디오 신청 사연의 장소 방문, 클럽 타임어택. 모두 같은 공도 자산을 재사용한다. 의뢰를 단순 배달 반복으로 통일하지 않는다.

## 컷신 제작 원칙

- 영상 파일 대신 실제 Three.js 장면에 카메라 구도·시간·자막을 배치한다. 차량 도색도 그대로 반영된다.
- 긴 인물 연기 대신 차량, 셔터, 작업대, 부두 풍경의 짧은 장면으로 시작한다.
- 운전 중에는 강제로 카메라를 빼앗지 않는다. 무전 자막은 도로·차량을 가리지 않는 곳에 표시한다.
- 출발/도착 컷신에서만 운전 입력과 물리를 잠근다. 일시정지, 창 전환, 건너뛰기, 재시작을 명확히 처리한다.
- OS 움직임 줄이기/차고 움직임 설정에서는 컷신 카메라 이동을 줄인다.
- 현재 무전은 **자막만** 제공한다. 음성 더빙·립싱크·배경음악은 미구현이다.

## 이번에 실제로 붙인 것

1. 차고의 첫 의뢰 카드와 완료 후 초대장. 기존 테스트 주행은 별도 버튼으로 유지.
2. 차량 주변 3구도, 15초 실시간 오프닝. 건너뛰기·일시정지 지원. 차고 셔터에서 도로로 끊김 없이 출차하는 애니메이션은 아님.
3. 약 250m 첫 시운전. 올바른 진행 방향으로 두 경유 지점을 실제 통과해야 한다. 위치 이동이나 목표 지점 정차만으로 임무를 건너뛸 수 없다.
4. 진행에 따른 무전 자막과 목적지 거리. 놓친 경유 지점/목적지는 R로 재시작 가능.
5. 라디오 쉼터의 표시된 정차 구역 안에서 **2km/h 미만, 접지 3륜 이상, 연속 2초** 정차하면 완료. 점수나 속도 목표를 강요하지 않는다.
6. 완료 화면과 브라우저 저장. `mumu.coast.story.v1` 키만 기록하며 차고 설정·기존 게임 저장은 건드리지 않는다. 저장 차단 시 실패를 알리고 게임 진행은 허용한다. 재시도는 완주 기록을 지우지 않고 현재 임무만 새로 시작한다.
7. 붉은 서킷 연석·체커 출발선·계측 표지·반복 콘을 제거하고, 황색 중앙선·양방향 차선·횡단보도·항만대로 안내판·라디오 쉼터·정차 구역을 코드로 제작.

## 현재 제한 — 공도처럼 보이는 것과 교통 시뮬레이션은 다르다

- 아직 **직선 공도 시안**이다. 실제 도로망, 교차로, 첫 코너는 미구현.
- 일반 통행 차량·보행자·교통 신호·경찰 AI 없음. UI에도 표시한다.
- 60 표지는 장소 설정이며 과속 위반 시스템이나 강제 최고속 제한은 아니다. 기존 230km/h 수준의 물리 성능은 유지.
- 넓이 20m의 왕복 4차로 표현. 석재 방벽·보도 충돌체는 유지하며 도로 가구는 차로 밖에 배치.
- 항구 디테일은 기존 400m가 기준. 바깥은 단순 계측 공간이며 길 끝 물리 경계가 남아 있다.
- 다음 장은 실제 해금된 플레이 콘텐츠가 아니다. 초대장에 ‘제작 예정’을 명시.
- 임무 도중 세부 위치 저장은 없음. 새로고침/차고 복귀 후에는 프롤로그 시작부터 재생.
- 기본 소리 꺼짐 유지. 소리 버튼으로 기존 합성 엔진·바람 소리만 켤 수 있다.
- 외부 에셋·신규 패키지·영상·폰트 다운로드 없음. 로컬 변경만 적용, GitHub 푸시·Vercel 배포 없음.

## 다음 작업 순서

1. 사용자가 프롤로그를 체험하고 인물·정서·컷신의 길이 확인.
2. **공도 첫 코너 + 갈림길 하나**. 시각 차선·충돌·목적지·AI가 같은 경로 데이터를 쓰게 만든다.
3. 다음 만남 하나를 실제 플레이로 구현. 장소만 늘리지 않고 한 편을 완결한다.
4. 양방향 통행 AI의 정지/회피/충돌 검증 후 소수 차량을 추가한다. 가짜 배경차를 물리차처럼 소개하지 않는다.
5. 코너 피드백·타이어 소리·카메라 개선을 기존 [주행 체감 계획](DRIVING_EXPERIENCE_PLAN.md)과 연결한다.
6. 반복 가능한 경주 이벤트 → 차고 변화 → 한 장 분량의 저장을 검증한 뒤 지도 확대.

## 검증

- `npm run check`: 기존 15개 + 스토리 상태/저장 5개, 총 20개와 프로덕션 빌드 통과.
- `scripts/verify-story.cjs`: 실제 브라우저 키 입력으로 컷신→경유→정차→완료→차고→새로고침→재도전·모바일·테스트 모드를 검증한다. 결과는 `artifacts/story-road/verification.json`.
- 2026-09-06 KST 첫 브라우저 실행 통과: 위 흐름, 컷신 자연 종료·건너뛰기·정지, 완료 저장과 재시작을 검증했다. 콘솔 오류·실패 요청·외부 요청 모두 0건. 실제 사용자 기기의 성능 측정은 아니다.
- agent-browser 스킬의 화면·오류·탐색 검증 기준을 적용. CLI가 설치되어 있지 않아 기존 Playwright + Chrome 경로를 사용한다.
- Three.js/Rapier 번들 크기 경고는 기존처럼 남아 있으며 전 기기 60FPS를 보증하지 않는다.
