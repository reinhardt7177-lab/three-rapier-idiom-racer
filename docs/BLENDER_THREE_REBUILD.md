# 기존 Unity 게임을 Blender + Three.js 웹 앱으로 재구성

> 차량 후속 변경: 복구 차량의 찌그러짐 문제로 세 대 모두 새 Blender 메시·기계식 리그로 교체했다. 현재 차량 상태와 이번 변경의 검증은 차량 재제작 기록 (이전 파일 정리됨)을 따른다. 아래 차량 추출·표면 정리는 이전 단계의 기록이다. 기존 월드와 경로는 계속 사용한다.

## 목표 · 2026-10-09

사용자가 새 엔진 전환을 명시적으로 요청했다. 기존 Unity v53의 수프라·SLK·머스탱, 차고와 해안 맵을 시각 기준으로 삼는다. Windows 빌드는 만들지 않는다. 이번 전환은 기존 웹 실험 v54를 그대로 최종 게임이라고 부르는 작업이 아니다.

## 보존

- 기존 Unity 실행본, Git 이력, 백업과 Blender 맵 원본은 보존한다.
- 앞선 ‘첫 번째 내용 삭제’ 요청의 대상은 아직 확정되지 않았으므로 삭제하지 않는다.
- 운영 공개 주소는 검증된 재구성본을 별도로 확인하기 전까지 기존 v53을 유지한다.

## 작업 순서와 완료 기준

1. **기존 에셋 확인·복구**: v53의 읽기 전용 사본에서 메시, 재질, 텍스처와 오브젝트 연결을 조사한다. 복구 결과와 실패 항목을 기록한다. C# 게임 로직과 Unity 프로젝트 전체 복구를 주장하지 않는다.
2. **Blender 차량 제작 파이프라인**: 복구 가능한 차량을 Blender에 가져와 법선·재질·비율을 다듬고, 차체와 바퀴를 분리한다. 수정 가능한 `.blend`와 웹용 `.glb`를 함께 보관한다. 복구 모델과 새로 제작한 모델의 출처를 구분한다.
3. **차고·차량 선택**: 실제 모델을 Three.js에서 로딩한다. 도장색, 바퀴 회전·조향, 로딩 실패와 자원 해제를 처리한다. 먼저 로컬에서 기존 차량과 비교한다.
4. **레이스 연결**: 플레이어 1대 + AI 5대, 카운트다운, 순위·결과·재시작·차고 복귀를 연결한다. 충돌과 도로 높이, 고속 카메라와 VFX를 검증한다.
5. **맵·UI 폴리싱**: 복구 가능한 맵 자료와 보존된 Blender 맵을 조사해 해안·도시·산길을 재구성한다. 구현된 맵이 기존 Unity 맵과 동일한지, 새로 만든 구간인지 정확히 기록한다.
6. **웹 빌드 검증**: 관련 시험과 프로덕션 빌드를 실행하고 실제 브라우저에서 차량 선택 → 출발 → 주행 → 메뉴 → 복귀를 확인한다. 공개 배포와 로컬 검증을 구분한다.

## 구현 결과

- UnityPy 1.25.4로 차량 3종·해안 월드의 선택된 825개 메시·54개 재질을 오류 없이 추출했다. 원래 `world-route` 2,656개 지점과 6,839.74m 길이도 추출했다. 삭제된 Unity C# 제작 프로젝트 전체 복구는 아니다.
- Blender 4.5.9에서 차량별 표면 용접·법선·표면 완화, SLK·머스탱 도장 정리, 웹 PBR 재질과 휠 분리를 처리했다. `assets-sources/rebuilt-unity/`에 차량 3종·월드·새 차고의 `.blend` 5개를 보관한다.
- `public/assets/rebuild/`에 Draco 압축 GLB, 디코더와 원래 주행 경로를 넣었다. 지형의 Unity 전용 표현은 Blender 정점색으로, 나뭇잎은 alpha cutout으로 바꿨다. 원래 셰이더와 완전히 같은 그래픽이라는 의미는 아니다.
- 새 입구는 `src/rebuild/main.jsx`다. 차량 선택, 6대 공유 Rapier 물리, 원래 월드·도로 충돌 160개, 3초 카운트다운, 순위·1바퀴 결과·재시작·차고 복귀, 일시정지·키보드·터치 입력을 구현했다.
- 바퀴 간격은 각 복구 모델에서 읽어 물리 휠 위치와 연결한다. 카메라는 차량과의 상대 거리를 유지하며, 타이어 연기·자국과 니트로를 연결했다. AI는 전방 곡률에 따라 미리 감속하며 5초 이상 막히면 해당 경로로 복귀한다. 이 자동 복귀는 아케이드 보조 기능이다.
- 빌드는 재구성 앱의 에셋만 포함한다. 기존 프로토타입 코드·웹 실행본·Git 이력·백업은 보존한다.

## 실제 검증

- 복구 도로의 실제 Blender 충돌 좌표를 사용하는 6대 자동운전 시험에서 모두 전체 6.84km 경로를 완주했다. 처음 산길 급커브에서 멈추던 문제는 전방 곡률 기반 감속으로 수정했다. 이 시험은 사람이 직접 운전한 완주나 렌더링 성능 시험이 아니다.
- 기존 전체 시험 `npm run check`: 203개 통과 후 빌드 성공. 기본 조향·카메라·물리와 기존 기능의 회귀 검증이며, 새 앱 UI 전체를 검증하는 203개 시험이라는 뜻은 아니다. 230–300km/h에서 차량과 카메라 거리가 누적해 늘어나지 않는 회귀 시험을 포함한다.
- 새 재구성 시험 `node --test scripts/rebuild-race.test.mjs`: 3개 통과. 원래 경로·진행도·복귀 시 부당한 완주 방지, 실제 GLB에서 읽은 차량별 휠 간격과 복구 충돌 메시를 사용하는 혼합 6대의 전체 코스 자동운전을 검증했다.
- 최종 `npm run build` 성공. 배포 산출물은 16개 파일, 35,212,882바이트(약 35.2MB)다. Three.js·Rapier의 큰 청크 경고는 남아 있으며, 최초 로딩과 모바일 성능의 추가 최적화 대상이다.
- 브라우저에서 차량 3종 선택 → 항구 레이스 시작 → 직접 가속 → 일시정지 → 재시작 → 차고 복귀를 확인했다. 최종 빌드 주행 표본에서 138km/h, 카메라 거리 약 7.98m, 플레이어·AI의 4바퀴 접지와 순위 변화를 확인했다. 38FPS 표본은 장시간 성능 보장이나 60FPS 벤치마크가 아니다.
- 390×844 세로 화면과 844×390 가로 화면을 브라우저 크기 조정으로 검수했다. 차고 카메라와 최소 높이를 수정해 차체와 시작 버튼이 잘리지 않도록 했다. 가로 화면의 문서 크기와 뷰포트가 동일해 페이지 넘침이 없음을 확인했다. 실제 휴대폰 검증은 아니다.
- 최종 프로덕션 미리보기 `http://127.0.0.1:5191/`에서 콘솔 오류가 없었다. 개발 중 발생했던 React HMR 중복 루트 오류는 루트 재사용 처리로 수정했다.

## 남은 한계

- SLK·머스탱의 복구 모델에는 원래 AI 모델의 형태 불규칙성이 남아 있다. 도장과 표면 정리만으로 수작업 리토폴로지와 같은 품질이 되지는 않는다. `.blend` 원본을 기준으로 추가 형태 정리를 할 수 있다.
- Unity 전용 셰이더·VFX·게임 로직은 그대로 실행하는 것이 아니라 웹 구현으로 재구성했다. 기존 저장 기록은 가져오지 않았다.
- 모바일 실기기, 장시간 GPU 메모리·성능, 사람이 직접 운전하는 전체 코스 완주는 아직 검증하지 않았다.
- 로컬 제작본만 검증 중이며, 기존 GitHub Pages 기본 주소는 Unity v53이다.

## 제작 재현 순서

1. `scripts/recover-unity-assets.py`, `scripts/export-unity-scene.py`, `scripts/export-unity-route.py`
2. Blender background로 `scripts/blender/rebuild_from_unity.py`
3. Blender background로 `scripts/blender/finish_rebuild_assets.py`
4. Blender background로 `scripts/blender/polish_recovered_world.py`, `scripts/blender/polish_recovered_cars.py`
5. `node --test scripts/rebuild-race.test.mjs`, `npm run check`

큰 JSON 중간 파일은 압축본의 SHA-256이 원본과 같은 것을 확인한 뒤 압축본만 남겼다. 이 작업에서 생성한 임시 데이터만 정리했다.
