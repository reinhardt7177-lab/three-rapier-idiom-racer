# 무무: 리페어 타운 — 게임 방향 전면 개편

작성일: 2026-09-05  
상태: 보류된 대안 / 구현하지 않음  
가제와 세부 수치는 제안이며, 사용자 확정 또는 실제 테스트 결과가 아니다.

> 후속 사용자 선택: 레이싱을 유지하고, 스타일라이즈드 해안 서킷에 레퍼런스 분위기의 차고를 결합한다. 이 문서는 개발 기준이 아니다. 현재 기준은 [레이싱 재설계 계획 16절](RACING_REBUILD_PLAN.md#16-최신-사용자-선택-해안-서킷과-레퍼런스-차고)이다. 아래 본문은 제안 이력으로만 보존한다.

## 1. 결정과 한 문장 소개

**고속 레이싱을 신규 게임의 중심에서 내려놓고, 손으로 꾸민 듯한 산업 동네를 탐험하고 복구하는 싱글플레이 게임으로 전환한다.**

“작은 정비 로봇이 비가 그친 동네를 돌아다니며 멈춘 기계를 고치고, 오래 닫혀 있던 작은 정비소를 다시 여는 게임.”

사용자가 제공한 AFTERLIGHT 캡처의 공간 밀도·재질감·빛을 미술 참고로 삼는다. 원작 로고·캐릭터·대사·지도·UI를 복제하지 않으며, 원작의 실제 게임 규칙이나 엔진 구현은 확인하지 않았다. 후속 게시물 캡처의 Three.js·45분·60FPS 설명은 작성자 주장으로 구분하고 우리 일정·성능 보장으로 쓰지 않는다.

이번 변경은 기획 문서와 진입 문서에만 적용한다. 기존 게임 소스·에셋·세이브·배포는 보존한다. 이전의 200km/h 목표, 서킷 확장, 차량 컬렉션은 새 게임의 완료 조건이 아니다. 학습 퀴즈도 다시 도입하지 않는다.

## 2. 이 맵과 어울리는 이유

| 공간의 특징 | 플레이로 연결하는 방법 |
|---|---|
| 좁은 골목, 문, 작은 마당 | 코너 너머를 발견하고 지름길을 여는 탐험 |
| 배관, 발전기, 수문, 작업대 | 배경 장식을 실제 조작 가능한 장치로 사용 |
| 벽돌·금속·물웅덩이의 가까운 디테일 | 천천히 이동하며 관찰할 이유를 제공 |
| 어두운 공간과 따뜻한 실내등 | 복구 전후의 변화와 다음 목적지를 빛으로 표현 |
| 비스듬한 위쪽 카메라 | 주변 장치와 이동 경로를 함께 읽게 구성 |

레이싱에 이 미술을 억지로 붙이는 대신 공간 관찰과 변화 자체를 보상으로 만든다. 전투 RPG·생존 제작·오픈월드는 첫 범위에서 제외한다. 많은 적, 광대한 맵, 복잡한 경제 없이도 한 구역의 완성도를 평가할 수 있게 한다.

## 3. 플레이어와 핵심 재미

- 주인공: 바퀴 두 개로 이동하는 작은 정비 로봇. 색상 두세 개, 분명한 얼굴과 집게 팔을 가진 자체 디자인을 제작한다.
- 기본 행동: 이동, 조사, 부품 집기/놓기, 밀기, 장치 작동. 수리는 시험 문제가 아니라 공간에서 원인과 결과를 발견하는 행동이다.
- 정비소: 차량 선택 메뉴를 변형하지 않고 실제 들어갈 수 있는 거점으로 새로 설계한다.
- 동료 드론: 첫 완성본에는 넣지 않는다. 동행 AI보다 주인공의 움직임과 한 구역의 상호작용을 우선한다.
- 보상: 켜진 가로등, 내려간 물, 열린 문, 살아난 작업대, 찾아온 작은 생활 로봇. 점수 폭죽이나 배지 팝업을 보상의 중심으로 삼지 않는다.

핵심 반복은 **발견 → 원인 관찰 → 부품 운반·장치 조작 → 공간 변화 → 새 길 발견**이다. 물건 수십 개를 반복 수집하는 심부름으로 만들지 않는다.

## 4. 첫 10분: 빗물 골목의 정비소

목표 플레이 시간은 8~12분이다. 작은 연결 공간 3곳, 핵심 장치 3개, 눈에 보이는 복구 결과 3개로 끝나는 완결된 구역을 만든다.

| 구간 | 플레이 | 눈에 보이는 결과 |
|---|---|---|
| 0~2분: 정비소 앞마당 | 이동·조사를 익히고 꺼진 배전함, 잠긴 골목, 멈춘 펌프를 발견 | 목적지가 실제 배선·물 흐름으로 읽힘 |
| 2~5분: 창고 작업장 | 낮은 운반 카트를 밀어 통로를 확보하고 예비 전원 모듈을 운반 | 창고 문이 안쪽에서 열려 지름길 생성 |
| 5~8분: 펌프 골목 | 모듈을 연결하고, 펌프와 문 중 어디에 전력을 보낼지 선택 | 펌프 작동 후 수위가 내려가 정비소 옆길 노출 |
| 8~10분: 정비소 복구 | 열린 옆길로 진입해 내부 차단기를 올리고 작업대를 가동 | 실내등·환풍기·작업대가 켜지고 첫 방문 로봇 도착 |

전력 퍼즐은 제한된 한 전원을 어디에 쓸지 이해하는 방식이다. 펌프 완료 상태는 유지하고, 문은 안에서 기계식 잠금을 풀 수 있게 해 전원을 회수해도 갇히지 않는다. 실제 게임에서 순서 변경·재접속·부품 유실 상황을 별도로 검증한다.

보조 목표는 정비소 앞 표지판 복구 1개만 둔다. 선택 목표를 하지 않아도 첫 구역을 완료할 수 있다. 첫 완성본에 돈·등급·상점·스킬트리를 추가하지 않는다.

## 5. 실패·힌트·조작

- 전투, 체력 소모, 굶주림, 시간제한 없음. 틀린 조작은 상태를 알려주고 다시 시도할 수 있게 한다.
- 모듈은 소비하지 않는다. 놓친 물건은 안전한 받침대에서 회수할 수 있고, 플레이어는 마지막 안전 지점으로 복귀할 수 있다.
- 막힌 상황에서 요청하면 힌트를 단계적으로 표시한다: 관찰 대상 → 관련 장치 → 필요한 행동. 일정 시간 정지했다고 힌트를 강제로 띄우지 않는다.
- PC 우선: WASD/방향키 이동, E 상호작용, Esc 일시정지. 집기·놓기는 같은 상호작용 체계로 처리한다.
- 한 번에 가장 적합한 상호작용 대상 하나만 선택한다. 거리뿐 아니라 벽 가림과 접근 방향도 확인한다.
- 클릭 이동, 자유 점프, 전방위 카메라 회전은 첫 범위에서 제외한다. 입력과 길찾기 경우의 수를 줄인다.
- 모바일 대응은 PC 첫 구역 검증 후 가상 스틱·상호작용 버튼으로 별도 설계한다. PC 결과를 모바일 성능 보장으로 해석하지 않는다.

## 6. 맵·카메라·미술

기본 카메라는 고정된 방위에서 비스듬히 내려다보며 주인공을 부드럽게 따라간다. 직교/약한 원근 두 안을 동일 장면에서 비교한 뒤 선택한다. 자유 카메라보다 길의 가독성을 우선한다.

맵은 큰 평지에 프롭을 흩뿌리지 않는다. 정비소 마당·좁은 골목·창고라는 닫힌 구도를 문과 코너로 연결하고, 각 공간에 대표 장치 하나를 둔다. 앞쪽 벽이 주인공을 가릴 때는 해당 벽·지붕을 낮추거나 숨기는 방식으로 시야를 확보한다. 매 프레임 전체 벽을 투명하게 만드는 것은 기본 해법으로 삼지 않는다.

- 색: 어두운 청록/회색의 구조물, 따뜻한 황토색 햇빛, 작은 주황색 작업등. 발광이 재질을 덮지 않게 한다.
- 바닥: 거친 포장과 부분적으로 젖은 면을 구분한다. 모든 바닥을 거울처럼 만들지 않는다.
- 밀도: 주 동선은 비워 두고 벽 가장자리·작업대·배관 접점에 디테일을 집중한다.
- 형태: 큰 벽체 → 창/기둥/배관 → 작은 파손·나사·식물의 세 단계로 구성한다.
- 움직임: 물결·환풍기·작업등·팔 동작처럼 세계 상태를 설명하는 애니메이션부터 만든다.
- 소리: 전원이 켜지며 시작되는 모터, 물이 빠지는 소리, 금속 발판, 실내외 잔향 차이. 브라우저 소리는 사용자 입력 후 시작하고 음소거를 제공한다.
- 에셋: 라이선스가 확인된 필요한 모델만 선별한다. 모델별 스케일·축·재질·텍스처·라이선스를 목록으로 관리한다. CC0라도 스타일이 안 맞으면 사용하지 않는다.
- 대표 로봇·정비소 정면·발전 장치는 별도 제작 후보로 두며, 배경 소품으로 주인공 품질을 대체하지 않는다.

환경맵 기반 재질부터 구축하고 고비용 반사·후처리는 비교 검증 후 추가한다. 화면만 보고 원본의 그림자·반사 구현 방식을 단정하지 않는다. 장식 벽돌은 묶어서 렌더링하고 충돌은 단순한 벽체로 분리한다.

## 7. UI와 진행 상태

- 시작 화면: 새로 시작/계속하기/설정. 거대한 홍보 문구와 카드형 선택 목록을 제거한 새 화면을 설계한다.
- 플레이 중: 현재 할 일 한 줄, 근처 행동 안내, 소지 중인 모듈만 표시한다. 미니맵은 실제 길찾기 테스트에서 필요할 때 추가한다.
- 한국어 본문 글꼴 1종을 중심으로 읽기 크기를 확보하고, 장식용 영문 대문자·과도한 자간을 기본값으로 쓰지 않는다.
- 완료: 복구된 장면을 잠시 보여준 뒤 계속 탐험/처음부터/설정 제공. 원작의 카드·명칭은 가져오지 않는다.
- 저장: 완료 장치·열린 문·부품 위치·플레이어 안전 지점·설정을 버전이 있는 독립 키로 저장한다. 기존 레이싱 기록은 읽거나 덮어쓰지 않는다.
- 상태 규칙: 장치마다 미복구/사용가능/작동중/복구완료를 명시하고 반복 상호작용이 부품 중복·완료 중복을 만들지 않게 한다.

## 8. 기술 이관과 보존 범위

현재 Three.js·Rapier·Vite를 출발점으로 하되, 차량 컨트롤러를 로봇 컨트롤러로 이름만 바꾸지 않는다. 새 게임은 이동·상호작용·구역 상태 중심으로 별도 구성한다. 기술 스택 자체를 바꾸는 작업은 지금 범위에 포함하지 않는다.

| 보존·선별 | 신규 제작 | 신규 범위에서 제외 |
|---|---|---|
| 라이선스와 에셋 원본, 로딩·자원 해제 방식 중 검증된 부분 | 캐릭터 이동, 카메라 가림 처리, 장치 상태, 진행·저장 | 차량 동역학, 랩·체크포인트·니트로·레이스 AI |
| 기존 소스·사용자 변경·세이브·문서 이력 | 공간 배치, 재질 명세, 인터랙션, 거점 UI | 차량 해금·고스트·서킷 선택·학습 시스템 |

구현 때는 별도 진입점에서 새 장면을 실행하고 기존 실행 경로는 유지한다. 새 데모 확인 전 기본 페이지나 운영 배포를 교체하지 않는다. 프레임 시간·자원 정리 등 기존 문제를 새 코드로 복사하지 않는다.

예상 모듈 책임은 app(화면/수명주기), player(입력/이동), world(구역/배치), interaction(대상/행동), machines(상태 전환), render(조명/재질/카메라), save(버전/복원), audio(상태별 소리)로 분리한다. 고정 물리 스텝과 렌더를 분리하고, 물리 시뮬레이션이 필요 없는 문·스위치는 명시적 상태로 처리한다.

## 9. 제작 순서와 통과 조건

| 단계 | 실제 결과물 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 1. 미술 기준 | 정비소 앞마당 콘셉트와 색·재질·배치 명세 | 사용자가 원하는 화면 방향과 일치. 아직 게임 완성으로 표시하지 않음 |
| 2. 실제 장면 | 주인공 이동, 작은 마당, 벽 가림, 스위치와 전등 | 같은 구도의 콘셉트/실행 화면 비교, 충돌·가독성 확인 |
| 3. 첫 게임 | 연결 공간 3곳, 부품 운반, 배수와 문, 완료·저장 | 처음부터 끝까지 진행 가능, 순서 변경과 새로고침 후에도 막히지 않음 |
| 4. 품질 마무리 | 재질·빛·애니메이션·소리·저사양 옵션 | 목표 기기에서 성능 기록, 여러 번 재진입해 자원 누수·상태 중복 확인 |
| 5. 후속 확장 | 두 번째 구역 또는 정비소 꾸미기 | 첫 구역의 플레이와 미술 방향 확인 후 선택. 동시에 확장하지 않음 |

첫 구현 우선순위는 **작은 마당 + 정비 로봇 + 스위치를 누르면 켜지는 정비소**다. 콘셉트 이미지만 완성하거나 회전하는 전시 장면만 만든 것을 플레이 가능한 결과로 보고하지 않는다.

성능 목표는 우선 선정한 PC에서 1080p·60FPS이며 실측 전에는 달성으로 표시하지 않는다. 기기·브라우저·화질·해상도와 프레임 시간 분포를 기록한다. 저사양은 그림자 해상도·픽셀 비율·반사/후처리를 낮추되 이동·상호작용 규칙은 유지한다.

필수 검증은 벽 관통, 카메라 가림, 문 끼임, 물건 유실/중복, 전원 회수 후 진행 불가, 완료 전후 저장 복원, 반복 구역 진입, 창 전환 복귀, 키보드 입력 해제, 음소거 유지다. 자동 상태 테스트와 실제 화면 검증을 구분한다.
