# 남은 결함 재개 · 2026-10-12

사용자의 “나머지 다시 작업 들어 가세요” 요청으로 같은 작업 브랜치 `codex/korea-circuits-progression-20261011`에서 재개했다. 시작 HEAD는 `549a270`, 추적 파일 변경은 없었다. 변경 전 파일/시각/해시는 `artifacts/release-repair-20261012/before/`와 `session.json`에 보존했다. 이전 증거·사용자 진행도·비밀 파일은 삭제하거나 출력하지 않았다.

## 범위와 우선순위

1. 해안 보통 맑음/비의 노면 이탈과 쉬움 3랩 미완주를 고친다.
2. 실제 지도 여수의 일반 교통 뒤 긴 따라가기와 잘못된 메달 기준을 고친다.
3. 실제 브라우저 흐름·입력 해제·네 화면 크기·성능을 확인한다.

물리 접지·조향·충돌체·activeRide 자세 고정과 난이도/니트로 설정은 유지한다. AI는 실제 페달/조향만 사용하며 위치나 진행 거리를 보정하지 않는다. 전체 검사가 통과한 단위만 다음 구현으로 진행한다. PR/main 병합은 하지 않으며 이번 재개 요청을 새 배포 완료로 표현하지 않는다.

계산은 이전의 사용자 지정 “연결없이 하셈”에 따라 로컬 Windows CPU/Rapier WASM에서 실행한다. Colab/GPU 활용이라고 표현하지 않는다.

## 해안 원인과 첫 수정

기준 실행을 현재 코드로 재현했다. 포르쉐는 도로 중심에서 -30.86m, 수프라는 -21.63m까지 이탈해 실제 잔디를 밟았다. 바퀴 지지면과 아래 방향 레이 검사로 경로 높이 오차만의 문제가 아님을 확인했다.

앞에서 추월 중인 RX-7이 빠르게 접근하는 뒤차 때문에 차선 변경을 계속하지 못하면, 도로 가운데서 정지 페달을 내보냈다. 뒤차가 충돌해 큰 회전 속도로 밀려났고 다음 차량도 같은 상황에 걸렸다. `rivalPlanner.js`는 이미 시작한 횡이동의 충돌 원인이 뒤차뿐일 때 현재 아스팔트 차선을 유지하며 앞으로 진행하게 바꿨다. 앞차/옆에서 끼어드는 차의 예측 충돌 검사와 평소 전방 제동은 유지했다. 정지 상태를 다른 숫자로 판정하거나 충돌을 끄지 않았다.

쉬움 3랩의 SLK도 기준 실행에서 산길 벽을 바라본 채 가속만 하며 멈췄다. 앞선 충돌 판단 수정 이후 이 정체가 재발하지 않아 별도 후진/복귀 기능은 추가하지 않았다.

## 진행 중 / 아직 통과하지 않은 항목

- 첫 수정의 전체 `npm run check`가 진행 중이다. 검사 중 소스 해시를 고정하고, 옛 시험이 쓰는 보고서 사본을 이번 작업 아래 보존한 뒤 원본 증거를 복구하는 실행기를 사용했다.
- 여수 일반 교통 6대/보통 1랩은 첫 수정 후에도 420초에 4/6만 완주했다. 포르쉐 8,508m, RX-7 6,735m였고 둘 다 움직이고 있었다. 전 차량 오프로드 0초/최저 0.37m 이상이었다. 이전 실패나 이 표본을 삭제하지 않는다. 추가 수정 전 추월 상태에서 느린 새 앞차를 다시 선택하는 조건을 확인한다.
- 개발 `qaPerf`의 임시 버튼 4개가 짧은 두 화면에서 차 선택과 겹친 표본을 `garage-ui.json`에 보존했다. 이를 제품 UI 통과 표본으로 사용하지 않는다. 제품 조작부와 같은 화면을 별도로 재측정한다.
- 첫 해안 브라우저는 산길 87.60초/복귀0까지 확인했지만 화면 변경 정지와 검수 탭 정리로 중단됐다. 완주 증거가 아니며 정지 화면 캡처도 코너 주행 검수로 사용하지 않는다.

최종 전체 검사·UI·성능·변경 상태·남은 위험은 검증 완료 후 이 문서에 덧붙인다.
