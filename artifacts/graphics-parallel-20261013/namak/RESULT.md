# 남악 담당 결과 · 2026-10-13

## 실제 반영

- `src/rebuild/namakVisuals.js`와 `scripts/namak-visuals.test.mjs`를 신규 생성했다. 원래 두 경로가 없었음을 변경 전 시각·후보 해시와 함께 `before/manifest.json`에 기록했다.
- 기존 world surface/colors 셰이더 훅을 유지하고, 판석의 비율·판별색·멀리서의 줄눈 떨림 완화, 외벽/장벽 패널·기단 음영, 재질별 거칠기·중성 색 분리, 식생의 약한 위치별 색/명암을 연결했다. 화면 전체 saturation/필터와 추가 텍스처는 없다.
- 기존 가로수62그루의 거친 윤곽을 부드러운558개 잎 덩어리로 보완한다.128m37셀, 공유 SphereGeometry1개/표준 재질1개, 인스턴스 색을 사용한다. 실제 충돌·길·기존 GLB/Blender 원본은 그대로 둔다.
- API: `createNamakVisuals(scene, world, route, {quality})` → `{root, stats, setQuality, update(camera,dt,elapsed,visible), dispose}`. `polishWorldSurfaces/applyNamakColors/batchWorldScenery` 이후, `createDecorationQuality` 이전에 호출한다. 새 root는 `userData.dynamic=true`라 공통 장식 품질/배칭에서 제외하며 자체 예산으로 제어한다.
- 물리/AI/공통runtime/package·기존 테스트는 편집하지 않았다. 런타임 통합·전체check·커밋·푸시·배포는 부모 작업 범위다.

## 남은 검증/위험

- 아직 실제 게임 런타임에 연결하지 않았다. 통합 후 전체check·GLSL 컴파일·같은 위치 전후 캡처·주행 시야·고정 조건 프레임/초기 로딩을 확인해야 한다.
- 기존 큰 나무 기하를 유지하면서 주변 덩어리를 추가하는 방식이다. 새 잎과 원래 큰 면이 실제 화면에서 서로 부자연스럽게 겹치는지 화면에서 평가해야 한다. 실제 화면을 보지 않고 좋아졌다고 최종 판정하지 않는다.
- 가까운 셀 상한/거리 전환에서 잎 덩어리가 갑자기 나타날 수 있어 주행 화면 검수를 남긴다. 낮음에서는 추가 장식을 숨긴다.
- 기존 남악의 반투명 고스트/전체장면 부하와 원본 건물 반복성은 이 모듈로 해결했다고 주장하지 않는다. 브라우저/휴대폰 성능·AAA 완성도는 미검증이다.

현재 후속 우선순위는 부모의 P1빗길 회귀격리 통과 → 런타임 연결 → 컴파일/화면/동일조건 프레임 확인이다.
