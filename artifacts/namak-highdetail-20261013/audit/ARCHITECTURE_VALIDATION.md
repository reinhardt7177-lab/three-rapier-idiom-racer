# 남악 신규 건축 레이어 자동 검증 — 2026-10-13

`scripts/namak-architecture.test.mjs`를 추가하고 최종 GLB에 실행했다. 결과는 **7개 통과, 실패 0개, 약 3.32초**다. 공유 제품 코드와 `package.json`은 수정하지 않았다.

```powershell
node --test scripts/namak-architecture.test.mjs
```

최종 로그: `architecture-tests.log`.

## 실제 확인한 범위

- 현재 원본 `namak.blend`, `namak.glb`, 경로 JSON, 충돌 바이너리와 manifest가 기존 고정 SHA-256과 일치한다. 신규 저장본은 `namak-highdetail.blend`이고 시각 GLB는 별도 파일이다.
- `GLTFLoader`로 실제 GLB를 파싱해 보고서와 메쉬·삼각형·바이트 수를 대조했다. `unity_collider` / `namak_collision` 없는 시각 전용 레이어, 6개 재질, 유한한 정점 배열과 Y 축 높이 범위를 확인했다.
- 도청 크라운 상면 87.4m, 앞마당 반사 연못 상면 0.055m, 저수지 목재 보행로 상면 0.125m의 실제 레이 교차와 상향 법선을 확인했다. 저수지 보행로 하면·안쪽 벽·바깥 벽의 법선도 닫힌 구조 바깥쪽을 향한다.
- 경로 **1,464개 점 전부 × 8개 차선**(±9, ±7, ±5, ±2.2m)에서 0.06~2.56m 차량 높이 레이를 실행하여 새 상세의 침범이 없음을 확인했다. 검사는 양면 교차를 사용하여 잘못 뒤집힌 면이 침범을 숨기지 않게 했다. 샘플 사이의 모든 부피를 수학적으로 보증하는 검사는 아니다.
- 실제 시각 그룹이 `Namak_Architecture` / `userData.dynamic=true` 상태로 배칭 후 유지된다. high 340m / medium 200m / low 0m 제한, 먼 카메라, 숨긴 월드, 가시성 인수 false, low에서 high 복귀를 확인했다.
- 컨트롤러 종료는 원본 자산을 해제하지 않으며, 최종 씬 종료에서 공유 재질과 geometry가 각각 한 번만 해제된다.

## 발견·수정·재검증

1. 초기 시험은 크라운 상면을 먼저 읽은 생성기의 85m로 기대했으나 제작자가 마지막 형태 변경으로 87.4m에 수출했다. 현재 생성기의 `y=86.7 / h=1.4`와 확인하고 기대값을 87.4m로 수정했다. 검사 허용오차나 상향 법선 조건은 완화하지 않았다. 당시 로그는 `architecture-tests-initial.log`에 보존했다.
2. 다시 실행하니 **저수지 목재 보행로 상면 법선 -Y**를 발견했다. 생성기 `ring()`의 면 순서가 뒤집힌 실제 구조 문제였다. 제작자에게 보고하고 제작자가 전체 ring 면 순서를 반전하여 다시 수출했다. 실패 로그는 `architecture-tests-ring-failure.log`에 보존했다.
3. 상면뿐 아니라 하면·내외벽 검사까지 추가한 동일 7개 시험을 최종 수출에 다시 실행해 모두 통과했다.

## 한계

브라우저를 새로 열거나 실제 운전·WebGL 성능 측정을 수행하지 않았다. 자동 검사는 신규 자산 구조·배치·컨트롤러의 논리와 자원 정리에 관한 결과다. 최종 브라우저 그림·광원·주행 시 가시성·실기기 성능은 별도 확인이 필요하다.
